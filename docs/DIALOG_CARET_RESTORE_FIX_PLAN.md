## 工程1: 調査の結果

行番号は `e215d01` の時点。

- 原因の処理: `src/components/dialogs/AppDialogModal.tsx` の `useLayoutEffect`（30〜98行）。開いたときに、そのときフォーカスのあった要素を `previouslyFocused` に取っておき、閉じるとき（96行）に `previouslyFocused.focus()` で戻す。
- エディタ側には、キャレットを保ったまま戻す口がある。`VerticalTextEditor.tsx` の `restoreFocus`（3565行）。中身は `editor.view.focus()` で、注記には「DOM の focus() だけだとブラウザがキャレットを本文冒頭の編集可能な位置へ置き直す」とある。
- 同じ問題を、コマンドパレットはすでに避けている。`App.tsx` の `restoreFocusAfterCommandPalette`（3696行）は、戻す先が本文（`.pm-root` の中）ならエディタの `restoreFocus()` を、そうでなければ素の `focus({ preventScroll: true })` を使う。これを `CommandPalette` と `ManuscriptTidyModal`（`useModalFocus` の3つ目の引数）に渡している。
- `AppDialogModal` だけがこの口を持たない。App.tsx で2か所に描かれる（6948行の起動画面の側、7705行の本文の画面の側）。
- 同じ素の `focus()` で戻すモーダルはほかに3つある（`SettingsModal`・`HelpModal`・`ThemePickerModal`。どれも `useModalFocus` の既定）。どれもメニューやボタンから開くので、開く前のフォーカスは本文ではなくボタンにある。本文から直接開く入口は見つからなかった。
- ソースの文字列を読むテストはない（`text-deps.mjs`、`scripts/` の grep）。`AppDialogModal` を描くテストもない。

## 工程2: 仕組みの説明

### 言葉

- **キャレット**: 本文の中で、次に打つ文字が入る位置。
- **フォーカス**: キー入力を受け取っている部品。本文、入力欄、ボタンのどれか1つにある。
- **素の `focus()`**: 部品にフォーカスを移すブラウザの命令。本文のエディタにこれを使うと、ブラウザがキャレットを本文の最初の書ける位置に置き、エディタはそれを本当の移動として受け取る。
- **`view.focus()`**: エディタ（ProseMirror）自身の命令。フォーカスを移すのと同時に、エディタが覚えているキャレットの位置を画面に書き戻す。

### 1. 利用者の操作と内部の処理

| 操作 | 開く前のフォーカス | 閉じたとき |
|---|---|---|
| 本文で Ctrl+N（作品を開いているとき）→「新規ファイルを作成」→ Esc | 本文 | 素の `focus()` で本文へ。キャレットが先頭へ（**確かめた**。下の「再現」） |
| コマンドパレットの「表を挿入…」→ 列数・行数のダイアログ → キャンセル | パレットが閉じるときに `restoreFocus()` で本文へ戻してから開く | 素の `focus()` で本文へ。キャレットが先頭へ（見込み） |
| 本文の右クリックメニューから開くダイアログ（見出しの移動など） | 本文 | 同上（見込み） |
| ファイルツリーの右クリック →「リネーム」→ Esc | 本物のマウスでは、右クリックしたツリーの項目（**確かめた**） | 開いたときのフォーカスはメニューの項目で、閉じるときには消えているので、どこにも戻さない。本文には触れない（**確かめた**）。3-1 の実機確認で先頭へ戻ったのは、右クリックを合成のイベントで送り、フォーカスが本文に残っていたため |

### 再現（QA 用アプリ、`e215d01`。本物のキーとマウスを CDP で送った）

1. 「# 第一章」で始まる文書の「最後の行。」の「後」をマウスでクリックした。キャレットは「最後」のあと（選択は `最後の行。` の2文字目）。
2. Ctrl+N で「新規ファイルを作成」が開き、入力欄にフォーカスが移った。
3. Esc で閉じた。フォーカスは本文に戻ったが、選択は `# 第一章` の2文字目（見出しの記号のあと＝本文の先頭）になった。
4. 続けて「★」を打つと、`# ★第一章` になった。キャレットが本当に先頭へ動いている。
5. 比べとして、ツリーの第二章.md を本物のマウスで右クリック →「リネーム」→ Esc。開く前のフォーカスはツリーの項目で、閉じたあとはどこにもフォーカスがなく、本文には触れなかった。

### 2. 保存

キャレットの位置は、作品ごとのカーソル位置（`.then/` の状態）として保存される。先頭へ戻ったあとに保存されると、次に開いたときも先頭から始まる。本文そのものは変わらない。

### 3. 今の挙動の癖（直さないもの）

- 設定・ヘルプ・テーマのモーダルも素の `focus()` で戻す。本文から開く入口がないので、今は先頭へ戻ることはない。

## 工程5: 案

### 5-1. 方針

コマンドパレットと原稿の整形のモーダルで使っている戻し方を、`AppDialogModal` にも渡す。新しい仕組みは作らない。

### 決めてほしいこと

1. **直し方**
   - **A（勧め）: `AppDialogModal` に、閉じるときの戻し方を受け取る口（`restoreFocus`）を足し、App.tsx の2か所で `restoreFocusAfterCommandPalette` を渡す。** 渡さなければ今と同じ素の `focus()`。`ManuscriptTidyModal` と同じ形なので、読む人が迷わない。変わるのは本文へ戻るときだけ。
   - B: `AppDialogModal` の中で、戻す先が本文なら `.pm-root` から自分でエディタを探して戻す。部品がエディタの作りを知ることになり、ほかの部品と形がそろわない。
2. **ほかのモーダルも一緒に直すか**
   - **A（勧め）: 今回は `AppDialogModal` だけ。** 設定・ヘルプ・テーマのモーダルは本文から開く入口がなく、今は起きない。入口ができたときに同じ口を渡せばよい（`useModalFocus` にはもう口がある）。
   - B: 3つにも同じ戻し方を渡す。今は何も変わらないが、将来の入口で起きなくなる。
3. **関数の名前**
   - **A（勧め）: `restoreFocusAfterCommandPalette` の名前は変えない。** 変えると差分が広がり、パレットのテストの読み手が迷う。
   - B: `restoreFocusToTarget` などに名前を変える。

### 見つけたこと（どれも直す前から。KNOWN_ISSUES に記録）

- **コマンドパレットから開いたダイアログを閉じると、フォーカスがどこにもなくなる。** ダイアログが開く瞬間、フォーカスはまだパレットの検索欄にあり、閉じるときにはその欄が消えている。
- **Ctrl+N で作ったファイルでは、打った文字が自動で入る見出しの前に入る。**
- 「新規ファイルを作成」の名前の欄で Enter を押しても作られなかった（「作成」ボタンでは作られる）。日本語入力の確定と分けるための作りかもしれず、確かめていないので KNOWN_ISSUES には書いていない。

### 確かめられなかったこと

- ヘルプとテーマのモーダルは、本文から開く入口がないので、本文へ戻す道は通っていない。メニューから開いて閉じる道は、設定と同じ `useModalFocus` の口なので、設定で確かめた。
