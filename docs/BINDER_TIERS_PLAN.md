### 1. データの形

- ツリーは `ProjectFolder`（作品のルート）の `children` を、そのままの順で描く。並び順は `project.json` の `order`（Rust 側で並べてから返す）。
- 素材フォルダがある作品では、作品直下のその1つのフォルダと、その中のすべてに `role: "material"` が付く。作品直下でない「素材」という名前のフォルダは原稿（1-3b の D-7）。
- 進捗は `appState.fileProgress`（絶対パス→状態）。素材には記号を出さないが、値は残っている。
- 折りたたみは、アプリ状態の3つの欄に作品ごとに持つ。フォルダ（`collapsedFolderPathsByWorkspace`）、ファイルの見出し（`collapsedOutlinePathsByWorkspace`）、見出しの子（`collapsedOutlineHeadingKeysByWorkspace`）。作品の `.then` には書かない。改名・移動のときにパスを書き換える（`projectEntryActions.ts` 280、381）。ライブラリ内で作品を移したときも写す（`library.ts` 87–95）。
- 進捗の絞り込みは `localStorage` の `then.sidebar.progressFilter`（作品をまたいで1つ）。

### 5. 今の挙動の癖（工程9で実機で確かめる）

固定用テストを書いていて見つけたもの。確認1で、直すかどうかを決めてもらう（決めてほしいこと 11〜13）。

1. **ファイルを自分の親フォルダの行の真ん中へ落とすと、フォルダの外（フォルダの後ろ）へ出る**。親が同じフォルダへの「中へ」は無効にしてあり（984–990）、代わりに前後の並べ替えの判定へ進んで、親の親の中の移動になる。例: `第一章/港.md` を「第一章」の行へ落とすと、作品直下の「第一章」の後ろへ移る。三段化で、素材の段の見出しへ素材のファイルを落としたときに同じことが起きないようにする。
2. **素材フォルダそのものを、ドラッグで別のフォルダへ入れたり削除したりすると、黙って素材でなくなる**。`materialsFolder` は作品直下の名前なので、作品直下から外れると一致しなくなり、中身は原稿として数えられる（字数・書き出しに入る）。改名だけは追う（1-3b）。
3. **右の Idea ペインの名前が「バインダー」**。左を「バインダー」にすると同じ名前が二つ並ぶ。

## 工程3: 依存関係

- `WorkspaceSidebar` の描画（`renderOutlineMode`）が段を作る。段の分け方は純粋な関数（一覧→原稿の項目・素材フォルダ）に切り出し、テストで直接確かめる。
- ポインタのドラッグは、行の `data-tree-entry-path` / `data-tree-entry-kind` / `data-tree-folder-path` を `elementFromPoint` で拾って行き先を決める（955–1024）。素材の段の行は、親を素材フォルダにすれば今の処理のまま動く。段の見出しへの落とし先は、見出しに `data-tree-entry-path`（ルートか素材フォルダのパス）と `data-tree-entry-kind="folder"` を付ければ「中へ」として扱える。ただし癖 1 の判定に当たらないよう、見出しは「中へ」だけにする。

- `LeftSidebar` → `WorkspaceSidebar` に、Idea を開く関数と Idea の件数、素材フォルダを作る関数を渡す。`App.tsx` に渡す元がある（`snippets`、`setRightSidebarTab`、`setIsRightSidebarCollapsed`）。

## 工程5: 案

### 5-1. 方針

- 段は**画面だけ**で作る。一覧（Rust）と集計は変えない。素材かどうかは `role` だけを見る。
- 段の分け方は、作品直下の `role: "material"` のフォルダ（1つ）を素材フォルダとし、ほかの作品直下の項目を原稿にする。パスや名前では決めない。
- 素材の段の中身・ドラッグ・メニュー・開閉は、今の `renderEntry` をそのまま使い、親を素材フォルダにするだけにする。新しい行の部品は作らない。
- 段の見出しの行は、モック（[binder-rebuild.html](mockups/binder-rebuild.html) の `.sec`）に合わせ、小さめの文字・控えめな色で、右に数を出す。色はテーマの既存の変数だけを使い、claude テーマでは見出しを橙にしない。説明の文は足さず、操作はボタンとメニューの文言で示す。

### 5-2. 段の見せ方（勧め）

```
⌄ 原稿                     1,073     ← 段の見出し（右クリック: ファイルを追加／フォルダを追加）
   第一章　届かなかった手紙    709 推   ← 今のツリーの行（並び・深さ・字数・印は今のまま）
   第二章 …
⌄ 素材                        320     ← 右クリック: ファイルを追加／フォルダを追加／リネーム
   人物 ⌄                              ← 素材フォルダの中身を深さ0から
     汐見.md
   年表.md
⌄ 投稿
   Idea                      3        ← クリックで右の Idea ペインを開く
```

素材フォルダがない作品の素材の段（勧め）:

```
⌄ 原稿                     1,073
   （今のツリーのまま）
  素材                [素材フォルダを作る]   ← ボタン1つ。押すと名前を聞く（既定「素材」）
⌄ 投稿
   Idea                      3
```

### 5-3. 素材フォルダを作る操作

- Rust に `create_project_materials_folder(root_path, name)` を足す。作品直下に新しいフォルダを作り、`materialsFolder` に名前を書き、一覧を返す。名前は `materials_folder_name` と同じ規則で確かめる。同じ名前のものがあれば作らずにエラーを返す（既存のフォルダを黙って素材にしない）。
- 既存の作品直下のフォルダを素材にする操作は、別に用意するかを決めてもらう（決めてほしいこと 3）。用意する場合も、利用者が右クリックで明示的に選んだときだけにする。
- 素材フォルダがある作品では、作る操作は出さない（1作品に1つ）。

### 5-4. 段をまたぐドラッグ

- 原稿の行を素材の段の見出しへ落とす＝素材フォルダの中（末尾）へ移す。素材の行の前後へ落とす＝その位置へ移す（今の「別のフォルダの前後」と同じ。1件のとき）。
- 素材の行を原稿の段の見出しへ落とす＝作品直下へ移す。原稿の行の前後へ落とす＝その位置へ。
- 移動は今の `onMoveEntry` をそのまま呼ぶ。進捗の値は Rust がパスごと書き換えて残す（1-3b で確かめ済み）。素材に入ると印が消え、原稿に戻すと元の印が出る。
- 素材フォルダそのものは行として出さないので、ドラッグで動かせない（癖 2 が素材の段からは起きなくなる）。
- 複数選択のまま段をまたぐ: 今と同じ規則（見出し＝「中へ」は複数でも可、行の前後は同じ親のときだけ）。
