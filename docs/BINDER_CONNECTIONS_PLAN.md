### 気づいた点

1. **経路を分けて出すには、索引に「どこで見つけたか」を持たせる必要がある。** 今の索引は名前と種類しか持たないので、素材リスト経由とコメント行経由を分けるには、`findLinks` が場所（フロントマターのどのキー／コメント行／本文）を返し、索引がそれを覚える形にする。規則は `findLinks` の中で既に場所ごとに分かれている（111〜112行の `lineStart < metadataEnd` と `isSlashCommentLine`）ので、判定を増やすのではなく、分かれている結果を捨てずに返すだけで済む。キャッシュの形が変わるので版を 2 に上げ、更新後の最初の起動で1回だけ全部読み直す（3-1 の見積もりで 10万字・50ファイルで数十ミリ秒）。
2. **フロントマターの `[[ ]]` は、`materials` 以外のキーでも数えている。** 概要に `[[汐見]]` と書けば、それもリンクになる（3-1 の規則のまま）。場所にキーを持たせれば、モックの「概要で参照」のように「素材」「概要」と出し分けられる。
3. **新しくノートをボードに置く口は、今はない。** Canvas の資料の候補は、作品のテキストファイル（原稿もノートも）を外している（`src/App.tsx` 2290〜2319行の `sortedReferenceCandidates`）。ノートを指す資料カードがあるのは、2-5 の移行で `素材/資料/` へ移った md の資料を指すカードなど、前からあるものだけ。だから「置かれているボード」は、4-2（`file` ノード）までほとんど空になる（見込み。実機の一時ライブラリでは、資料カードを持つボードを作って確かめる）。
4. **同じ名前のノートが2つあると、そのノートのリンク元は欠ける。** 上の表のとおり、`[[A]]` はどちらにも数えない。3-2 は本文で行き先が2つのリンクを薄く描き、押すと選ばせている。
5. **`load_canvas_board` は読むついでに書くことがある。** 古い共通 Canvas の資料カードが残っていると消して書き戻す。「つながり」を出すたびに全ボードをこれで読むと、ペインを開いただけでボードのファイルが書き換わりうる。読むだけの口を別に用意するほうがよい。
6. **3-3 で先送りにした「素材の項目の下に出すノートの説明」（モックの「郵便局員・三十二歳」）は、3-4 の範囲ではない。** ノートの中身を読む話で、つながりではないため（今回やらない）。

### 右のペインの中身を移す・隠すか

今回、既存の画面を隠したり移したりはしない（ペインを1つ足すだけ）。ドロップダウンの並びに1つ増えるので、テスト `test:right-sidebar` の「ペインの並び」の期待が変わる（工程5の「テストの直し方」）。

## 工程2: 仕組みの説明

### 言葉

| 言葉 | 意味 |
|---|---|
| つながり | 本文に出ている文書を、ほかのどこが指しているか。右のペインの1つとして出す |
| リンク元 | その文書を `[[名前]]` か `@[[パス]]` で指しているファイル。索引の `backlinksTo` が返すもの |
| 場所（経路） | リンクを書いた場所。**プロパティ**（フロントマター。キーごと。`materials` は「素材」、`synopsis` は「概要」と出す）・**コメント**（原稿の `//` 行）・**本文**（ノートの行、どこでも数える `@[[パス]]`） |
| 元の投稿 | 2-3 の「ノートにする」でそのノートを作った投稿（とその返信）。投稿の行の `note` がそのノートを指している |
| 置かれているボード | そのノートを指す資料カードを持つ、作品のボード |

### 1. データの形

ファイルに足すものはない。変わるのはアプリのデータフォルダにある索引のキャッシュの形だけ（作り直せるもの）。

- 索引の1本のリンクに、場所を足す: `{ kind, target, place }`。`place` は `{ in: "property", key: "materials" }`・`{ in: "comment" }`・`{ in: "body" }` のどれか。
- キャッシュは版 2。`l: Array<[種類, 名前, 場所, キー?]>`。版 1 のキャッシュは捨てて全部読み直す（今の「壊れていた・形が古いとき」の扱いのまま）。
- 「つながり」の中身は、画面の中で毎回その場で組み立てる（保存しない）。
  - 原稿に登場・リンク元: 索引の `backlinksTo` と場所ごとの数。索引の `version` か、出している文書が変わったときだけ組み立て直す。
  - 元の投稿: `postStream.posts` のうち、`note.workRoot` が開いている作品で `note.path` がその文書の相対パスのもの。
  - 置かれているボード: 作品のボードの資料カードの `sourcePath` の一覧（Rust の読むだけの命令で、1回で全ボード分を取る）のうち、その文書の相対パスのもの。
