# v0.6.6 タイプライター描画の改善・検証記録

2026-10-10。v0.6.6 のローカル修正版。公開リリースではない。

後続の装飾不具合修正と性能比較は [装飾更新の実現性・性能検証](DECORATION_MAPPING_VALIDATION_2026-10-10.md) に記録した。この記録の確認用インストーラーには、後続の修正は含まれていない。

## 結果と限界

録画に映っていた原稿の現在の内容を読み取り、メモリ上の模擬バックエンドで比較した。原稿そのものは変更していない。17,712文字、352段落。縦書き・行番号あり・末尾で日本語変換を20回確定。同一の計測器、Edge、1600×1000、DPR 1、CPU制限なし。比較対象は前回の文字数フォーマッター共有だけを適用したビルド。両方とも本番モードの非圧縮ビルド。

| 指標 | 修正前 | 修正後 |
| --- | ---: | ---: |
| フレーム間隔 中央値 | 8.9ms | 8.5ms |
| フレーム間隔 95％点 | 687.9ms | 219.6ms |
| フレーム間隔 最大 | 910.1ms | 367.9ms |
| スクロール位置が動いたフレーム数 | 1 | 73 |
| 1フレームの最大移動量 | 164px | 11px |
| 最終的な中央位置の誤差 | 0.04px | 0.04px |

95％点は約68％短縮。大きな一括移動を、複数フレームの小さな移動に変えた。文字内容、選択位置、Undo／Redoの復元は両方で一致。

ただし、**日本語入力を含むフレーム間隔には約220msの停止が残る。完全な解消、常時60fpsとは言えない。** この計測は各回12文字を一括変換し、50ms後に確定、さらに100ms後に次の変換を始める負荷試験。Windowsの実際の候補ウィンドウを操作した検証ではない。

別の10万文字の原稿では、通常設定の連続改行30回で95％点213.4ms→37.4ms。行番号・現在行・改行記号をすべて表示した20回の行移動では、最終修正の95％点46.5ms。10万文字ですべて表示したネイティブIME入力には約1.26秒の95％点が残った。長文のIME、装飾の写像、選択更新などに残負荷があり、すべての原因の切り分けは完了していない。

## 特定した原因と変更

1. **入力・IME確定時に瞬間移動していた。** `onUpdate` と `compositionend` の強制センタリングをアニメーションに変更。ProseMirrorの即時スクロールとの競合も抑制。変換中、範囲選択、手動ドラッグでは従来の操作を妨げない。
2. **アニメーションを入力ごとに中断・再作成していた。** 1つのRAFを継続して目標だけ更新する方式に変更。キャレットの座標を毎フレーム測らず、変更時と終了前に測定。到達できないスクロール位置は範囲内へ制限して停止する。
3. **Idea・プロットのCSSが本文更新でも画面全体を無効化していた。** `:has()` と `:not()`／全子孫指定の組み合わせを、Idea入力欄の空状態・添付ボタンのフォーカス・既存のドラッグ状態を示す属性に変更。修正前のトレースでは約10,442要素のスタイル更新、1回約230〜266msを確認した。
4. **表示補助が変更のない段落まで再計測していた。** 行断片・改行末尾を段落単位で保存。DOMの実変更、寸法、フォント、画面幅の変更では再計測する。同じ値を再設定した属性のMutationRecordは変更と見なさない。スクロール時の小数誤差でも全キャッシュを捨てない。
5. **行番号・改行記号を毎フレーム全削除・再生成していた。** 表示中のDOM要素を再利用し、画面外の改行記号は作成しない。座標を読んでからDOMを更新する。
6. **全文装飾時の子段落検索が段落数の二乗で増えていた。** ProseMirrorの不変なDecorationSetを保持し、最上位の子段落検索だけ索引化する。元の集合やライブラリ全体は変更しない。段落をまたぐinline装飾や未対応の内部構造では標準実装に戻る。
7. **IME確定ごとに全文装飾を強制再構築していた。** 未更新の変換行だけを反映するメタデータを追加。段落数・構造・テーブルなどの変化では既存の再構築経路を維持する。

前回のサイドバーの文字数整形の削減だけでは、上記の描画停止と瞬間移動を解消できていなかった。

## 正しさの検証

- `npm run test:typewriter`：連続追従、目標変更、RTL、小数ピクセル、端での停止、変換中の停止、レイアウト変更、DOM再利用、装飾の同一性、IME更新の比較。
- 装飾検索は2,400段落で標準実装と同じ子集合を返すこと、元の集合を変更しないこと、写像後も同じことを確認。
- IMEの通常表示・全文装飾表示で、ルビ・太字の確定後の装飾が全文再構築した結果と一致することを確認。通常確定時の全文再構築は0回、段落構造変更時は再構築に戻る。
- 実ブラウザで、入力内容・スクロールによる選択の不変・Undo／Redo・手動ホイール・ドラッグ開始時の停止を確認。
- 縦書きと横書きで、行番号・現在行をキャッシュなしのDOM再計測と比較。入力・リサイズ・フォント変更後とも位置の差は0.5px以内。
- Ideaの空欄／空白文字／添付ボタン／入力欄／送信ボタンへのフォーカス／クリア後の状態を確認。
- 既存の可視範囲、IME表示行、位置復元、ページ復旧、Idea UI、表のIME・移動のテストを実施。

索引化は現在のProseMirrorの集合構造を実行時に確認して使用する。依存ライブラリ更新時は、同一性テストと実ブラウザ検証を再実行する必要がある。

## 再現

```
npm run test:typewriter
node scripts/test-idea-composer-state.mjs
node scripts/benchmark-typing.mjs --project --typewriter --at middle --samples 30 --dist <build-directory>
node scripts/benchmark-typing.mjs --project --typewriter --at end --samples 20 --scenario ime --line-numbers --manuscript-file <original-text-file> --verify-controls --dist <build-directory>
node scripts/benchmark-typing.mjs --project --typewriter --at middle --samples 20 --scenario selection --line-numbers --highlight-line --line-breaks --verify-overlays --dist <build-directory>
```

`--output <json-file>` で結果を保存できる。`--trace --trace-file <json-file>`、`--profile --profile-file <json-file>` で原因調査用の記録も保存できる。フレームと移動量はUndo／Redoの前に集計する。`cpuPerKey` は集計後のUndo／Redo確認も含むため、純粋な入力1回のCPU時間として解釈しない。
