### 気づいた点

1. **本文へ落としたとき、今は何も入らない。** 投稿の行が運ぶのは `CANVAS_POST_DRAG_MIME` だけで、ProseMirror は `text/plain` がないと何もしない（前回の工程9の D5 で確かめた）。U6 は、エディタの側に受け口（`handleDrop`）を足せば作れる。
2. **エディタは投稿の本文を知らない。** 運ぶのは ID だけなので、受け口は App に「この ID の本文」を聞く（App の `postStream.posts` から引く）。行の側で本文も運ぶ（別の形式を足す）こともできるが、`text/plain` にすると、ペインの入力欄・検索欄・ほかのアプリにも文が落ちる。
3. **落とした位置は ProseMirror の `posAtCoords` で決まる。** 縦書きでも、右クリックのメニュー（`App.tsx` 3902 の `positionFromPoint`）とページの位置の記録（`VerticalTextEditor.tsx` 3214）が同じ関数を使っている。縦書きで正しく当たるかは、工程9で確かめる（見込み）。
4. **ProseMirror の既定では、落としたあと入れた範囲が選ばれる。** そのまま文字を打つと、入れた文が打った文字に置き換わる。
5. **元に戻す**: エディタの履歴（`History`）に1回の変更として入る。ただし直前の打鍵から 0.5 秒以内だと、打鍵と同じ1回にまとまることがある（prosemirror-history の `newGroupDelay`）。`closeHistory` で分けられる。
6. **ほかのドラッグとの取り合い**（今あるもの）:
   - 見出しのドラッグ（`HEADING_DRAG_MIME`）、ライブラリの作品（`LIBRARY_PROJECT_DRAG_TYPE`）、パンくず（`BREADCRUMB_ENTRY_DRAG_MIME`）: `text/plain` がないので、本文へ落ちても何も入らない。
   - バインダーの行・素材の段へのドラッグ: ポインタのドラッグ（自前）なので、本文の drop は起きない。
   - 別ウィンドウの Canvas のサイドパネル（`CanvasWindowApp.tsx` 1018-1027）: `text/plain` に名前（投稿なら本文の1行目）も付ける。メイン画面の本文へ落とすと、その名前が文として入る見込み（試していない。K1）。
   - 画像の貼り付け・ファイルの投げ込み: 本文には今ない（`dragDropEnabled: false`、`handlePaste` なし）。
   - 本文の中の文のドラッグ（選んだ文を動かす）: ProseMirror の `view.dragging` を使う別の道。受け口は投稿の形式があるときだけ働かせれば巻き込まない。
7. **IME と打鍵の遅さ**: 受け口は drop のときにしか動かないので、打鍵のたびの処理は増えない。App から渡す関数を描くたびに作り直すとエディタの部品が描き直されるので、`ref` で持つ（`onLinkActivateRef` と同じ）。`editorProps` の変更は HMR では入れ替わらない（開発中は全部読み直す）。変換中（IME の未確定の文があるとき）に落としたときは、入れないのが安全。
8. **投稿は全部 App の中にある**（`posts.jsonl` を読んだ一覧）。検索は、この一覧の本文を調べるだけで済む。Rust も索引も要らない。数千件でも、1打ごとに全件を調べて足りる見込み（`arrangePosts` も今、絞り込みのたびに全件を回している）。
9. **左の検索はファイルと行の作り。** 投稿を入れるには、結果の形・置換から外すこと・範囲の札（投稿はライブラリで共有なので「文書・作品」の範囲に合わない）を足すことになる。ペインの中なら、今の行の描画をそのまま使える（その場で直す・返信・ノートにする・ドラッグ）。
10. **当たった所の印は、DOM を変えずに付けられる。** 投稿の本文の欄は `contentEditable` で、React が文をそのまま描いている。印のために `<mark>` を挟むと、直すときに崩れる。CSS の Custom Highlight API（`CSS.highlights`。WebView2 の Chromium で使える）なら、文の DOM を変えずに色だけ付く。jsdom にはないので、実機で確かめる。
11. **狭いペインの原因**: 右のボタンは「ノートにする」（文字のボタン、約 70 px）と、返信・受信箱から外す・その他の操作（24 px ずつ）で、合わせて 160 px ほど。ペインが約 300 px だと、左に残るのは 80 px ほどで、時刻・ボードの札（縮めない）のあと、作品名に幅が残らない。
12. **文字列を確かめるテスト（`text-deps`）**: `PostStreamPane.tsx`・`postModel.ts`・`posts.css`・`ideaPlot.css` を文字列で読むテストはない（すべて動かすテスト）。`VerticalTextEditor.tsx` は `test:typewriter`（`const LayoutAstExtension` より前を切り出す）、`test:performance`（`updateEmptyAttribute(currentEditor, next)`、`const handleWheel` から `const handleMouseDown` まで など）、`test:markdown-table-ime`（`function focusEmptyCell(` から `function buildWindowDecos(` まで）、`test:v058-index`・`test:v058-counts` が読む。受け口は `editorProps`（5287-）に足すので、どの切り出しにも入らない。`App.tsx` は多くのテストが読むが、エディタへ渡す値（7776-7819）を読むテストはない。`RightSidebar.tsx` は `test:right-sidebar` が手で並べた値で描く（値を足したら、そのテストにも足す。前回の工程8と同じ）。

## 工程5: 案

### 5-1. 方針

- U6: 運ぶものは今のまま（投稿の ID だけ）にし、エディタに受け口を1つ足す。本文はメイン画面の一覧から引く。

### 決めてほしいこと

#### 2. U6（本文へドラッグ）

- **2-1 入れるもの: A. 投稿の本文の写し（改行はそのまま行にする）（勧め）**。理由: 投稿はファイルでないので `[[ ]]` のリンクは張れない。写しなら、投稿をあとで直しても原稿は変わらない（原稿は原稿として育てる）。B. 写し。ただし「ノートにした」投稿なら、ノートへのリンク `[[ノートの名前]]` を入れる（ノートはファイルなのでリンクが張れる）。C. 写しの後ろに、時刻をコメント行（`%%`）で添える。
- **2-2 入る場所: A. 落とした位置（文字と文字のあいだ。行の途中なら行が分かれる）（勧め）**。理由: ドラッグは「ここへ」を指す操作なので、カーソルの位置ではなく落とした所に入るのが自然。本文の中で選んだ文をドラッグして動かすときと同じ。B. 落とした行の後ろに、新しい行として入れる（行の途中には入らない）。C. 落とした位置に関係なく、今のカーソルの位置に入れる。
- **2-3 入れたあとのカーソルと元に戻す: A. カーソルを入れた文の後ろに置く（選ばない）。履歴を区切り、Ctrl+Z 1回で入れた文だけが消える（勧め）**。理由: ProseMirror の既定（入れた文を選ぶ）だと、続けて打つと入れた文が消える（K3）。打鍵と一緒に消える（K4）こともなくなる。B. ProseMirror の既定のまま（入れた文が選ばれる）。
- **2-4 落とす位置の印（K2）: A. 印は足さず、工程9で今の見え方を確かめる。印がなく位置が分からなければ、そのとき聞く（勧め）**。理由: 縦書きでは ProseMirror の dropcursor（横書き用の縦線）がそのまま使えず、自前で作ることになる。まず実機で、ブラウザの印が出るかを見る。B. 縦書きにも合う印（落とす位置に細い線）を自前で足す。
- **2-5 投稿の側: A. 何もしない（受信箱に残る）（勧め）**。理由: 本文の Ctrl+Z で投稿の側は戻らないので、投稿を変えると、戻したときに揃わない。同じ投稿を何度も使うこともある。受信箱から外すのはボタン1つでできる。B. 受信箱から外し、メイン画面の通知に「受信箱から外しました」と「元に戻す」（5秒）。C. 受信箱から外す（通知なし）。

- **2-6 変換中に落としたとき: A. 何も入れない（勧め）**。理由: 未確定の文と入れた文が混ざらない。B. 入れる。

#### 3. U9（投稿の検索）

- **3-1 置き場所: A. アイデアのペインの絞り込みの並びに、検索欄（虫眼鏡の印と、空のときの「検索」の文字。左の検索欄やファイル内検索と同じ）（勧め）**。理由: 結果をふだんの行のまま見せられるので、その場で直す・返信・ノートにする・ドラッグ（U6・U7）ができる。左の検索はファイルと行の作りで、投稿を入れると置換や範囲の決めごとが増える。B. 左の検索の画面に「投稿」の範囲を足し、結果を押すとペインを出してその投稿まで送る（`postReveal`）。C. 両方。
- **3-2 当たり方: A. 本文だけ。大文字小文字は区別しない（左の検索の既定と同じ）（勧め）**。理由: 作品で分けるのは「この作品」の絞り込みがある。作品名でも当たると、その作品の投稿が全部出て、探したいものが埋もれる。B. 本文と作品名。C. 本文・作品名・ノートの名前。

- **3-4 絞り込みとの組み合わせ: A. 今の絞り込み（受信箱・すべて・この作品）の中で探す（勧め）**。理由: 札が押されたままなので、今どこを探しているかが見える。全部から探すときは「すべて」を押す。B. 検索欄に文字があるあいだは、絞り込みに関係なく全部から探す（札の押されている見た目は残る）。
