## 工程1: 調査の結果

- AI の画面と処理は、すでに App.tsx の外にある。画面は `src/components/ai/AiPane.tsx`（270行）と `aiPane.css`、会話の処理は `src/ai/useAiConversations.ts` ほか。App.tsx に残っているのは、`<AiPane ... />` へ渡す props（約20行、行番号は `9cfcef6` 時点で 12037〜12054）と、本文などから AI へ文字を渡す `aiInsertRequest` の値だけ。
- 不具合の原因は `aiPane.css` にあり、App.tsx は関係しない。
- 保存先の欄の文字列（「保存先のスレッド」「このスレッドに保存」）や `.aiTurnActions` を読んでいるテストはない（`text-deps.mjs` で確かめた）。
- `docs/KNOWN_ISSUES.md` に、この不具合の項はない。

## 工程2: 仕組みの説明

### 言葉
- **select**: 選択肢から1つを選ぶ欄。閉じているときは、選んでいる項目の名前を欄の中に出す。
- **flex**: 部品を横に並べる CSS の仕組み。幅が足りないとき、どの部品を縮めるかを部品ごとに指定する。

### 操作と表示
1. 回答の下の「資料に保存」を押すと、その回答の下が「保存先のスレッド（select）」「このスレッドに保存」「やめる」の1行に替わる（`AiPane.tsx` の `startSave`）。
2. select の初期値は、前回選んだスレッドがまだあればそれ、なければ先頭のスレッド。
3. 「このスレッドに保存」で回答を資料のファイルにし、選んだスレッドに足す（App の `onReferenceSaved`）。

### 今の挙動の癖（不具合の原因）
- 1行の並び（`.aiTurnActions`）では、2つのボタンは「縮めない・折り返さない」、select は「幅 80px を目安に、足りなければいくらでも縮む」指定になっている。select の中には左右に計 32px の余白（右は ▼ の分）がある。
- 右サイドバーの幅は 300px。中の余白と回答一覧のスクロールバーを引くと、ボタン2つ（約190px）の残りが select になり、80px 前後しか残らない。そこから余白を引くと、名前に使える幅は 2〜3 文字分になる。
- UI 表示サイズを大きくしているときや、文字の幅が広い環境では、さらに狭くなり、名前がまったく見えなくなる（利用者の画面写真がこの状態）。
- 確かめたこと: `aiPane.css` を同じ指定で置いた再現ページで、幅 300px のとき select が 82px になり、「Then開発ログについて」が「Then」の途中までしか出ないことを見た。

## 工程5: 案

### 直し方の選択肢

| 案 | 見た目 | 文言 | 手間 |
|---|---|---|---|
| **A（勧め）** 保存先の select を1行目に横幅いっぱいで出し、2つのボタンを2行目の右に寄せる | 1行増える | 変えない | CSS 数行 |
| B ボタンの文言を「保存」に縮め、1行のまま | 1行のまま。select は約 150px | 「このスレッドに保存」→「保存」 | CSS なし、文言1つ |
| C select に最低幅（たとえば半分）を持たせ、足りないときだけボタンを次の行へ回す | 幅しだいで1行／2行が変わる | 変えない | CSS 数行 |

勧めは A。スレッド名は長いことが多く（例「Then開発ログについて」）、幅いっぱいにしないと B や C でも途中で切れる。2行に固定するので、サイドバーの幅や UI 表示サイズで並びが変わらない。

### 右サイドバーの分離について

- 右サイドバー（`<aside className="rightSidebar">`）の JSX は App.tsx の約240行で、中で App の値を約60個使っている（プロット、Idea、資料、校正、プロパティ、プラグイン、下書き）。切り出すと、それをすべて props で渡す部品になり、props の形を新しく決めることになる。
- タブの選択・畳む・広げるの値は、アプリ状態への保存（`rightSidebarTab`）や作品を開く経路とつながっている。
- 今回の不具合は AI の画面の CSS だけで直り、右サイドバーの分離とは関係しない。
- 勧めは「今回は分離しない」。分けるなら、別の作業として、右サイドバーの頭の部分（タブの切り替えと、タブごとのボタン、畳む・広げる）から始めるのがよい。

### 足すテスト
- ブラウザで `aiPane.css` を読み込み、幅 300px の右サイドバーに保存先の行を置いて、select の幅と、選んだ名前が欄に収まっていること（`scrollWidth <= clientWidth`）を確かめる。UI 表示サイズを大きくした状態（zoom）でも確かめる。
- 「資料に保存」などのボタンの行（`<div>`）が1行のままであることも確かめる。

## 工程6: 人の確認

2026-10-24 に決まったこと。

- 直し方は **A**（保存先の select を1行目に横幅いっぱい、ボタンを2行目の右に寄せる）。
- 右サイドバーは **全体を分ける**。先に分離をして、その後に修正する。

### 分離の線引き（確認1の後に詰めたもの）

- 新しい部品 `src/components/layout/RightSidebar.tsx` に、`<aside className="rightSidebar">` の JSX（`9cfcef6` 時点で App.tsx 11894〜12131行）をそのまま移す。React の仕組み（useState・useEffect・useCallback）は持ち込まない。
- 一緒に移すもの: 組み込みのタブの一覧（`rightSidebarBuiltinTabs`、554〜620行）と、タブの切り替えに出す項目の組み立て（`rightPaneSwitcherItems`、2358〜2375行）。どちらも右サイドバーでしか使っていない。
- App に残すもの: 値（タブ、畳む、広げる、下書きを開いたか、など）、それを保存・復元する処理、useEffect、プラグインの表示の判定（`activePluginView`、`isDockedPluginRuntimeVisible`）。右サイドバーの直前にある、Zone で右端に触れると出すための `zoneRightSidebarHoverTarget` も App に残す（CSS の `+ .rightSidebar` が隣り合いを前提にしているが、部品は DOM を足さないので並びは変わらない）。
- App から部品へは、JSX が今読んでいる App の値と関数を、同じ名前の props で渡す（約90個）。移す JSX を1文字も変えずに済む。
- App の外側（モジュール）にあって、ほかでも使う関数の扱い:
  - `isTauriRuntime`: ほかの部品（`WindowControls.tsx`、`IdeaPane.tsx`、`projectEntryActions.ts`）と同じく、新しいファイルにも1行で書く。
  - `referenceFileKey`、`mergeReferenceFiles`（と、それが使う `referenceKey`）: App の中でも使うので、`src/referenceFileKeys.ts` へ移して、App と部品の両方から読む。
  - App の中だけの型（`AppMode`、`ToastAction`、`ProofreadIgnoredByPath`）: `ideaThreadActions.ts` と同じく、新しいファイルに写す。食い違えば型検査で落ちる。
- テスト: `test:v061-plugins` は App.tsx の中で `<aside>` の位置（プラグインの置き場所が中にあり、プラグインの本体と資料のカードが後ろにある）を確かめている。部品のファイルで「置き場所が aside の中」、App で「`<RightSidebar` の後ろにプラグインの本体と資料のカード」を確かめるように読み先を分ける。
