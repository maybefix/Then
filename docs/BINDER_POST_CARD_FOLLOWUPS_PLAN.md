1. **置かれているボード**: 投稿の側に、その投稿のカードが置かれているボードを出し、押すとそのボードとカードへ行く。

### 気づいた点

1. **投稿のカードは、どの作品のボードにも、ライブラリ直下のボードにも置ける**（投稿はライブラリで共有）。置かれているボードを出すには、ライブラリ直下と全作品の `.then/boards/*.canvas` を読む。ライブラリに入っていない作品は、その作品のボードだけ。
2. **ほかのフォルダのボードを開くには、作品の切り替えが要る。** `openIdeaCanvasBoard` は開いているフォルダのボードしか開けない。切り替えたあとにボードを開く仕組みは今はない（足す）。
3. **埋め込みの Canvas は、すでに投稿の ID の HTML5 ドラッグを受け取れる**（1572-1610）。U7 は、アイデアのペインの行に「つかむ場所」と `dragstart` を足せば済む見込み。
4. **ドラッグに `text/plain` を付けると、本文（エディタ）に落としたとき文が入る。** U6 に当たるので、`CANVAS_POST_DRAG_MIME` だけを付ける（見込み。テストで確かめる）。
5. **別ウィンドウの Canvas へ、メイン画面から HTML5 のドラッグが届くかは分からない。** 4-3 で「届かない」としたのはバインダーのポインタのドラッグ（窓の外へ出られない）。HTML5 のドラッグは、WebView2 の窓どうしで届く可能性がある。試していない。工程9で確かめる。
6. **「投稿にする」は、作った投稿の ID を知らない。** 置き換えるには、メイン画面が作った投稿の ID を返す必要がある。Rust の `posts_add` は一覧を返すので、`add` の前後の一覧の差で ID が分かる（Rust は変えずに済む見込み）。
7. **4-4 の置き換えの作り（`CardConversion`）が、ほぼそのまま使える。** 違うのは、置き換え先が投稿のカードであること、戻すときにゴミ箱へ移す代わりに投稿を消すこと。
8. **テキストカードの欄のうち、投稿のカードにないもの**: タイトル（`title`）、書字方向（`writingMode`）、フォント（`fontSource`）、元の印（`thenOrigin`）、スレッドの欄。置き換えるとカードからは消える（元に戻すと戻る）。今の「投稿にする」は、タイトルを投稿に入れない（本文だけ）。
9. **文字列を確かめるテスト（`text-deps`）**: `CanvasWindowApp.tsx` は `test:performance` の `createLatestFrameScheduler` だけ（触らない）。`App.tsx` は多いが、今回触る近く（`canvasPosts`・「投稿にする」の受け口）を読むのは `test:project-portability` の「`const refreshPortableProjectState = useCallback` から `const openIdeaCanvasBoard` まで」の切り出しだけ。その間に足さないようにする。`PostStreamPane.tsx`・`usePostStream.ts`・`link_index.rs`・`canvasToManuscript.ts` を文字列で読むテストはない（すべて動かすテスト）。

| 操作 | 画面で起きること | 内部の処理 |
|---|---|---|
| テキストカードを選んで「投稿にする」 | 書けたら、カードが同じ場所・大きさ・色の投稿のカードに変わる。状態の欄とメイン画面の通知に「N件を投稿にしました」（通知に「元に戻す」） | Canvas が `{ rootPath, conversionId, cards: [{ id, text }] }` を頼み、メイン画面が1件ずつ投稿にして、`{ made: [{ id: カードの ID, post: 投稿の ID, hash }], failed }` を返す（4-4 の `requestManuscriptFromMain` と同じ頼みと答え）。Canvas は `made` のカードだけ置き換える |

### K8 の直し方（決めたあとの調べ）

原因: ボードの保存（`CanvasWindowApp.tsx` 2210-2240 の保存の effect）が、変更のたびに状態の欄（`status`）を「保存中」にし、0.5 秒後に「保存済み HH:MM:SS」にする。操作の知らせ（「原稿を N 本作りました」「接続線を作成しました」など、`setStatus` の約40か所）も同じ欄に書くので、その操作のボードの変更の保存が、すぐに知らせを上書きする。

直し方: 状態の欄を2つの値に分ける。

- **保存の状態**（読み込み中・ボードがありません・保存中・保存済み）: 保存と読み込みだけが書く。
- **操作の知らせ**: 今の `setStatus` の呼び出し（保存の失敗も含む）。あれば、保存の状態より先に出す。
- 知らせを消すのは、次に利用者がボードを変えたとき（`pushHistory`・Ctrl+Z・やり直し）だけにする。時間で消さない。知らせを出した操作そのものの変更（`pushHistory` は知らせより前に呼ばれる）では消えないので、その保存では上書きされない。次の変更からは、今と同じく「保存中」「保存済み」が出る。

決めた範囲のうち、これで変わること: Canvas の状態の欄だけ。メイン画面の通知、保存のしかた、文言は変えない。知らせのあとにボードを変えずにいると、その間の保存の状態は見えない（知らせのほうを出す）。保存に失敗したときは、失敗の文が知らせとして出る（今と同じ）。
