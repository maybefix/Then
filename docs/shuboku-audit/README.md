## 再検査

以下は順に実行する。各コマンドで結果を更新する。

```powershell
npm run audit:shuboku -- --check
npm run audit:typewriter-guides -- --check
npm run audit:shuboku:browser
npm run audit:shuboku:tests
node scripts/test-window-controls-contrast.mjs
node scripts/test-tree-row-contrast.mjs
npm run build
```

`audit:shuboku` は選択表示、キーボードフォーカス、内容のずれ、情報文字、バインダー、平面処理と罫線、プロットの枠、縦横の中央線を検査する。`audit:typewriter-guides -- --check` は実描画の色差・局所コントラスト・不可視・入力の遮断を検査する。監査結果の一時的なファイルアクセス失敗だけを短時間再試行し、保存できなければ失敗として報告する。

## 確認範囲と継続候補

実画面の17状態は、通常縦書き、ファイルを開く、テーマ選択、横書き、縦横ページ表示、原稿用紙、UI 150%、プロット入力、バインダー、校正、プロパティ、設定、コマンドパレット、本文検索、コンテキストメニュー、集中表示。架空の原稿・メモとメモリ内IPCを使用した。

実アプリのツリーでは、選択前後のファイル名の移動は明暗とも0px。簡略化したCSSフィクスチャの3px移動は確定不具合としない。プロット入力はキャレットによってフォーカスが分かるため、独自の枠を追加する変更は行っていない。

別窓Canvas/Export、プラグイン、PDF/画像カード、全設定タブ、全フォント・全倍率、OSの高コントラスト設定、実ファイルへの保存結果は、この視覚監査には含めない。比較用のStandard / Default Darkに記録された既存の薄い文字は、Shubokuの合否へ混ぜていない。
