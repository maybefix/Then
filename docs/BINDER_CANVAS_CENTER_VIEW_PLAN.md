### 気づいた点

1. **埋め込みの Canvas は、キャンバスモードを離れると外される**（7705行が `appMode === "canvas"` のときだけ描く）。戻るたびにボードをファイルから読み直す。だから「埋め込みで直す → 本文へ → 外で書き換え → キャンバスへ戻る」なら外の変更は読まれる。上書きが起きるのは、Canvas を開いたまま外で書き換えたとき。
2. **埋め込みと別ウィンドウが同時に開くのは、設定を途中で切り替えたときだけ**。別ウィンドウを開く道は `openIdeaCanvasBoard` の1つで、設定が on のときしか通らない。キャンバスモードのまま設定を on にしてメニューの「キャンバス」を押す、または別ウィンドウを開いたまま設定を off にしてキャンバスモードにする、の2通り。メインのキャンバスモードと別ウィンドウが同じボードを開くと、後勝ちになる（癖2）。
3. **左サイドバーを Canvas で出すと、今のままではバインダーで開いたファイルが隠れた本文に開く**。コルクボードには「バインダーで開いたら本文へ移る」処理（`selectBinderFile`・`openSearchResultInBody`・`jumpToProjectOutlineInBody`）があるが、`appMode === "corkboard"` だけを見ている。
4. **`save_canvas_board` は書く前に `updatedAt` を書き換える**ので、保存したあとのファイルの中身は Canvas が送ったものと違う。ハッシュで確かめるなら、Rust が書いた中身のハッシュを返す必要がある。
5. **Rust が Canvas の外でボードを書き換える場面がある**: 改名・移動（`retarget_boards`）、読み込み時の古い資料カードの削除（`load_canvas_board`）。ハッシュで確かめるなら、改名・移動の知らせ（`then-canvas-path-changes`）を受けたときに基準のハッシュを取り直さないと、次の保存が「外の変更」と誤って止まる。
6. **バインダーの素材の画像・PDF（2-5）は、Canvas へドラッグしても置けない**。ドラッグの経路は、ノート・原稿（`dragState.files`）だけを Canvas へ送る。画像・PDF は `dragState.reference` で、素材のフォルダへの移動にしか使っていない。Canvas の「資料を追加」の一覧からは置ける（見込み。コードを読んで）。
7. バインダーの幅は 320px＋レール 44px。QA の窓（CSS 1266px）で右のペインも開いていると、Canvas の幅は約 600px になる。

| 言葉 | 意味 |

| 基準のハッシュ | 読んだとき（または前回保存したとき）のファイルの中身から作る指紋。保存の前に今のファイルと比べ、違えば外で書き換えられたと分かる（`expected_hash`） |
| 後勝ち | 2か所で同じファイルを直すと、あとから保存したほうの中身だけが残ること |

### 1. データの形

- ボード: 作品の `.then/boards/<id>.canvas`（JSON Canvas）。Canvas が 0.5 秒止まったら書く。
- 左サイドバーの開閉: `appState.leftSidebarCollapsed`（本文・コルクボードで共通の1つ）。見ている段（ファイルツリー・検索など）は `appState.leftSidebarView`。
- 設定 `settings.canvasOpensInWindow`（既定 false）。

### 2. 利用者の操作と内部の処理（今）

| 操作 | 内部で起きること |
|---|---|
| 上の「本文 ▾」から「キャンバス」 | 設定が off なら、前回の中身があればそれで、なければ作品のボードを読んで、キャンバスモードにする。左の群は隠れる。右サイドバーは開いていれば出る。on なら別ウィンドウを開くか前に出し、メイン画面のモードは変えない |
| 本文へ戻る | 埋め込みの Canvas を外す。待っている保存は順番待ちが書き切る |
| 別ウィンドウで直す | 別ウィンドウがボードを保存する。メイン画面の埋め込みは知らない |
| 外のアプリで `.canvas` を書き換える | 開いている Canvas は気づかない。次に何か動かすと、Canvas の中身で上書きする |
| バインダーのノート・原稿の行を Canvas へドラッグ | 4-2 で受け口を作ったが、Canvas の画面ではバインダーが隠れているので、今は届かない |

### 3. 保存

- ボードを書くのは、開いている Canvas（埋め込みか別ウィンドウ）だけ。Rust の `save_canvas_board` は、中身を確かめずに `updatedAt` を付けて書く。
- 改名・移動では、Rust の `retarget_boards` が全部のボードを直接書き換え、`then-canvas-path-changes` で開いている Canvas に知らせる。Canvas は手元のボードの資料カードも同じように付け替える。
- ノート・原稿への書き戻しは、4-2 でメイン画面の書き込み口を通り、読んだときのハッシュで確かめる（`canvasFileWriter.ts`）。

### 4. ほかの機能との関係

- **コルクボード**: バインダーで選んだ原稿フォルダを、カードとして並べる。バインダーで開くと本文へ移る。Canvas も同じ「中央の表示」になるので、同じ規則に揃えるのが自然。
- **右サイドバー**: Canvas でも出ている（中間稿のペインは Canvas の選択を読む）。今回は変えない。
- **ホバー表示の設定**（「サイドバーをホバーで表示」）: 左は本文とプラグインの画面だけに効く。コルクボードでは押し出す形のまま。
- **作品の切り替え**: 埋め込みの中身を捨てて本文へ戻る。別ウィンドウは開いたまま、次に開くとき中身が入れ替わる。

## 工程5: 案

### 5-1. 方針

- 左サイドバーは、コルクボードと同じ規則で Canvas にも出す（開く・畳む・バインダーで開いたら本文へ移る）。カードを並べる場所を狭くしないよう、Canvas では開閉を別に覚え、既定は畳む（勧め）。
- 埋め込みと別ウィンドウは、同じボードを同時に開かないようにする（勧め）。メイン画面の中央が主で、別ウィンドウは「外へ出す」操作にする。
- 外の変更は、ボードの保存にもハッシュを付けて防ぐ（勧め）。書き戻しと同じ選ぶ画面を使う。

### 決めてほしいこと

**1. Canvas で左サイドバー（バインダー）をどう出すか**

| 案 | 利用者から見て | 手間 |
|---|---|---|
| 1-A 本文・コルクボードと同じ開閉の状態で出す | 本文で開いていれば、Canvas でも開いた状態で出る。Canvas は 364px 狭くなる | 小 |
| **1-B 同じバインダーを出すが、開閉は Canvas だけ別に覚える。既定は畳む（勧め）** | 初めて Canvas を開くとレール（44px）だけが出る。レールのファイルツリーのボタンか上の帯の「左サイドバーを表示」で開き、カードを置き終えたら畳める。本文の開閉とは互いに影響しない。幅は本文と同じ 320px | 小〜中（`appState` に `canvasLeftSidebarCollapsed` を1つ足す） |
| 1-C 畳んだ状態から開くと、Canvas の上に重ねて出す（押し出さない） | Canvas の幅は変わらない。開いているあいだ、Canvas の左の部分が隠れる。Canvas の余白を押すと閉じる | 中（重ねて出す CSS と閉じる条件を Canvas 用に作る。ホバー表示の CSS は本文向け） |

勧めの理由: 1-B は「狭くならない」と「同じバインダー」の両方を満たし、CSS を新しく作らずに済む。1-C は幅が変わらないが、カードを置きたい場所の上にバインダーが重なる。

どの案でも一緒にすること（変えると挙動が変わる所）:

- バインダーでファイル・見出し・検索の結果を開くと、コルクボードと同じく本文へ移って開く（工程1の気づいた点 3）。
- 上の帯の「左サイドバーを表示」を Canvas でも出す。
- 設定「サイドバーをホバーで表示」の左は、コルクボードと同じく Canvas には効かせない（押し出す形）。（確認1で変更: Canvas ではホバー表示にも従い、ドラッグが Canvas に入ったらバインダーを隠す。工程6）
- 4-2 のバインダーからのドラッグがそのまま届くことを、本物のバインダーから落とすテストと実機で確かめる。

**2. 埋め込みと別ウィンドウの関係（癖2: 後勝ち）**

| 案 | 利用者から見て | 手間 |
|---|---|---|
| **2-A 同時に開かない（勧め）** | 別ウィンドウを開くと、メイン画面は本文へ戻る（中央の Canvas は別ウィンドウへ移る）。別ウィンドウが開いているあいだにメイン画面で「キャンバス」を選ぶと、別ウィンドウが前に出る。別ウィンドウを閉じれば、また中央に出せる | 中（Rust が別ウィンドウの開閉をメイン画面へ知らせる。移る前に埋め込みの順番待ちを書き切る） |
| 2-B 同時に開けるまま、ボードの保存のハッシュ（3-A）で、後から書くほうに選ぶ画面を出す | 両方で直すと、そのたびに「ほかのアプリでファイルが変更されました」が出る | 小（3-A があれば足すものはない） |

| 2-D 今のまま（記録のみ） | 同時に直すと、先に書いたほうが消える | なし |

勧めの理由: 後勝ちは「同じボードが2か所で開いている」ことから起きる。2-A はその状態そのものを作らないので、選ぶ画面も出ない。今も同時に開くのは設定を途中で切り替えたときだけなので、失う使い方はほとんどない。3-A と組み合わせれば、外のアプリとの衝突も防げる。
