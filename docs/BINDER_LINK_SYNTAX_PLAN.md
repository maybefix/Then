### 気づいた点

1. **エディタはフロントマターを見ない。** App は `parseFrontMatter(markdown).body` だけをエディタに渡す（`src/App.tsx` 1841行）。だから 3-1 の規則のうち「フロントマターの `[[ ]]`」はエディタの出番がなく、3-3（右ペインの素材リスト）の担当になる。
2. **コメント行には今、行の中の装飾が1つも付かない。** `pushLineDecos`（935行）は `line.kind === "comment"` で何もせずに戻り、コメント行は `pushStructureDecos`（1,520行）が行全体の色と畳みだけを付ける。原稿の `//` の行にリンクを描くには、この行にも行の中の装飾を足すことになる。
3. **装飾には「窓」がある。** カーソルの周りと見えている所だけに全部の装飾を付け（`decorationRange`、463行）、1打ごとは変わった行だけを貼り替える（`patchWindowDecos`、1,797行）。ただしコメント行・コード行が絡むと貼り替えをあきらめて全部作り直す。コメント行のリンクを窓の中だけに付けると、貼り替えの道で付け直されずに消えるので、コメント行は**全文**で付けるのが筋になる。
4. **`findLinks` は速い。** 10万字（2,500行・うちコメント50行）で1回0.05ミリ秒、ノート扱いで0.018ミリ秒、1行だけなら0.19マイクロ秒（この調査で実測。`scripts/` には残していない）。重さの心配は走査ではなく、装飾の数と作り直しの回数のほうにある。
5. **行き先が「ない」と「2つ以上」を外から区別できない。** `LinkIndex.resolve` はどちらも `null` を返す。薄く描く・候補から選ばせるには `candidates` を外に出す必要がある（3-1 の中の小さな追加で、挙動は変わらない）。
6. **索引を同期で読む口がない。** `useLinkIndex.current` は非同期。装飾は同期で作るので、索引の実体を同期で覗く口（まだ読めていなければ「分からない」）を足すことになる。
7. **`//` の判定は行頭だけを見る。** `isSlashCommentLine`（`documentAst.ts` 57行）はコードブロックの中かどうかも `\//` の打ち消しも見ない。`findLinks` はこれをそのまま使うので、コードブロックの中の `// [[名前]]` も索引に入る（癖 Q2）。
8. **`<!-- -->` のコメント行は 3-1 の対象外。** 規則は `//` の行だけ。エディタも同じにする。
9. **`Ctrl+L` はどこでも使っていない**（App・エディタ・各画面のキー処理を検索）。
10. **索引は Tauri のときだけ動く**（`enabled: isHydrated && isTauriRuntime()`）。ブラウザで開いた見た目の確認では索引がないので、「行き先が分からない」ときの描き方を決めておく必要がある。

## 工程2: 仕組みの説明

### 言葉

| 言葉 | 意味 |
|---|---|
| 装飾（デコレーション） | 本文の文字そのものを変えずに、色や印だけを重ねるしくみ。ProseMirror の `Decoration` |
| 装飾の窓 | カーソルの周りと、画面に見えている所。ここだけ全部の装飾を付けて、打つたびの作り直しを小さくしている |
| 索引（リンク索引） | どのファイルがどのリンクを書いているかの一覧。3-1 で作った |
| 行き先 | リンクの名前やパスに当てはまる実際のファイル。当てはまるものが1つのときだけ決まる |
| ノート | ファイル一覧の `role` が `material` のファイル。エディタはノートモード（横書き・連続表示）で開く |

### 1. データの形

ファイルには何も書き足さない。画面の中だけで次の3つを持つ。

- **リンクの位置**: 行ごとに `[[` から `]]` までの範囲と、その中の名前（`|` や `#` の前まで）。本文から毎回求める（持ち回らない）。
- **行き先の数**: リンクの名前・パスごとに 0／1／2以上。索引から引く。索引の `version` が変わるまでは変わらないので、その間は覚えておく。
- **候補の一覧**: その作品のノートの名前（必要ならフォルダ付き）。索引の行き先の表から作る。

### 2. 利用者の操作と内部の処理（案）

| 操作 | 画面 | 内部 |
|---|---|---|
| ノートを開く | `[[名前]]` と `@[[パス]]` に色が付く。行き先のないものは薄い | 行ごとに読む規則を当て、索引に行き先の数を聞いて装飾を付ける |
| 原稿を開く | `//` の行の中の `[[ ]]` だけ色が付く。本文の行は今までどおりただの文字 | 同じ。原稿ではコメント行だけ対象 |
| リンクを押す（Ctrl+クリック） | その行き先をタブで開く | 装飾が付けた印から名前を取り、索引に行き先を聞き、App の「ファイルを開く」を呼ぶ |
| 行き先のないリンクを押す | 何も起きない | 行き先が決まらないので呼ばない |
| `[[` と打つ／`Ctrl+L` | 候補の一覧が出る。続けて打つと絞り込まれ、`Enter` で入る | その位置の直前の文字で絞り込み、選んだ名前を `[[ ]]` の中に入れる |
| 日本語入力の確定中 | 候補は出さない・絞り込みも止める | `isEditorComposing` が真の間は閉じたままにする |
| ファイルを改名・移動（3-1） | 本文が書き換わり、色もその場で付き直す | 3-1 が本文を書き換える → 索引が更新 → `version` が増える → 装飾を作り直す |
| ファイルを削除 | そのリンクが薄くなる | 本文は変えない（3-1 の決定）。索引の行き先がなくなる |
| 外部エディタでノートを足してアプリに戻る | 薄かったリンクが濃くなる | 戻ったときの読み直しで `version` が増える |

### 3. 保存

- 保存するものはない。装飾は画面だけ。
- 候補から選んで入れた文字は、ふつうの入力と同じ道で本文に入り、いつもの保存に乗る。保存の記録（`journal_save`）にも打鍵と同じように届く。
- 保存が終わると 3-1 がその1本のリンクを読み直し、変わっていれば `version` が増えて色が付き直す。

## 工程5: 案

### 5-1. 方針

1. **規則は1本のまま。** `linkSyntax.ts` の中に「1行を走査する」小さな関数を作り、`findLinks`（全文）はそれを行ごとに呼ぶ形に書き直す。エディタは同じ関数を行ごとに呼ぶ。規則を書いた場所は今までどおり1か所。
2. **行き先は索引に聞く。** エディタは索引の中身を持たず、「この名前の行き先は、ない／1つ／2つ以上／まだ分からない」だけを聞く。まだ分からない（索引を読む前、Tauri でないとき）は**濃いまま**にして、薄いリンクが一瞬ちらつかないようにする。
3. **装飾の置き場所は、ノートと原稿で分ける。** ノートは行ごとの装飾（窓の中だけ、今の仕組みに乗る）。原稿のコメント行は全文（貼り替えの道でも消えないように）。どちらも色だけで、組版は変えない。
4. **押して開くと候補の一覧は、本文の外に置く。** `ImageHoverPreview` と同じく、装飾が付けた印を手がかりに外側の部品が受け持つ。エディタ本体の変更を小さくする。

### 5-2. 描き方（案）

- `[[` から `]]` まで（`@` があればそれも）をひとまとまりとして色を付ける。括弧は隠さない（隠すとカーソルの動きが分かりにくくなり、打ち直しもしづらい）。
- 色は変数を1つ足し、既定はテーマの `--accent`。薄いほうは `--text-muted` を既定にする。どちらも `var(--editor-link-color, var(--accent))` の形で、テーマ側から変えられるようにする。新しい固有色は足さない。
- カーソルのある行でも色は付ける（ルビなどの記法と違い、隠す文字がないため）。
- 行き先がない・2つ以上は同じ「薄い」描き方にする（3-1 の決定4と揃う）。

### 5-3. 押して開く（決定後の形）

- **ふつうのクリックで開く**（確認1の決定1B）。ノートでも原稿の `//` の行でも同じ。`Ctrl+クリック` でも同じく開く。
- **カーソルがすでにその行にあるときは開かず、カーソルを置く。** Obsidian の Live Preview が、カーソルの入った行だけリンクを素の `[[名前]]` に戻してふつうの文字として扱うのと同じ考え方。これでリンクの名前を直せる（別の行から入って1回押すと開き、同じ行にいる間は文字として触れる）。
- 文字を選んだとき（押して引いたとき）は開かない。押して離すまで動いていない、ボタンが左、1回押しのときだけ開く。
- 行き先が1つに決まるリンクはそのファイルをタブで開く。行き先のないリンクは何も起きない。
- 行き先が2つ以上のときは、どれを指すか選んでもらう（5-5）。
- 作品の外・ライブラリをまたぐリンクは今回扱わない（3-1 と同じ）。

### 5-4. 候補（案）

- 入口は `[[` を打ったときと `Ctrl+L`（`Ctrl+L` は `[[]]` を入れて中にカーソルを置き、一覧を出す）。
- 一覧はその作品のノートの名前。同じ名前が2つ以上あるものは、フォルダを付けた形（`人物/汐見`）で出す。
