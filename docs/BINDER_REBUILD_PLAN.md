# バインダー再構築 計画書

作成日: 2026-11-09
状態: 実装中（決めごと D-1〜D-7 は 2026-11-09 に確定。1-1・1-2 は済み）
モック: [docs/mockups/binder-rebuild.html](mockups/binder-rebuild.html)

## 0. 目的

「アイデアを X のように書き、Obsidian のようにまとめ、Scrivener のように作品を書く」体験を、一続きの流れとしてつなぎ直す。

ベータ版のため、破壊的変更（Plot の廃止、Idea のデータ形式の変更）を許容する。ただし、利用者のデータは移行前に必ずバックアップし、失わせない。

## 1. いまの断絶

素材の置き場が5つあり、互いにコピーでしかつながっていない。

| 置き場 | 実体 | つながり |
| --- | --- | --- |
| Idea（スレッド・断片） | `project.json` の `ideaThreads`（「全作品で共有」設定時はアプリ側） | Canvas へコピー |
| Idea Board（Canvas） | `.then/boards/*.canvas` | Idea・Plot へコピー |
| Plot（章・セクション） | `load_project_plot_cards`（`src-tauri/src/lib.rs`）で読む `PlotCard` | 原稿ファイルとつながりがない |
| 中間稿 | `.then/boards/.intermediate-drafts/` | Canvas のスナップショット。本文へは手でコピペ |
| 原稿ツリー | 作品フォルダの `.md` | どこからも参照されない |

[IDEA_CANVAS_REQUIREMENTS.md](IDEA_CANVAS_REQUIREMENTS.md) で「送信はコピー、同期しない」と決めたため、素材を一段先へ送るたびに元とのつながりが切れる。

## 2. 完成像

素材は3段だけにし、昇格しても**同じ物のまま**にする。コピーをやめるので、同期の問題も起きない。

| 段 | 手本 | 実体 | 主な画面（モックの番号） |
| --- | --- | --- | --- |
| 投稿 | X | 1ファイルに追記する軽い記録 | 1 右ペインの投稿ストリーム |
| ノート | Obsidian | `素材/` 配下の `.md` | 2 ノート ／ 3 ボード |
| 原稿 | Scrivener | 作品フォルダの `.md`（従来どおり） | 4 コルクボード ／ 5 書く |

画面の割り振り:

- **左＝バインダー**: 「原稿／素材／投稿」の三段。いまのファイルツリーを広げた形。
- **中央＝表示の切り替え**: 本文・コルクボード・キャンバス・アウトライン。いまのトップバー右の「本文 ▾」で切り替える。
- **右＝インスペクタ**: 投稿・つながり・概要・この場面。いまのヘッダー左のドロップダウンで切り替える（右端のレールは作らない）。

## 3. 決定事項

### 3.1 エディタ

- **エンジンは一つ、設定を2つ**にする。同じ ProseMirror の土台に「原稿モード」と「ノートモード」を載せる。
- ノートモードは横書きで、縦書き・原稿用紙・タイプライタースクロール・ページ送りを使わない。文字数や進捗にも数えない。
- ルビ・傍点などの記法、保存と自動保存の仕組みは両モードで共通にする。資料の台詞を本文へ貼ったとき、そのまま通るようにするため。

### 3.2 原稿と素材のつなぎ方

**原稿の本文に `[[ ]]` は書かせない。** 読みにくくなるうえ、書き出し時に外す処理が要るため。原稿と素材は次の3つでつなぐ。

1. **フロントマターの素材リスト（主）**: 原稿ファイルのフロントマターの `materials`（3.5b）に素材ノートの一覧を持たせる。利用者は YAML を書かず、右ペインの「素材」へノートをドラッグするか「＋」で選ぶと書き込まれる。既存のプロパティの仕組み（`src/properties/`）に乗せる。
2. **`//` コメント行の `[[ ]]`（補助）**: 既存のコメント記法（[COMMENT_OUT_SPEC.md](COMMENT_OUT_SPEC.md)）の行の中でだけ `[[ ]]` を有効にする。コメントは書き出されないので安全。
3. **ノート名の自動検出（おまけ）**: ノート名が本文に出てくる箇所を数え、「原稿に登場 · 6か所」と出す。

これにより `[[ ]]` の記法はノートとコメント行にだけ入り、縦書き本文の通常の行には入らない。

### 3.3 リンク索引（バックリンク）

全ファイルを毎回読み直さない。

1. **起動時に1回だけ全部読む**。結果をファイルに残し、次回からは更新日時が変わったファイルだけ読み直す。
2. **入力中は数え直さない**。保存時にそのファイル1本だけ読み直し、リンク先の増減だけを索引へ反映する。
3. **外部エディタでの変更**は、アプリに戻ったときに更新日時を見て、変わったファイルだけ読み直す。
4. **改名**したら、そのファイルへの `[[旧名]]` を `[[新名]]` に書き換える。**削除**したら、リンクを行き先のないリンクとして薄く表示する。

既存のプロジェクト検索やプロパティ索引（`usePropertyValueIndex`）の全ファイル読み込みを土台にする。

### 3.4 Canvas

- カードはノート・投稿・原稿を**参照**する（JSON Canvas の `file` ノード）。コピーは作らない。
- Canvas 上でカードを編集したら、参照先のファイルへ書き戻す。いまの Canvas は自分の `.canvas` しか保存しないため、**書き戻しの経路を新しく作る前に、保存の部分を [CanvasWindowApp.tsx](../src/CanvasWindowApp.tsx) から切り出す**。
- 選んだカードから「この順で原稿を作る」。**中間稿はこれに統合する**（2026-11-09 決定、D-6）。
  - 中間稿の並べ替え画面（矢印から初期の順序を決め、カードを除外して並べ替える）をそのまま使う。
  - 作った原稿は、バインダーの「原稿」で選んでいるフォルダに置く。出力先は次の2つから選ぶ。
  - **カードごとに原稿を作る**（2026-11-09 決定）: カードの文章は**原稿の概要になる**。本文には入れない。
    - カードのタイトルを、原稿のファイル名と先頭の見出しにする。タイトルがなければ、文章の書き出しから名前を付ける。
    - カードの文章を、原稿の `synopsis` に入れる。本文は空から書き始める。
    - カードは、その原稿を指すカード（`file` ノード）に置き換える。カードに出すのは原稿の概要なので、見た目は元の文章のままで、「原稿」の印が付くだけになる。本文を書き進めても、カードの長さは変わらない。
    - これにより、キャンバスのカードとコルクボードのカードは同じ物（原稿の概要）の別の見え方になる。どちらで直しても、もう片方に出る。
    - 置き換えは Undo で戻せるようにする。戻すと、作った原稿ファイルも消す（ゴミ箱へ移す）。
    - 文章の長いカードは、そのまま長い概要になる。いまは手を入れない。
  - **1本の原稿につなげる**（2026-11-09 決定）: カードの文章を順につないで、本文にした原稿ファイルを1本作る（いまの中間稿の代わり）。
    - カードはテキストのまま残す。1本の原稿に何枚ものカードが入るため、置き換える先がないから。
    - 原稿には、どのカードから作ったかだけを記録する（フロントマターの `sourceCards`。値は `"ボード名#カードID"` のリスト。表示名は「元のカード」）。
  - 作った原稿は通常の原稿として書き直す。版はチェックポイントで残し、中間稿専用の保存と版管理（`.then/boards/.intermediate-drafts/`、`save_intermediate_draft`）はなくす。
  - 右サイドバーの「中間稿」ペインと、Canvas の「稿」ボタンはなくす。
  - 決定時の利用状況: 中間稿があるのはテスト用の作品の2件だけで、どちらも版は1つ。関連コードは約530行（`IntermediateDraftPane.tsx`、`intermediateDraft.ts`、`intermediateDraftStore.ts`）。

### 3.5 Plot

- Plot を廃止し、原稿ファイルごとの**概要**（フロントマター）に置き換える。
- コルクボードは「選んだフォルダの原稿を、概要カードとして並べる表示」。カードを並べ替えるとファイル順が変わる。
- 進捗（未・執・推・完・ア）は既存の `FileProgressStatus` をそのまま使う。
- **カードの単位はファイルだけ**（2026-11-09 決定）。1ファイル＝1カードで、概要はファイルのフロントマターに持つ。場面ごとに分けたい場合はファイルを分ける（Scrivener と同じ考え方）。見出し単位のカードは作らない。
- **移行は、Plot 全体を素材のノート1本「プロット（移行）」に移す**（2026-11-09 決定、D-1）。
  - 章カードは見出し、セクションカードは番号付きの小見出しと本文にする。
  - 本文中の資料リンク（`@[[...]]`）はそのまま残す。
  - 原稿ファイルの概要へは自動で割り当てない。利用者が後から書くか、ノートの文をドラッグして入れる。
  - 理由: 手元で Plot を使っていた6作品のうち、章と原稿ファイルの対応が付きそうなのは2作品だけだった。残る4作品は Plot を開発ログなどのメモ帳として使っていた（うち3作品は原稿ファイルが0〜1本）。対応が付く作品でも、場面の所属がファイルとずれていた（海辺の書斎の「最初の宛先」は第一章の下にあるが、内容は第二章）。推測で割り当てると誤りが出るため、何も失わない形に限る。
  - Plot が空の作品では、ノートを作らない。

### 3.5b フロントマターのキー（2026-11-09 決定、D-2）

- キーは英語にし、既存のプロパティ（`title` `slug` `date` `tags` `description`）と揃える。

| キー | 型 | 画面の表示名 | 例 |
| --- | --- | --- | --- |
| `synopsis` | text | 概要 | `synopsis: 書庫に眠っていた未発送の手紙。…` |
| `materials` | list | 素材 | `materials: ["[[汐見]]", "[[手紙と伏線]]"]` |
| `sourceCards` | list | 元のカード | `sourceCards: ["潮待ち郵便局#a1b2c3"]`（「1本の原稿につなげる」で作った原稿だけ。3.4） |

- 値は Obsidian のプロパティと同じ `[[名前]]` 形式にする。Obsidian で開くとリンクとして扱われ、改名時の書き換えもノートの `[[ ]]` と同じリンク索引（3.3）で行える。
- 同名のノートが複数あるときだけ、`[[人物/汐見]]` のように `素材/` からのパスを付ける。
- 画面に日本語で出すため、**キーと表示名の対応表**を新しく足す（いまのプロパティ欄はキーをそのまま表示している）。対応表はプロパティ欄・インスペクタ・コルクボードで共通に使い、キーを日本語に書き換えることはしない。
- 利用者が YAML を直接書く必要はない。概要はインスペクタとコルクボードのカードで編集し、素材はドラッグか「＋」で追加する（3.2）。

### 3.6 素材の置き場所（2026-11-09 決定、D-3）

- 素材は**作品フォルダ直下の `素材/`** に置く。外部エディタや Obsidian でそのまま読み書きでき、作品フォルダごと別端末へ移せる。
- フォルダ名は `project.json` に記録する（例: `materialsFolder: "素材"`）。利用者がフォルダを改名しても追えるようにし、コードにフォルダ名を直書きしない。
- いまのファイル一覧（`list_project_folder`）は `.then` 以外の全 `.md` を返し、その結果は次の処理にそのまま渡っている。素材をどう扱うかを、処理ごとに決めて入れる。

| 処理 | 主な箇所 | 素材の扱い |
| --- | --- | --- |
| 文字数・進捗（ライブラリ画面、ステータスバー、凡例の合計） | `src/library/libraryData.ts`、`WorkspaceSidebar.tsx` | 数えない |
| 書き出し（PDF／DOCX、投稿用テキスト） | `src/export/`、`ExportSourceSelector.tsx` | 対象にしない |
| 進捗記号（未・執・推・完・ア） | `WorkspaceSidebar.tsx` | 付けない |
| 全文検索・置換 | `projectSearchActions.ts` | 対象に含める（素材も探せるほうが便利なため）。ただし確認1で改めて確かめる |
| 見出しアウトライン・文書 AST | `src/editor/ast/projectAst.ts` | 原稿だけ |
| プラグインへ渡す一覧 | `src/plugins/pluginHostActions.ts` | 原稿と素材を区別できる形で渡す |
| App.tsx 内の `collectProjectTextFiles` 呼び出し（8か所） | `src/App.tsx` | 呼び出しごとに上の分類で決める |

- 判定は、一覧を作る側で一度だけ行い、各ファイルに「原稿／素材」の区分を付けて渡す。各処理で毎回パスを見て判定しない。

### 3.7 既存の資料の移動（2026-11-09 決定）

- いまの資料（`.then/references/imports/` の画像・PDF・テキスト）は `素材/` へ移し、素材を一か所にまとめる。
- 資料のパスを参照しているものも、移動と同時に書き換える。
  - Idea スレッドの資料リンク（`project.json` の `ideaThreads`）
  - Plot 本文の `@[[.then/references/...]]`（移行後はノート「プロット（移行）」の本文）
  - ボードの資料カード（`.then/boards/*.canvas`）
  - 資料カードの配置（`.then/reference-layouts/`）と、開いているカードの状態
- 移動の前に `.then/references/` をまるごとバックアップする。書き換えに失敗したら、移動を取り消して元のパスに戻す。

### 3.8 投稿の範囲（2026-11-09 決定、D-4）

- 投稿は**ライブラリで共有**する。ライブラリの `.then/` に1本で持ち、どの作品を開いていても同じ流れを出す。作品になる前の着想も置ける。
- 各投稿には、書いたときに開いていた作品を記録する。流れの絞り込みに「この作品」を足し、「受信箱」「すべて」と並べる。
- 「ノートにする」と、**いま開いている作品の `素材/`** にノートができる。元の投稿には、そのノートへのリンクを残す。
- ライブラリに入っていない作品を単独で開いた場合だけ、投稿はその作品の `.then/` に持つ。
- いまの設定「Ideaの管理単位」（`snippetStorageMode`: `workspace` / `profile`）は廃止する。「全作品で共有する」はアプリのデータフォルダに保存するため、作品フォルダごと別端末へ移す方針と合わないため。
- 決定時の利用状況: 設定は「作品ごとに分ける」。Books ライブラリの7作品にそれぞれ Idea があり、ほとんどは0〜1件、多いのはテスト用の作品の58件。アプリ側（`profileSnippets`）は1件。

### 3.9 同時に開いたときと、保存の衝突（2026-11-09 決定、D-5）

**アプリ内: 本文を編集できるのは一か所だけ。概要はどこからでも直せる**（2026-11-09 改訂）

- **ノートの本文**: 本文のタブで開いている間は、Canvas のカードは表示だけになる。カードをダブルクリックすると、そのタブへ移る。カードの表示はタブ側が保存するたびに更新し、タブを閉じればカードで編集できる。
- **原稿の概要**: 原稿を指すカードが映すのは概要（3.4）なので、カード・コルクボード・インスペクタ・プロパティ欄のどこからでも直せる。
  - その原稿をタブで開いているときは、ファイルへ直接書かず、開いているタブのフロントマターへ反映する。本文と概要の保存がぶつからないようにするため。
  - 開いていないときは、ファイルのフロントマターだけを書き換える（保存前の外部変更の確認は下の規則に従う）。
- Canvas が別ウィンドウのときも同じにする。「どのファイルをどこで編集中か」をウィンドウ間で共有し、別ウィンドウで直した概要はタブを持つウィンドウへ渡して反映する。
- 即時同期（両方で編集して入力ごとに反映）は採らない。別ウィンドウとの入力ごとのやり取りと、編集中のカーソルや日本語入力を崩さずに外から書き換える処理が重いため。

**外部エディタとの衝突: 保存前に確かめる（今回一緒に直す）**

- いまの `save_markdown_file`（`src-tauri/src/lib.rs`）は、開いたあとにファイルが外で書き換えられたかを確かめずに上書きする。素材を Obsidian などでも開けるようにすると、外部の編集が黙って消える場面が増える。
- 保存の前に、開いたとき（または前回保存したとき）の内容のハッシュと、いまのファイルを比べる。違えば上書きせず、利用者に選ばせる。ボタンは結果が分かる名前にする（例:「ファイルの内容を読み込む」「この内容で上書きする」）。説明文は出さない。
- 原稿にも素材にも効く。チェックポイントなどですでに使っている `expected_hash` の作法に揃える。
- アプリに戻ったときに更新日時を見て読み直す処理（3.3 の 3.）とも同じ比較を使う。

## 4. 進め方

各段階は then-safe-change の経路（チェックポイント → 手順書 → 確認 → 実施 → 自動テストの前後比較 → QA 用アプリでの実機確認 → 確認）で進める。着手前に必ず git のチェックポイントを作る。
