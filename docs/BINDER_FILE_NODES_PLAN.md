## 工程2: 仕組みの説明

### 言葉

- **file ノード（ファイルのカード）**: JSON Canvas の決まりにあるカードの種類の1つ。`{"type": "file", "file": "素材/汐見.md"}` のように、ファイルの場所だけを持つ。中身は持たない。Obsidian でも同じ形で読める。この手順書では「ファイルのカード」と呼ぶ。
- **ノートのカード／原稿のカード**: ファイルのカードのうち、指すファイルが素材（一覧の `role: "material"`）ならノートのカード、原稿ならば原稿のカード。どちらなのかはボードには書かず、開くたびに今の一覧から決める（素材の段へ移せば、ノートのカードになる）。
- **書き戻し**: カードで直した中身を、カードが指すファイル（またはそのタブ）へ書くこと。
- **書き戻しの順番待ち**: 書く先（ファイル）と、書く中身と、読んだときのハッシュを組にして並べ、1つずつ書く仕組み。今のボードの順番待ち（`canvasBoardSaveQueue`）と並べて `src/canvasBoardStore.ts` に置く。
- **ハッシュで確かめる（`expected_hash`）**: 書く前に「読んだときのファイルの中身のハッシュ」と今のファイルを比べ、違えば書かずに知らせるやり方。1-3a・1-5・プロジェクト全体の置換が使っている。

### 1. データの形

ボードの `.canvas` に足すカード:

```json
{ "id": "file-…", "type": "file", "file": "素材/汐見.md", "x": 120, "y": 80, "width": 280, "height": 220, "color": "4" }
```

- `file` は作品からの相対パス、`/` 区切り（JSON Canvas の決まりと同じ。資料カードの `sourcePath` とも同じ書き方）。
- 名前・種類・大きさのような写しは持たない（改名で古くなるのを避けるため。表示の名前はパスから作る）。
- 画面で使う中身（本文・概要・ハッシュ）はボードに書かない。Canvas が開くたびにファイルから読む。

### 2. 利用者の操作と内部の処理（案。工程5の勧めの形）

| 操作 | 内部の処理 |
|---|---|
| カードを置く | 埋め込みの Canvas では、バインダーのノート・原稿の行を Canvas の上へドラッグする（3-3 の「この場面」の素材の欄と同じ、ポインタのドラッグ）。どちらの Canvas でも、ツールバーの「資料を追加」の一覧と、別ウィンドウの横のパネルの一覧に、ノートと原稿も出し、選ぶ・ドラッグすると置く。置くとファイルを読み、カードに映す |
| ノートのカードを見る | 見出し（ファイル名から拡張子を除いたもの）と、本文（フロントマターを除く）を出す。長ければカードの中でスクロールする |
| ノートのカードを直す（タブで開いていない） | ダブルクリックで直せる状態にし、テキストカードと同じように書く。書くたびに書き戻しの順番待ちへ入れ、0.5 秒止まったらメイン画面へ渡して書く。フロントマターは読んだときのまま残す |
| ノートのカードを直す（タブで開いている） | 表示だけ。ダブルクリックすると、そのタブへ移る（埋め込みなら本文の画面に戻ってタブを選ぶ、別ウィンドウならメイン画面を前に出してタブを選ぶ）。タブ側が保存するたびにカードの表示を新しくする。タブを閉じれば、また直せる |
| 原稿のカードを見る | 見出し（ファイル名）と概要を出す。概要がなければ概要の欄に何も出さない（コルクボードと同じ） |
| 原稿のカードの概要を直す | ダブルクリックで直せる状態にする。タブで開いているかどうかに関わらず直せる。メイン画面へ渡し、メイン画面が、タブで開いていればそのタブのフロントマターへ（ファイルへはタブの保存が書く）、開いていなければファイルのフロントマターへ書く（コルクボードの `saveSynopsis` と同じ処理） |
| 外で書き換えられていた | メイン画面が `save_text_file` に読んだときのハッシュを付けて書き、違えば書かずに Canvas へ返す。Canvas は「ほかのアプリでファイルが変更されました」と出し、「ファイルの内容を読み込む」「この内容で上書きする」を選んでもらう（1-5 と同じ文言） |
| ファイルを改名・移動した | Rust がボードのカードの `file` を付け替え、開いている Canvas は `then-canvas-path-changes` で付け替える（資料カードと同じ道） |
| ファイルを消した | カードは残し、見出しだけを薄く出す。直せない |
| ボードを切り替える・Canvas を閉じる・ゴミ箱へ・送る | ボードの順番待ちと一緒に、書き戻しの順番待ちも書き切る（工程5の 5-4） |

### 3. 保存

- **ボード**: 今と同じ（0.5 秒の遅延保存、`.then/boards/<ID>.canvas`）。ファイルのカードは場所と大きさだけを書く。
- **ノートの本文**: Canvas の書き戻しの順番待ち → メイン画面 → `save_text_file`（`expected_hash` は Canvas が読んだときのハッシュ）。書けたら、新しいハッシュを次の書き戻しの基準にする。リンク索引へも知らせる（タブの保存と同じ `noteSaved`）。
- **原稿の概要**: 順番待ち → メイン画面 → `saveSynopsis`（タブで開いていればタブのフロントマター、なければ `save_text_file` とハッシュ）。
- **書く人は一人**: ファイルへ書くのは、いつもメイン画面にする（埋め込みでも別ウィンドウでも、Canvas は自分で `save_text_file` を呼ばない）。タブを持っているのはメイン画面だけなので、「タブで開いているか」を確かめてから書くまでのあいだに、別ウィンドウの古い情報で書く事故をなくすため。
- **再起動**: カードの中身はボードに書かないので、再起動のあとはファイルを読み直して出す。

### 4. ほかの機能との関係

- **タブ**: メイン画面は、開いているタブのパスの一覧を、別ウィンドウには `CANVAS_LIVE_DATA_EVENT` に足して、埋め込みには props で渡す。タブが保存したら、そのパスと新しい中身とハッシュを全部の窓へ知らせる（新しい知らせ `then-canvas-file-saved`。改名の知らせと同じく `emit`）。
- **コルクボード・この場面・プロパティ欄**: 概要の書き込み口は同じ（`synopsisWriter.ts`）。カードで直した概要は、タブで開いていればタブへ入るので、そのまま「この場面」やプロパティ欄にも出る。
- **リンク索引・つながり**: ノートの本文の書き戻しは、タブの保存と同じくリンク索引へ知らせる。「置かれているボード」は、ファイルのカードも数える（Rust の `board_references`）。
- **改名・移動**: Rust の `retarget_board` と、Canvas の `retargetCanvasReferenceNodes` に `file` を足す。
- **ほかの作品へ送る**: 工程5の 5-5。
- **中間稿**: 中間稿はテキストカードだけを並べるので、ファイルのカードは入らない（4-4 で扱う）。
- **投稿へコピー**: テキストカードだけ。ファイルのカードは今のところ対象にしない。

## 工程5: 案

### 5-1. 方針

- カードは JSON Canvas の `file` ノードにする（3.4 の決定どおり。Obsidian でも読める形）。
- ファイルへ書くのはメイン画面だけ。Canvas は書き戻しの順番待ちで頼み、答えを待つ。
- 書き戻しは、いつも読んだときのハッシュを付ける（3.9）。
- 書き戻しの順番待ちは `src/canvasBoardStore.ts` に `canvasBoardSaveQueue` と並べて置き、書き切る所もボードの順番待ちと並べる。

### 5-2. 書き戻しの順番待ち（`canvasFileWriteQueue`）

- 型は新しい `src/canvasFileWriteQueue.ts`（`canvasBoardSaveQueue.ts` と同じく React を使わない）。実体は `canvasBoardStore.ts` で1つだけ作る。
- 入れるもの: `{ rootPath, path, kind: "body" | "synopsis", text, baseHash }`。同じファイル・同じ種類のものがまだ書かれていなければ、新しい `text` で置き換える（入力のたびに書かない）。
- 1つずつ書く。書けたら、返ってきたハッシュを、同じファイルのまだ書いていない分の基準にする。
- 返る結果は、`saved`（新しい中身とハッシュ）・`tab`（タブへ入れた）・`open-in-tab`（ノートがタブで開いていたので書かなかった）・`conflict`（外で変わっていた。今の中身）・エラー。
- `flush()` は、今入っているものを全部書くまで待つ。失敗したものは順番待ちに残す（ボードの順番待ちと同じ）。

### 5-3. メイン画面の書き込み口

- 新しい `src/canvasFileWriter.ts` に、React に依存しない処理として置く（`synopsisWriter.ts` と同じ「host」を受け取る形）。App.tsx からは host を渡して呼ぶだけにする。
- 概要: `saveSynopsis(host, path, text, base)` をそのまま呼ぶ。
- 本文: タブで開いていれば書かずに `open-in-tab` を返す。開いていなければ、読んだときのフロントマターを残して本文だけ差し替え、`save_text_file` にハッシュを付けて書く。書けたら `linkIndex.noteSaved` を呼ぶ。
- どちらも、書けたら `then-canvas-file-saved` を全部の窓へ送る。
- 別ウィンドウからは `then-canvas-file-write`（頼みの ID 付き）で受け、`then-canvas-file-write-result` で答える。埋め込みは props の関数で同じものを呼ぶ。

### 5-4. 書き切る所

工程3の表のとおり（`loadBoardList`・`submitTransfer`・`trashBoardAndRefresh`・閉じるときの useEffect で書き切り、`openTransfer` では書き切らない）。

### 5-5. ほかの作品へ送るとき

- **ファイルのカードは、テキストカードに変えて送る（勧め）。** 見出しをカードの題、本文（原稿なら概要）をカードの文章にする。送り先の作品には同じノート・原稿がないので、指したままだと切れる。資料（画像・PDF）のように「写す」と、送り先の作品に同じ名前のノートが増え、原稿なら原稿の段に原稿が増えてしまう。
- ほか: 「写す」を選べば、ノートは送り先の素材フォルダへ写してファイルのカードのまま送る（原稿はテキストカードに）。外す（カードを消す）。

### 5-6. 置く入口

- 埋め込みの Canvas: バインダーのノート・原稿の行を Canvas の上へドラッグ（3-3 の素材の欄と同じ作り）。
- 両方の Canvas: 「資料を追加」の一覧と、別ウィンドウの横のパネルの一覧に、ノートと原稿も出す（別ウィンドウにはバインダーがないため）。一覧の並びは今の資料の一覧の規則に、ノート・原稿の段を足す形にする。
- ファイルのカードを開く（タブで見る）入口: カードの見出しの右に「開く」のボタンを置く（ノートも原稿も）。ノートのダブルクリックは「直す」、タブで開いているノートのダブルクリックは「タブへ移る」。
