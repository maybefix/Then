# 不具合の記録

## 2026-10-13: 選択範囲を IME 変換で置き換えると、変換候補が置き換わらずに積み重なる

- **確認された対象と挙動:** Tauri 開発版の縦書き原稿で、本文の文字列を選択した状態で日本語 IME の入力を始め、変換候補を切り替えると、候補が置き換わらずに本文へ追加されていく。例として「た」の変換候補を順に切り替えると、本文が「た春田春多春他春足春タ春太春汰春陀春唾春舵春…」のように増えた。段落の一部を選択して「ちばけん」と入力した場合も、「チバケン船橋市に千馬兼船橋市に…」のように、選択していた文字列と変換中の文字列が重複した。
- **期待する挙動:** 選択範囲が変換中の文字列に置き換わり、候補を切り替えるたびに変換中の文字列だけが入れ替わる。
- **切り分け:** `prosemirror-view` を 1.42.6・1.42.3・1.41.9（セキュリティ更新前の版）に切り替えて試し、すべてで再現した。ProseMirror の更新による不具合ではなく、更新前からある Then 側の問題と判断した。選択範囲がない状態での変換入力では起きていない。
- **見込み:** 候補を切り替えるたびに前の候補が残る症状は、変換の途中で変換中の文字を含む DOM がエディタに書き換えられ、IME が変換範囲を見失ったときに起こりやすい。選択範囲があると、変換開始時に ProseMirror が DOM を描き直す。そこに Then の処理が重なっている可能性がある。疑わしいのは次の処理（`src/VerticalTextEditor.tsx`）。
  - `handleCompositionStart` から同期的に呼んでいる `renderLineBreakMarks()`
  - `compositionend` の1フレーム後に流す `refreshComposition` 付きのトランザクションと、それに伴う装飾の作り直し（IME は変換の区切りごとに `compositionend` → `compositionstart` を続けて投げる）
  - 禁則処理などの装飾 span（`.ks-line-head-ban` / `.ks-line-end-ban` / `.ks-keep-short`）の作り直し
- **調べ方:** 変換中に editor の DOM がどう書き換えられているかを `MutationObserver` で記録する仕掛けを入れ、実機の IME で一度操作して、変換中の文字を含むノードを書き換えている処理を特定する。ブラウザ画面からの合成イベントでは実際の IME の挙動（選択範囲の削除や変換範囲の管理）を再現できないため、実機での操作が必要。
- **状態:** 未修正。原因は特定していない。

## 2026-09-25: コマンドスイッチャーを Esc で閉じると本文カーソルが先頭へ移る

- **確認された対象と挙動:** インストール済み Then と Tauri 開発版の縦書き原稿で、本文の途中から Ctrl+P を開き Esc で閉じると表示範囲が原稿先頭へ移る。
- **期待する挙動:** モーダルを開く前の本文表示位置とカーソル位置を保つ。
- **切り分け:** 背景クリックで閉じる場合と、本文上で直接 Esc を押す場合は先頭へ戻らない。Esc 後のフォーカス復帰で本文のスクロール量が変化する。`focus({ preventScroll: true })` と復帰の遅延だけでは防げず、インストール済みの同じビルドでも再現した。カーソルを末尾に置き、画面を50行目付近へスクロールした自動計測では、Esc 直後に末尾へ移るのを確認した。
- **修正:** パレットを開く前の本文スクロール量を記録し、Esc・背景クリックで閉じるときは元の要素へフォーカスを戻してからスクロール量を復元する。コマンド実行時には復元しない。
- **確認:** ヘッドレス Edge の CDP 計測で、Esc 後の表示範囲が50行目付近のまま1.2秒間維持された。`scripts/test-command-palette.mjs` でフォーカス復帰時にスクロールする条件を再現し、復元を検証した。
- **状態:** 再修正と自動計測済み。更新版のインストール済み Then では未確認。
