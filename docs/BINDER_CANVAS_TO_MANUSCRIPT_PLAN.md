# 「この順で原稿を作る」（BINDER 4-4）の手順書

Canvas で選んだカードを、並べ替えの画面で順序を決めてから原稿にする。出力は2つ。「カードごとに原稿を作る」は、カード1枚を原稿1本にし、カードの文章を原稿の概要（`synopsis`）に入れ、カードをその原稿を指すファイルのカード（4-2 の `file` ノード）に置き換える。「1本の原稿につなげる」は、カードの文章を順につないだ本文の原稿を1本作り、カードは残してフロントマターの `sourceCards`（表示名「元のカード」）に記録する。中身は [BINDER_REBUILD_PLAN.md](BINDER_REBUILD_PLAN.md) の 3.4（D-6・D-7）と 4-4。

変えないもの: 中間稿の画面・保存（右サイドバーの「中間稿」ペイン、Canvas の「稿」ボタン、`.then/boards/.intermediate-drafts/`、`save_intermediate_draft`）は 4-4 では消さずに残す（退役は 4-4b）。コピーカードの移行（4-5）には手を付けない。ボードの保存形式（`.canvas`）・ファイルのカードの形・書き戻しの経路（4-2）・Rust の命令は変えない見込み。画面に説明の文は足さない。

### 気づいた点

- 中間稿の並べ替えは「ボードのテキストカード全部」が対象で、選んだカードだけを取る口はない。`captureDraft` はボードを受け取るだけなので、選んだカードだけのボードを渡せば、そのまま使える（矢印は、選んだカードどうしのものだけが効く）。
- 並べ替えの一覧（ドラッグ・上下・除外）は `DraftEditor` の中に直に書かれていて、部品になっていない。流用するなら、一覧だけを部品に切り出す。
- 中間稿はカードの**タイトルを使わない**（`captureDraft` は `text` だけを取る）。
- 概要を書く `writeSynopsis` は改行を取り除く（プロパティ欄の text と同じ扱い）。段落が2つ以上あるカードを「カードごと」にすると、概要では1続きの文になり、カードの見た目が変わる。
- `create_text_file` が書く先頭の見出しは、ファイル名（「-2」付きのこともある）から作られる。4-4 では中身を自分で書くので、見出しはカードの名前にできる。
- 新しいファイルはフォルダの後ろに**名前順**で並ぶ（並び順に名前がないため）。「この順で」作っても、並び順を書かなければバインダーではあいうえお順になる。
- スレッド（近くに落として親子にしたカード）の親をファイルのカードにすると、子の `threadParentId` がテキストでないカードを指すことになり、次に読んだとき（`normalizeCanvasDocument`、`canvasTypes.ts` 634〜646行）黙ってスレッドから外れる。たたんでいた子は、そのとき急に現れる。
- ファイルのカードには `writingMode`（縦書き・横書き）と `fontSource` がない。置き換えるとカードの書字方向とフォントの指定は消える（色は `color` で残せる）。
- ライブラリのボード（作品の外）は `rootPath` がなく、ファイルのカードを置けない。原稿も作れない。
- 「投稿にする」は、グループとカードを一緒に選ぶとカードだけ、グループ1つだけを選ぶと中のカード、と対象の決め方が表示設定（和を取る）と違う。

## 工程2: 仕組みの説明

### 言葉

| 言葉 | 意味 |
|---|---|
| テキストカード | 文章を書くカード（`type: "text"`）。タイトル（`title`）は付けても付けなくてもよい |
| ファイルのカード | ノート・原稿を指すカード（`type: "file"`、4-2）。ボードにはファイルの場所だけを書き、原稿なら概要を映す |
| 並べ替えの画面 | 中間稿の「並べ替え」タブの一覧。行ごとに、つまみ（ドラッグ）・番号・抜粋・除外・上下がある |
| 概要 | 原稿のフロントマターの `synopsis`。コルクボードのカード・インスペクタ・ファイルのカードで直せる |
| 元のカード | 原稿のフロントマターの `sourceCards`。`"ボード名#カードID"` のリスト |
| 原稿のフォルダ | バインダーの「原稿」の段のフォルダ（素材のフォルダではない） |

### 1. データの形

- ボード: `nodes`（カード）と `edges`（線）。線の `connector` が `arrow`（または未指定）なら矢印として順序に効く。
- 中間稿の取り込み（`DraftCapture`）: `cards`（ID と文章）、`order`（ID の並び）、`excluded`（除外した ID）。
- 作る原稿（案）: 「カードごと」は `---\nsynopsis: <カードの文章>\n---\n# <名前>\n`。「1本」は `---\nsourceCards:\n  - "<ボード名>#<ID>"\n  …\n---\n# <名前>\n\n<カードの文章>…`。

### 2. 利用者の操作と内部の処理（今）

| 操作 | 内部 |
|---|---|
| 「稿」を押す（埋め込み） | 右サイドバーの「中間稿」タブを開く |
| 「稿」を押す（別ウィンドウ） | 右の横のパネルに中間稿を出す |
| 「取得」 | ボードのテキストカード全部を `captureDraft` で並べる |
| 並べ替え・除外 | `moveDraftCard`・`toggleDraftCard`。取り込みはメモリの中だけ |
| 「テキストを生成」 | `generateDraft` で文章にし、版として `.then/boards/.intermediate-drafts/` に保存 |
| 選んだカードの「投稿にする」 | 文章を1枚ずつ投稿にする（メイン画面へ知らせる） |

### 3. 保存

- ボード: 0.5 秒後にまとめて保存（4-1 の `canvasBoardSaveQueue`、4-3 で `expected_hash` 付き）。
- 原稿の作成: Rust の `create_text_file`（空の原稿）→ 中身を `save_text_file`（作った直後のハッシュ付き）で書く、の2回。ファイルへ書くのはメイン画面だけ（4-2 の決まり）。
- 並び順: `reorder_project_entries` で、フォルダの `order` を書き直す。
- ゴミ箱: `delete_project_entry_to_trash`（OS のゴミ箱、だめならアプリのゴミ箱）。

### 4. ほかの機能との関係

- コルクボード・インスペクタ: 作った原稿の概要は、そこでも見え、直せる（3.4 の「同じ物の別の見え方」）。
- リンク索引（3-1）・つながり（3-4）: 作った原稿は、次の読み込みで索引に入る。ボードに置いたファイルのカードは「置かれているボード」に出る。
- チェックポイント: 作った原稿は普通の原稿なので、ほかと同じく残る。
- 中間稿: 4-4 では触らない。並べ替えの一覧だけを共通の部品にする（案 1 のとき）。
