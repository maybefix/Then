## 工程2: 仕組みの説明

### 現在

Appが右クリック時の選択範囲と座標を記録し、`EditorContextMenu` に渡す。メニューの各ボタンは既存の編集操作を呼ぶ。開閉状態、外側クリック・Escapeの共通処理、本文の編集・保存はAppまたは既存の操作モジュールにある。

`EditorContextMenu.tsx` は高さ322にプラグイン分を足して位置を決める。実際のボタン・見出し・区切り線の高さとは一致しない。項目が縦に並ぶため、高さ自体も大きい。

### 修正後

ミニツールバーはよく使う操作の近道とする。下のメニューはグループだけを並べ、選んだグループの子メニューを横に開く。選択範囲は右クリック時の控えを引き続き使う。

開いている階層、フォーカス、表示寸法はメニュー内だけの一時的なUI状態とする。本文の値・作品・保存先の値は移さない。表示を変えても、ルビ・縦中横・圏点・クリップボード・AI・プラグインの処理は既存の関数を呼ぶ。

| 対象 | 読む／書く／呼ぶ | 方針 |

## 工程5: 案

### 案A（勧め）: ミニツールバーに6操作

上段の1列に、切り取り・コピー・貼り付け・ルビ・縦中横・圏点を置く。アイコンや短い表記にも、操作名のラベルとツールチップを付ける。

下段は次の4項目（プラグインがなければ3項目）にする。

| 親の項目 | 子メニュー |
|---|---|
| AIに渡す | その場で既存のAI欄へ渡す |
| 独自記法 › | ルビ...／縦中横／圏点／記法をクリア |
| 行の操作 › | 文章方向...／原稿を整える... |
| プラグイン › | 選択範囲用として登録されたコマンド。長い一覧は子メニュー内でスクロール |

ツールバーにある記法も、キーボードや操作名から探せるように子メニューへ残す。元の全10操作を維持し、Excelのフォント名・文字サイズなど新しい編集機能は追加しない。

### 案B: ミニツールバーに3操作

ツールバーは切り取り・コピー・貼り付けだけ。下段の階層は案Aと同じ。見た目はさらに簡素になるが、ルビ・縦中横・圏点は子メニューを開いて選ぶ。

### 両案共通の収め方

- 外側の寸法を実際に測り、右クリック座標から画面内へ補正する。322などの推定高さは使わない。
- 子メニューは右へ開くことを基本に、右へ入らなければ左へ開く。縦方向も独立して補正する。
- 画面が小さい場合や拡大率が大きい場合には、利用できる高さを上限にし、一覧内をスクロールさせる。横幅にも画面内の上限を設ける。
- 親メニューから子メニューへ移る途中で閉じないようにする。クリックでも階層を開けるようにする。
- 矢印キー・Home／End・Enterで選び、右矢印で階層を開き、左矢印で戻る。Escapeは開いている階層を閉じ、親の状態なら全体を閉じる。無効な項目は飛ばす。
- 選択なし・複数行の制限は既存どおり。子メニューを開く操作だけで本文の選択の控えを変えない。
