# Canvasのボード切り替え時の保存先混同を修正

## 不具合

ボードAの編集後、500msの自動保存待ちの間にBへ切り替えてCanvasを閉じると、Aの保存先にBの内容を保存してしまう。保存待ちの情報に本文が含まれず、終了時に表示中のボード参照から本文を取得していたため。同じ名前・内容のボードが複数できたように見え、Aの元の内容を失う。

範囲や作品の切り替えでも、切り替え途中の保存先と読み込み前の本文が組み合わさる危険があった。

## 修正

- 保存要求に範囲・作品パス・ボードID・本文のコピーをまとめて保持する。
- 保存を直列化し、古い保存の完了で新しい編集を消さない。
- 切り替え前に保存完了を待つ。失敗時は要求を保持し、読み込みへ進まない。
- ボードの保存先は読み込み成功時に確定する。遅れて完了した古い読み込みは反映しない。
- 画面が作り直されても同じ保存キューを使い、前の画面の保存を待ってから読む。
- 削除前にも保存を待ち、画面終了時は保存要求自身の本文だけを保存する。

## 検証

`npm run test:canvas-save` は実際のCanvasコンポーネントをReact/JSDOMで動かし、ファイルI/Oに相当する呼び出しを隔離したメモリ上のボードに接続する。

編集直後の切り替え・終了、保存中の切り替え、保存失敗と再試行、作品／共通の切り替え、別作品への切り替え、読み込みの順序逆転、再マウント、削除、StrictModeを検証する。保存キュー単体では本文コピー、同時編集、同名IDの保存先分離も確認する。

中間稿機能は `npm run test:v063-draft`、型チェックとフロントエンド生成は `npm run build` で確認する。

この修正は既存の破損データを自動修復しない。中間稿履歴からの復元ではカード本文・ID・順番を利用できるが、元の配置や接続線など、履歴に保存していない情報は復元できない。
