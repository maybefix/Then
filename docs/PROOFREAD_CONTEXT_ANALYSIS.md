# 異字同訓と文脈解析

## Sudachi・GiNZA試験版の使い方

ブランチ：`codex/proofread-sudachi-ginza`。先行実装の異字同訓ルールを含む。

WindowsのPython 3.13で動作確認。プロジェクト直下で次を実行する（この作業環境では導入済み）。

```powershell
python -m venv .venv-nlp
.venv-nlp/Scripts/python.exe -m pip install -r scripts/nlp/requirements-lock.txt
npm run tauri:dev
```

右側の「校正」→「指摘」→「文脈解析（試験機能）」でモードを選び、「この原稿を解析」を押す。

- **形態素解析＋連語辞書**：SudachiPyで品詞・原形・位置を取得し、常時動作するルールと同じ手掛かり語の表（報告の全項目）を照合。活用形と、「お茶」のように分かち書きが割れる語に対応する。
- **係り受け解析＋確認ルール**：GiNZA標準モデルで同じ文の語の関係を取得。「期待に十分答える」のような離れた連語も照合。解析器の誤推定で直近の連語を見落とさないよう、Sudachiの検査も併用する。「趣味・楽しみ・目標・目的は」と動詞述語の対応も、限定的な確認候補として示す。

出典は校正のルール欄に表示する。係り受けは意味の正しさを保証しない。前後8トークン程度の範囲に限定し、主語省略、長距離の関係、比喩、人物・時系列の整合性を一般的に判定するものではない。

本文・ファイル・設定・辞書・モードを変更すると前回の文脈解析結果は非表示になり、再解析を促す。文脈解析結果も既存の無視・ルール停止・項目停止・辞書保護に対応する。近接照合と重複する異字同訓の指摘は文脈解析の説明を優先する。

### 実行方式と配布上の制限

- 端末内でのみ解析。原稿をネットワークへ送信せず、一時ファイルにも保存しない。
- 1回12,000 UTF-16単位まで。上限超過は黙って切り捨てず、実行不可として案内する。
- 手動実行、同時実行は1件、タイムアウト90秒。編集操作とは別プロセスで解析する。
- 現段階は各実行でモデルを読み込む。常駐化・段落キャッシュは未実装。
- **今回のPython実行環境は開発用で、通常のNSISインストーラーへは同梱していない。** Rust側はビルド元プロジェクトの `.venv-nlp/Scripts/python.exe` を使う。同じ開発PCでは使えるが、別PCにThen.exeだけを移しても文脈解析は使えない。配布対応時にはPython・モデル・辞書の独立した同梱とライセンス通知を整備する。
- GiNZA 5.2.0、ja_ginza 5.2.0、SudachiPy 0.6.11、SudachiDict-core 20260723、spaCy 3.8.7。最新版spaCy 3.8.16ではモデルの設定読込みに失敗したため、互換性を確認した構成をlockファイルに保存した。

### 検証

三点リーダー等の内部正規化により、Sudachiが長さ0の空形態素を返すことがあるため、Python側で除外する。起動済みの旧バックエンドへの互換処理として、画面側も形態素解析の空の句読点だけを除外する。係り受けノードや実際の本文不一致は除外せず検証を維持する。マスク文字は共有の `MASK_CHAR` を使い、解析前に同じ長さの空白へ変換する。

```powershell
npm run test:proofread
npm run test:proofread-nlp
npm run test:proofread-nlp-ui
cargo test --manifest-path src-tauri/Cargo.toml --offline proofread_nlp -- --include-ignored
npm run build
```

実モデルの統合テストでは、連語・活用・介在する副詞・正しい語法・別の係り先・文や段落の境界・会話・ルビ・コード・UTF-16位置・無効化を検証する。検証用の人工例と解析結果は `test-artifacts/nlp` に出力される。利用者の原稿はテストに使わない。

## 常時動作する異字同訓ルール

`ijidokun` は、報告の**全項目**を対象にする。連語をひとつずつ書く方式をやめ、報告の用例から起こした手掛かり語の表を引いて、文脈が別の表記を指すときだけ確認を出す。Pythonを入れていなくても動く。

対象は128項目・299表記・1,002語の手掛かり。報告の133項目のうち、用例から手掛かりを取れなかった5項目（016 ある、022 うた、048 かま、120 まわり、127 よ）は入らない。

### 何を手掛かりにするか

本文に現れた表記の周りから、次の関係にある語を取り出して表と照合する。

- **格の項**：「期待に答える」の「期待に」。述語の直前へ8文字までさかのぼり、句読点・鉤括弧・マスクをまたぐものは結び付けない。
- **連体修飾の被修飾名詞**：「暑い湯」の「湯」。「乾いた土」のように助動詞が挟まる形も見る。形容詞や自動詞ではガ格の項と同じ語になるため、ガ格と連体は同じ手掛かりとして扱う。
- **複合・述語**（名詞の項目）：「立つ鳥後を濁さず」の直前の「鳥」、「脚の裏」の「の裏」、「足が出る」の述語「出る」。

活用は見出し形の最後の仮名から語尾の行を作って当てる。品詞解析はしないので拾いすぎるが、手掛かり語が一致しない限り指摘は出ない。

### 出さないための条件

- 同じ語が同じ項目の複数の表記に現れる場合は、関係が違っても手掛かりにしない（004 あく・あける の「目」など）。
- 報告が注記（\*）や併記（（　））を付けた用例は、報告自身が使い分けの分かれる例だと述べているので手掛かりにしない（「子供が生まれる\*」「体重を量る\*」など）。
- 見出しが「上がる・上げる」「揚がる・揚げる」のように自動詞・他動詞で対になる項目では、並びの位置か送り仮名がそろう語だけを候補にする。「国を建てる」を根拠に「国を立つ」を疑わない。
- 直前が漢字・片仮名のときは複合語の一部とみなし、前に付く語が決め手になる形だけを見る（「正直」「最後」「都合」を拾わない）。
- 語の切れ目は仮名で判断する。「思い出」の「思い」、「大根」の「根」のように漢字が続く末尾は別語の一部として採らない。

指摘は「参考」で、候補・語義・出典の項目番号とページを表示し、置換ボタンは出さない。項目別の停止（`ijidokun/<項目番号>`、ルール一覧では畳んで表示）、会話文除外、辞書の保護に対応。コード・URL・ルビの読みは既存のマスクに従って除外する。引用・比喩を完全には判別できないため、著者による確認を前提とする。

### データの作り方

`src/proofread/ijidokunData.ts` は生成物で、手では直さない。報告のPDFから項目・語義・用例を取り出し、用例をSudachiで解析して共起語を集める。

```powershell
.venv-nlp/Scripts/python.exe -m pip install pymupdf
.venv-nlp/Scripts/python.exe scripts/nlp/build-ijidokun.py <報告のPDF>
```

報告の用例に無い日常語（「質問に答える」「洗濯物が乾く」「司会を務める」など）は、報告が示した語義の範囲を出ない形で `src/proofread/ijidokunExtra.ts` に足す。見出しは表記そのままで書き、番号への解決と、同じ項目で既に別の表記に割り当てられている語の除外は読み込み時に行う。解決できない行は `npm run test:proofread` が落とす。

### 精度の目安

青空文庫の公開作品（『こころ』『坊っちゃん』『羅生門』『蜘蛛の糸』、約27万字）で、指摘は8件（1万字あたり0.3件）。「便宜を計る→図る」「腰を卸す→下ろす」「支度を整える→調える」のように、確認する価値のあるものが多い。本リポジトリの日本語ドキュメント約25万字では0件。処理はこの分量で60〜100ミリ秒。

根拠：文化審議会国語分科会『「異字同訓」の漢字の使い分け例（報告）』（2014年2月21日）。前書きは、異なる使い分けを否定しないと明記する。資料の語義を参考にThen独自の検出条件を作成した。

https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93927001_12.pdf

## 同音異義語ルール

`homophone` は、同じ音読みで意味の違う漢語を34組扱う。異字同訓と同じ考え方で、接する語が別の表記でしか使わない語のときだけ確認を出す。

- **直前に付く語**：「品質保証」の「品質」。「損害の補償」「損害を補償する」のように助詞で続く形も、助詞を落として名詞を見る。
- **直後に付く語**：「保証人」の「人」、「対照的」の「的」。
- **直後の述語**：「関心を持つ」の「持つ」、「感心する」の「する」。サ変動詞の活用は別に持つ。

どちらの表記でも使う語（「解放感」と「開放感」、「想像力」と「創造力」、「配付」と「配布」）は決め手にならないので入れない。判断が割れる語も入れない。

異字同訓の表と違い、同音の漢語の使い分けを定めた告示・報告は無い。根拠は『記者ハンドブック』が示す使い分けの考え方で、一覧そのものは語義に沿ってThenが編んだものであることを、指摘の説明にも明記している。

誤りの例74件で71件を検出し、正しい用法では0件。青空文庫の4作品（約27万字）とこのリポジトリの日本語ドキュメント（約25万字）では、いずれも0件だった。

## 今後の拡張

手掛かり語の補いを、試験原稿での誤検出を見ながら増やす。同音異義語は組数を増やす余地があるが、判断が割れる語を入れないことを優先する。実行面では、常駐プロセス・変更段落のキャッシュ・長文対応・配布用ランタイムを整備する。人物・時系列・省略された主語の推測は、別の推敲機能として検討する。
