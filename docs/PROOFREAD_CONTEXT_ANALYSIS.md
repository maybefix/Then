# 異字同訓と文脈解析

## Sudachi・GiNZA試験版の使い方

ブランチ：`codex/proofread-sudachi-ginza`。先行実装の異字同訓ルールを含む。

WindowsのPython 3.13で動作確認。プロジェクト直下で次を実行する（この作業環境では導入済み）。

```powershell
python -m venv .venv-nlp
.venv-nlp/Scripts/python.exe -m pip install -r scripts/nlp/requirements-lock.txt
npm run tauri:dev
```

右側の「校正」→「指摘」→「文脈解析（試験機能）」でモードを選び、「この原稿を解析」を押す。

- **形態素解析＋連語辞書**：SudachiPyで品詞・原形・位置を取得し、異字同訓5組の連語を照合。活用形に対応する。
- **係り受け解析＋確認ルール**：GiNZA標準モデルで同じ文の語の関係を取得。「期待に十分答える」のような離れた連語も照合。解析器の誤推定で直近の連語を見落とさないよう、Sudachiの検査も併用する。「趣味・楽しみ・目標・目的は」と動詞述語の対応も、限定的な確認候補として示す。

出典は校正のルール欄に表示する。係り受けは意味の正しさを保証しない。前後8トークン程度の範囲に限定し、主語省略、長距離の関係、比喩、人物・時系列の整合性を一般的に判定するものではない。

本文・ファイル・設定・辞書・モードを変更すると前回の文脈解析結果は非表示になり、再解析を促す。文脈解析結果も既存の無視・ルール停止・項目停止・辞書保護に対応する。近接照合と重複する異字同訓の指摘は文脈解析の説明を優先する。

### 実行方式と配布上の制限

- 端末内でのみ解析。原稿をネットワークへ送信せず、一時ファイルにも保存しない。
- 1回12,000 UTF-16単位まで。上限超過は黙って切り捨てず、実行不可として案内する。
- 手動実行、同時実行は1件、タイムアウト90秒。編集操作とは別プロセスで解析する。
- 現段階は各実行でモデルを読み込む。常駐化・段落キャッシュは未実装。
- **今回のPython実行環境は開発用で、通常のNSISインストーラーへは同梱していない。** Rust側はビルド元プロジェクトの `.venv-nlp/Scripts/python.exe` を使う。同じ開発PCでは使えるが、別PCにThen.exeだけを移しても文脈解析は使えない。配布対応時にはPython・モデル・辞書の独立した同梱とライセンス通知を整備する。
- GiNZA 5.2.0、ja_ginza 5.2.0、SudachiPy 0.6.11、SudachiDict-core 20260723、spaCy 3.8.7。最新版spaCy 3.8.16ではモデルの設定読込みに失敗したため、互換性を確認した構成をlockファイルに保存した。

### 検証

三点リーダー等の内部正規化により、Sudachiが長さ0の空形態素を返すことがあるため、Python側で除外する。起動済みの旧バックエンドへの互換処理として、画面側も形態素解析の空の句読点だけを除外する。係り受けノードや実際の本文不一致は除外せず検証を維持する。マスク文字は共有の `MASK_CHAR` を使い、解析前に同じ長さの空白へ変換する。

```powershell
npm run test:proofread
npm run test:proofread-nlp
npm run test:proofread-nlp-ui
cargo test --manifest-path src-tauri/Cargo.toml --offline proofread_nlp -- --include-ignored
npm run build
```

実モデルの統合テストでは、連語・活用・介在する副詞・正しい語法・別の係り先・文や段落の境界・会話・ルビ・コード・UTF-16位置・無効化を検証する。検証用の人工例と解析結果は `test-artifacts/nlp` に出力される。利用者の原稿はテストに使わない。

## 先行実装：常時動作する異字同訓ルール

`ijidokun` を共通ルールに追加。答・応、熱・暑、乾・渇、直・治、習・倣の5組を、限定した隣接語と活用語尾で照合する。全文の意味解析ではなく、登録外の連語や間に修飾語が入る文は検出しない。全133項目を網羅するものではない。

指摘は「参考」で、候補と理由を表示し、置換ボタンは出さない。組別の停止、会話文除外、辞書の保護に対応。コード・URL・ルビの読みは既存のマスクに従って除外する。引用・比喩を完全には判別できないため、著者による確認を前提とする。

根拠：文化審議会国語分科会『「異字同訓」の漢字の使い分け例（報告）』（2014年2月21日）。本文5ページ008、12ページ050、14ページ057、20ページ094、21ページ097。前書きは、異なる使い分けを否定しないと明記する。資料の語義を参考にThen独自の検出条件を作成した。

https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93927001_12.pdf
