### ノートかどうかの判定

- 今あるもの: 書き出しの処理（`App.tsx:5481〜5486`）が、その場で `collectProjectTextFiles(projectFolder)` から `role === "material"` を探している。

- 案: App.tsx で `projectFolder` から素材のパスの集合を1回作って覚えておき（`useMemo`）、開いているタブのパスがそこにあればノートとする。

### 気づいた点

- エディタのタブは1つのウィンドウにしかなく（別ウィンドウはエクスポートと Canvas だけ）、同じパスのタブは2つ作らない（`openDocumentInTab` は既存のタブへ移る。`App.tsx:1727`）。ただし、ここだけパスを `===` で比べていて、ほかの箇所（`isSamePath`）と違う。大文字小文字の違うパスで2つ開ける余地がある（工程2-5 の癖3）。

- 作品の中のフォルダ（たとえば `素材` そのもの）を作品として別に開くと、そのフォルダには `project.json` がないので素材の区分が付かず、ノートも原稿モードで開く（見込み）。

## 工程2: 仕組みの説明

### 言葉

- **原稿モード／ノートモード**: 同じエディタの2つの見え方。原稿モードは今の見え方そのもの（設定どおり）。ノートモードは横書き・連続表示・原稿用紙なし・タイプライターなし。
- **ノート**: ファイル一覧で `role: "material"` が付いた `.md`。作品直下の素材フォルダ（`project.json` の `materialsFolder`）の中のもの。
- **エディタ向けの設定**: 全体の設定のうち、エディタの見え方に効く値（本文方向・編集表示・ページ送り・タイプライター・原稿用紙）。

### 1. データの形

ファイルにもアプリの状態にも、新しい値は書かない。ノートかどうかは開くたびに一覧の `role` から決まる。タブごとの表示位置（`viewportState`）は今も `writingMode` を持っていて、向きが変わると古い位置を使わずにカーソルの位置で開く（`workspaceDocumentTabs.ts:38`）。

### 2. 利用者の操作と内部の処理（案のとおりにしたとき）

| 操作 | 原稿 | ノート |
|---|---|---|
| ファイルを開く・タブを切り替える | 今と同じ | 横書き・連続表示で開く。設定が縦書き・ページ表示・原稿用紙でも、ノートには効かない |
| 書く・ルビ・傍点・コメント・検索・置換 | 今と同じ | 同じ（同じエンジン、同じ記法） |
| 保存・自動保存・外部変更の確認（1-3a） | 今と同じ | 同じ |
| 設定画面で本文方向などを変える | 今と同じ | 開いているノートの見え方は変わらない（設定は原稿に効く） |
| トップバーの縦横ボタン | 今と同じ | 決めてほしいこと 2 |
| ステータスバー | 字数・原稿用紙の枚数・ページ | 原稿用紙の枚数とページは出ない。字数は決めてほしいこと 3 |
| 開いたまま素材フォルダへ移す／素材から出す | — | 決めてほしいこと 5 |

### 3. 保存

変えない。原稿もノートも、タブの保存・自動保存・保存の記録（`journal_save`）・保存前のハッシュ確認を同じ道で通る。

### 4. ほかの機能との関係

- **1-3b・1-4（素材の区分・三段）**: 判定は一覧の `role` だけを使う。ツリーの見せ方は変えない。
- **1-5（コルクボード）**: 素材は出さない。変えない。
- **1-6（プロット（移行））**: 作品の素材フォルダに置いたものはノートモードで開く。ライブラリ直下のものは `role` がないので原稿モード（決めてほしいこと 4）。
- **1-7（この場面）**: 素材は概要だけを出す。変えない。
- **2-1（投稿）・以前のアイデア**: 触らない。
- **2-3（ノートにする）**: 計画では「いま開いている作品の `素材/`」にノートを作るので、`role: "material"` が付き、ノートモードで開く（見込み。作品に素材フォルダがないときにどうするかは 2-3 で決める。1-6 と同じく作るなら同じく付く）。
- **外部エディタ（Obsidian など）**: アプリにはファイルを外部エディタで開く機能はない。外で書き換えたときは 1-3a の確認がそのまま効く。ノートモードはファイルに何も書き足さない（フロントマターに印を付けない）ので、外から見たノートはふつうの `.md` のまま。
- **書き出し**: ノートは対象外（1-3b）。書き出しの縦横は書き出しの設定なので関係しない。

### 5. 今の挙動の癖（工程9で実機で確かめる）

1. **タブの印に、素材でも進捗の色が付く**。`DocumentTabs.tsx:414` が `fileProgress[tab.path] ?? "todo"` で、素材でも「未着手」の色と、マウスを載せたときの「進捗: 未着手」を出す。ツリーでは素材に進捗を出さない（1-3b）のと食い違う。→ 決めてほしいこと 6 で直すかを決める。
2. **ライブラリ直下の「プロット（移行）」は素材の区分を持たない**（工程1）。
3. **同じファイルを、パスの大文字小文字の違いで2つのタブに開ける余地がある**（`openDocumentInTab` だけ `===`）。今回の範囲では、モードはパスから決まるので、2つ開いても両方同じモードになり食い違いは起きない。記録だけにする。

## 工程5: 案

### 5-1. 方針

- `src/editor/noteMode.ts` に、全体の設定と「ノートか」から、エディタ向けの設定を作る関数を1つ置く。ノートなら `writingMode: "horizontal-tb"`、`editorDisplayMode: "continuous"`、`typewriterScroll: false`、`showTypewriterGuide: false`、`manuscript.layoutMode: "normal"` に差し替え、ほかの値（フォント・サイズ・行間・横書きの文字表示幅・行番号・改行マーク・現在行・鉤括弧の色・コメント）はそのまま使う。
- App.tsx では、開いているタブがノートかどうかを素材のパスの集合から決め、工程1の表の読み口をすべてその関数の結果に替える。設定画面と保存される設定は今のまま（原稿に効く）。
- ノート用の設定項目（ノートだけのフォントや幅）は作らない。
