## 工程2: 仕組みの説明

### 言葉

- **投稿**: 右のペイン「アイデア」の流れの1件。ライブラリの `.then/posts.jsonl` の1行。
- **スレッド**: 返信（`replyTo`）でつながった投稿の列。先頭の投稿と、その下の返信。
- **素材フォルダ**: 作品の `project.json` の `materialsFolder` に名前が書かれた、作品直下のフォルダ。その中のファイルは一覧で `role: "material"` が付き、ノートモードで開く。
- **リンク札**: モックの、ノートにした投稿の時刻の横に出る、ノート名の小さな札。

### 1. データの形（今）

投稿1行（2-1）: `v`・`id`・`at`・`work`（書いたときの作品の ID と名前）・`replyTo`・`body`・`edited`・`filed`。`note` は 2-1 の計画で「作品の ID と `素材/` からのパス」と決めてあり、今は書く処理がない。

### 2. 利用者の操作と内部の処理（今）

| 操作 | 内部 |
|---|---|
| 投稿・返信 | `posts_add`。末尾に1行足す |
| 本文を直す | `posts_update`（ハッシュを比べる） |
| 受信箱から外す／戻す | `posts_update`（`filed` だけ。ハッシュは比べない） |
| 削除 → 元に戻す | `posts_delete`（ハッシュを比べる）→ トーストから `posts_restore` |

### 3. 保存

投稿は Rust だけが読み書きする。ファイルの鍵（`atomic_file::with_lock`）を取ったまま読み、その行だけ差し替える。作品の `project.json` は別の鍵（`lock_project_config`）。1-6 は `project.json` の鍵を取ったまま、素材フォルダ・ノート・`project.json` の順に書き、途中で失敗したら作ったものを消した。

### 4. ほかの機能との関係

- 2-2: ノートモードは一覧の `role` で決まる。ノートを作ったら一覧を読み直してから開けば、ノートモードで開く。
- 2-4: 名前の付いた Idea スレッドを素材のノートにする（スレッド名をノートの名前、断片を段落）。2-3 で作るノートの書き方（素材フォルダの決め方・名前の重なり・本文の形）を、2-4 でもそのまま使える形にしておく。
- 3-1・3-3・3-4: リンク索引、`[[ ]]`、ノート側の「つながり」ペイン（「元の投稿」を出す）。2-3 で決める `note` の形を、3-4 は逆にたどる。
- 3.4: キャンバスのカードから原稿を作る操作は「Undo で戻すと、作った原稿ファイルも消す（ゴミ箱へ移す）」と決めてある。

### 5. 今の挙動の癖（直さないもの）

- ノートにした投稿（`noted`）でも、「受信箱から外す／戻す」のボタンは出る。押しても受信箱には戻らない（`isInInbox` が `noted` で外すため）。今は `note` を書く処理がないので、画面に出ることはない。→ 案の 5-2 で扱う。

## 工程5: 案

### 5-1. 方針

- ノートを作る・投稿にリンクを書く・失敗したら作ったものを消す、を Rust の1つの命令で行う。画面は「この投稿（とそのハッシュ）を、この名前・この本文のノートにする」を送るだけ。1-6 と同じ作りにし、途中で止まっても「ノートだけできてリンクがない」「リンクだけあってノートがない」を残さない。
- 書く順: 投稿の鍵を取る → 投稿の行のハッシュを比べる（違えば何も書かずに知らせる。2-1 と同じ）→ `project.json` の鍵を取り、素材フォルダを決める（なければ作る）→ ノートを書く → `project.json`（作ったときだけ）→ 投稿の行に `note` を書く。途中で失敗したら、その回に作ったノート・素材フォルダを消す。
- 素材フォルダの決め方と名前の重なりの避け方は、`plot_migration.rs` から共通の関数に出して両方で使う（2-4 でも使う）。

### 5-2. 決めてほしいこと

**1. 素材フォルダがないとき**

| 案 | 内容 |
|---|---|
| **A（勧め）** | 1-6 と同じ。「素材」を作って `materialsFolder` に登録する。登録されていないふつうのフォルダ「素材」があれば、それは原稿なので使わず「素材-2」を作る |
| B | 「ノートにする」を押せなくする。先にバインダーで素材フォルダを作ってもらう |

勧める理由: 1-6・2-4（決定済み）と同じ扱いになり、利用者が手順を覚えなくてよい。作ったフォルダはすぐ素材の段に出る。

**2. 作品を開いていないとき**

| 開いているもの | 勧め | ほかの案 |
|---|---|---|
| ライブラリの中の作品 | 3.8 どおり、その作品の素材フォルダに作る（投稿を書いた作品が別でも、いま開いている作品に作る） | — |
| ライブラリの外の作品を単独で開いている | 同じ（投稿もその作品の `.then/` にあるので、行き先がはっきりしている） | — |
| ライブラリ直下 | **「ノートにする」を出さない**。ライブラリ直下には素材の区分がなく、作ったノートが `role` を持たず原稿モードで開く（KNOWN_ISSUES 2026-11-14 と同じ形の食い違いを新しく作ることになる）。作品の一覧もツリーに出ないので、作ったノートが見えない | (b) 投稿に記録された作品（`work.id`）の素材フォルダに作り、その作品に切り替えてノートを開く。記録のない投稿では出さない。(c) ライブラリ直下にそのまま作る（1-6 と同じ。原稿モードで開く） |
| フォルダを開いていない | 投稿の流れ自体が出ない（2-1 の R3。今の Idea がそのまま出る）ので、何もしない | — |

**3. ノートの名前と本文の形**

- 名前: **投稿の書き出し（最初の行、記号を除いて20字まで）を初期値にして、名前を聞く**（勧め。新規ファイルと同じ入力の小窓で、確定ボタンは「ノートを作る」）。名前はあとでリンクの見え方（札）になるので、作る前に直せるほうがよい。ほかの案: 聞かずに書き出しで付ける（モックと同じく1回で済む。名前はあとで改名する）。
- 同じ名前があるとき: **「名前-2」「名前-3」… を付ける**（勧め。1-6 と同じ。上書きしない）。ほかの案: 小窓で「もうあります」と出して名前を聞き直す。
- 返信の付いた投稿: **押した投稿と、その下の返信をまとめて1本にする**（勧め。先頭で押せばスレッド全体になる。2-4 で名前の付いたスレッドを1本のノートにするのと揃う）。まとめた投稿の全部にリンクを残し、全部が受信箱から外れる。ほかの案: 押した投稿1件だけ。
- 本文: **`# 名前` の見出しのあと、投稿1件を1段落として、古い順に空行で区切って並べる。日時は書かない**（勧め。新規ファイルと同じく見出しで始め、2-4 の「断片を段落」と揃える。日時は投稿の側に残り、3-4 の「元の投稿」から見られる）。ほかの案: 段落ごとに投稿の日時（例: `11/14 10:42`）を1行添える。
- 置く場所: 素材フォルダの直下（勧め）。素材の中で選んでいるフォルダがあってもそこにはしない。

**4. 元の投稿に残すリンクの形と、付いていくか**

欄の形（勧め）:

```json
"note":{"work":"w-2b8e…","path":"素材/手紙と伏線.md"}
```

- `work` は作品の `workId`、`path` は**作品のフォルダからの相対パス**（区切りは `/`）。2-1 の計画では「`素材/` からのパス」としていたが、ノートは段の見出しへのドラッグで原稿へ出せる（1-4）ので、素材フォルダの外も表せる作品からの相対にする。素材フォルダの改名は、下の改名の処理で一緒に書き換える。
- ほかの案: `"note":"[[手紙と伏線]]"`（3.5b の `materials` と同じ名前の形）。Obsidian と揃うが、作品をまたぐので作品の ID は別に要り、同じ名前のノートが2本あると決まらない。名前での引き当ては 3-1 の索引ができるまでできない。

付いていくか（勧め）:

| 起きたこと | 勧め |
|---|---|
| Then の中でノートや、それを含むフォルダ（素材フォルダを含む）を改名・移動 | 付いていく。改名・移動の処理（`retargetPathOwners` の並び）で、そのパスを持つ投稿の `note.path` を書き換える。外す・戻すと同じく、ハッシュは比べない（本文を変えないため） |
| 外部（エクスプローラーや Obsidian）で改名・移動 | 2-3 では追わない。札は「行き先のないリンク」として薄く出し、押せない（3.3 の 4. と同じ見せ方）。3-1 のリンク索引で直す |
| ノートを削除 | 同じく薄く出す。ゴミ箱から戻せばまた押せる |

3-3 との関係: 3-3 の `materials`（原稿 → 素材）は `[[名前]]` で、3-1 の索引が改名を書き換える。投稿のリンクは作品をまたぐので形を変えるが、3-1 の索引ができたら、外部の改名もこの欄に反映する（3-1 の作業に足す）。3-4 の「元の投稿」は、`posts.jsonl` の `note` を逆にたどる。ノートの側（フロントマター）には書かない（勧め。リンクの持ち主を投稿の1か所にし、食い違いを作らない）。ほかの案: ノートのフロントマターにも `sourcePosts: ["p-…"]` を書く（3.5b の `sourceCards` と揃い、外部で改名されても投稿を探し直せる）。

**5. 投稿の流れでの見せ方**

- 「ノートにする」: 投稿の操作の右端に、文字のボタン「ノートにする」（勧め。モックと同じ位置）。色はモックの `--accent` ではなく、今の小さいボタン（`ideaMiniIcon`）と同じ中立の色にし、マウスを載せたときだけ強める。coral-light は使わない。ノートにした投稿とライブラリ直下では出さない。
- リンク札: 時刻の横に、ノートの印とノート名（モックと同じ）。押すとノートをタブで開く。いま開いていない作品のノートなら、札に作品名も添え（「潮待ち郵便局 / 手紙と伏線」）、押すとその作品に切り替えてから開く（勧め）。ほかの案: 別の作品のノートの札は押せない。
- 「ノート化済み」の絞り込み: **足さない**（勧め）。チップはもう4つ（受信箱・すべて・この作品・以前のアイデア）あり、右のペインの幅で折り返す。ノートにした投稿は「すべて」「この作品」に札つきで出る。ほかの案: モックどおり足す（5つ目）。
