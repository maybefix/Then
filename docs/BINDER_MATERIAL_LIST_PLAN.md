### 気づいた点

- **3-1 の索引は、すでに `materials` を読んでいる。** フロントマターの `[[ ]]` は原稿でも数えるので、原稿の `materials` に `[[汐見]]` があれば「汐見」へのリンクとして索引に入り、汐見を改名すれば 3-1 の書き換えで `materials` の中も書き換わる（タブで開いていればタブの文字列、閉じていればハッシュ付きでファイル）。3-3 で足すのは「画面」と「書き込み」だけで、規則と行き先はそのまま使える。
- **「この場面」は打鍵ごとに YAML を読み直している（今の挙動）。** App は打鍵ごとに描き直し、`ScenePane` は描くたびに `readSynopsis(markdown)` でフロントマターを YAML として読む。概要は打鍵では変わらないので、フロントマターの文字列が変わったときだけ読めば足りる。素材の欄を足すと、読む物がもう1つ増える。
- **書き込みは表示中のタブだけで足りる。** 「この場面」が出すのは本文に出ている文書だけなので、素材リストの書き込みはいつも `updateFrontMatter` で済む。タブで開いていないファイルへ書く経路（コルクボードの概要の `synopsisWriter.ts`）は要らない。
- **バインダーのドラッグは `elementFromPoint` で落とす先を探している。** 右のペインの素材の欄に目印の属性を付ければ、同じ仕組みで「素材の欄に落とした」が分かる。App を通さずに済む。
- **名前に `#`・`|`・`[`・`]` を含むノートは、`[[名前]]` で指せない**（3-1 の規則で `#` と `|` の前までが名前になる）。3-2 の候補はこれも出している。3-3 の「＋」とドラッグで足すと、行き先の違うリンクになる。
- **3-2 の「リンクを直して開く」はそのまま使える。** 直すのは `rewriteTarget(next)` に任されているので、素材の欄では「その項目の名前を書き換えて `updateFrontMatter`」を渡せばよい。直したあとの保存と「元に戻す」は全文で行うので、フロントマターの変更にもそのまま効く（「元に戻す」は `applyToActiveTab` で全文を戻す）。

## 工程2: 仕組みの説明

### 言葉

| 言葉 | 意味 |
|---|---|
| 素材リスト | 原稿のフロントマターの `materials`。値は `[[名前]]` を項目にしたリスト。画面では「素材」と出す |
| ノート | 一覧で `role: "material"` が付いたテキストファイル（素材フォルダの中の `.md`・`.txt`） |
| 項目 | 素材リストの1行。`"[[汐見]]"` のように、ちょうど1つの `[[ ]]` だけなら「リンクの項目」、それ以外（`汐見メモ` など）は「ただの文字の項目」 |
| 行き先 | 項目の名前が指すファイル。索引に聞き、0／1／2以上のどれか（3-1・3-2 と同じ） |
| 最短の名前 | `shortestName`。ふつうはファイル名（拡張子なし）、同じ名前のノートが2つあれば `人物/汐見` のようにフォルダを足す（3.5b） |

### 1. データの形

- ファイルに足すのは `materials` の1キーだけ。書くときの形は `formatProperty` のとおり:

```yaml
materials:
  - "[[汐見]]"
  - "[[人物/灯]]"
```

- 読むときは、手で書かれた `materials: ["[[汐見]]"]` も、1つだけの `materials: "[[汐見]]"` も受け付ける。書き戻すときは上の形になる（その行だけ。ほかのプロパティと本文は1バイトも変えない）。
- 画面の中だけで持つもの: 項目の一覧（フロントマターの文字列が変わったときだけ読み直す）、各項目の行き先の状態（索引の `version` が変わったときだけ聞き直す。3-2 の `linkLookup` を使う）。

### 2. 利用者の操作と内部の処理（案）

| 操作 | 画面 | 内部 |
|---|---|---|
| 原稿を本文に出す | 「この場面」の概要・進捗の下に「素材 2」と項目が並ぶ。行き先のない項目は薄い | フロントマターの `materials` を読み、各項目の名前を `linkLookup.destination` に聞く |
| 項目を押す | そのノートをタブで開く（「この場面」はそのノートを出す） | 3-2 の `linkOpenActions.activate`。行き先が2つ以上なら 3-2 と同じ一覧で選んでもらい、「リンクを直して開く」ならその項目を書き換える |
| 「＋」を押す | 欄の中に絞り込みの入力と、まだ入っていないノートの一覧が開く。打つと絞り込まれ、↑↓と Enter、またはクリックで足す。Esc で閉じる | 一覧は `linkLookup.names(query)`（3-2 と同じ `filterNames`）。足すのは `[[最短の名前]]` |
| バインダーのノートを素材の欄へドラッグ | ドラッグ中、欄の枠が強調される。落とすと足される（複数選んでいれば全部） | バインダーのドラッグが `elementFromPoint` で欄の目印を見つけ、欄へ「落ちた」ことを知らせる。原稿・フォルダ・画像・PDF は受けない |
| 項目の「×」を押す | その項目が消える | `materials` からその項目だけを除いて書き戻す |
| 何かを書き込んだ | — | 新しい `materials` の行を作り `updateFrontMatter`。0.7秒後の自動保存でファイルへ。保存が終わると 3-1 の索引がその原稿を読み直す |
| ノートを改名・移動（3-1） | 素材の欄の名前も新しい名前になる | 3-1 の書き換えが `materials` の中の `[[旧名]]` を書き換える（今のまま） |
| ノートを削除 | その項目が薄くなる（押せない） | 書き換えない（3-1 の決定）。行き先がなくなるだけ |

### 3. 保存

- 素材リストは原稿のフロントマターにだけ持つ。書き込みは表示中のタブの文字列を `updateFrontMatter` で書き換えるだけで、ファイルへはタブの自動保存（`journal_save`、1-3a の外部変更の確認つき）が書く。新しい保存の経路・Rust の命令・`project.json` の欄は足さない。
- 打鍵では何も書かない。書くのは「＋」で選んだ・落とした・「×」を押した・「リンクを直して開く」を選んだときだけ。

| 機能 | 関係 |

## 工程5: 案

### 5-1. 方針

- 読む規則と行き先は `src/links/` に任せ、3-3 は「`materials` の項目を読む・書く」と「画面」だけを持つ。
- 書くのは `updateFrontMatter` だけ。
- 素材の欄は「この場面」の中に置く。新しいペインは作らない（モックの 5 と同じ並び: 概要・進捗・素材）。
- 浮かせ物は作らない。「＋」の一覧は欄の中に開く（右のペインは狭く、3-2 で浮かせ物が窓の外に出た）。

### 5-2. `src/links/materialList.ts`（新規、約90行）

- `readMaterials(metadata)`: `{ state: "none" | "list" | "readonly" | "error", items: Array<{ text, link: { target } | null }> }`。`readProperties` で `materials` の行を読み、list ならその項目、1つだけの文字なら1項目として扱う。各項目は `findLinksInLine(text, true)` でちょうど1つの `[[名前]]` だけのときリンク。読むだけ（入れ子・コメント）のときは、その行の文字から `findLinksInLine` でリンクを拾って出す（開けるが書けない）。
- `addMaterials(metadata, names)`: まだ入っていない名前だけを末尾に足す（同じ行き先かどうかは呼ぶ側が索引で決める）。キーがなければ `addProperty`、あれば `setPropertyValue(..., "list", ...)`。
- `removeMaterial(metadata, at)`、`renameMaterial(metadata, at, nextTarget)`（`|表示名` `#見出し` は残す）。
- どれも `materials` の行だけを書き換える。ほかの行・本文は1バイトも変えない。

### 5-3. 画面（`ScenePane.tsx`）

- 欄の見出し「素材」と項目の数、右端に「＋」。
- 項目: ノートの印＋名前（項目に書かれた名前のまま）＋「×」（マウスを載せたときとフォーカスがあるときに出す）。行き先のない項目は薄く、押せない。ただの文字の項目は押せないが「×」で外せる。
- 「＋」: 欄の中に入力と一覧。まだ入っていないノートだけ。↑↓・Enter・Esc、日本語入力の確定中の Enter は無視（概要の欄と同じ）。候補がないときは「＋」を押せない。
- ドラッグの受け口: 欄に目印の属性を付け、バインダーが落としたときに出す DOM のイベントを受けて足す。
- 説明の文は足さない。ボタンの名前（`aria-label`）は「素材を追加」「「汐見」を素材から外す」。

### 5-4. 打鍵ごとの処理
