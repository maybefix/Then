# Then v0.6.0 テンプレートによるファイル作成 — 改訂実装提案

作成日: 2026-08-27  
対象: Then v0.6.0

## 1. 結論

テンプレートは、登録済みのテキストを新規ファイルの初期本文としてそのままコピーする機能に限定する。

- 変数展開は行わない
- JSONメタデータは作らない
- テンプレート1件を通常の `.txt` または `.md` 1ファイルとして保存する
- `Ctrl+N` の現行ダイアログへ、ファイル名の下にテンプレート選択を追加する
- テンプレート選択の既定値は毎回「なし」
- 「なし」の場合は現行の新規ファイル作成挙動を維持する

テンプレートはスニペットと似た「定型テキスト」だが、スニペットが本文の途中へ挿入されるのに対し、テンプレートはファイル全体の初期状態として使う。

## 2. 新規ファイル作成UI

### 2.1 `Ctrl+N` の動作

`Ctrl+N`、ファイルメニューの「新規ファイル」、ファイルツリーの新規ファイルボタンは、すべて同じダイアログを開く。

```text
┌──────────────────────────────────┐
│ 新規ファイルを作成               │
├──────────────────────────────────┤
│ テキストファイル名               │
│ [ 新規ノート.txt              ]  │
│                                  │
│ テンプレート                     │
│ [ なし                        ▾]  │
│                                  │
│                    [キャンセル] [作成] │
└──────────────────────────────────┘
```

テンプレート欄はファイル名の直下に置く。詳細設定や変数入力画面へ遷移させず、このダイアログだけで作成を完了できるようにする。

### 2.2 テンプレート選択肢

選択肢は次の順に表示する。

```text
なし
────────────
このプロジェクト
  登場人物メモ
  章の下書き
共通
  日誌
  レビューメモ
────────────
テンプレートを管理…
```

- 「なし」を常に先頭へ置く
- 同名テンプレートがある場合は「プロジェクト」「共通」のグループ名で区別する
- 前回選択したテンプレートは記憶せず、ダイアログを開くたび「なし」に戻す
- テンプレート本文のプレビューはv0.6.0では必須にしない
- 選択肢が0件でも「なし」と「テンプレートを管理…」は表示する

### 2.3 「なし」の意味

「なし」はテンプレートファイルをコピーしないという意味にする。

現行の `create_text_file` は `# {ファイル名から拡張子を除いた文字列}` を初期本文として作成している。v0.6.0では互換性を優先し、「なし」を選んだ場合もこの挙動を維持する。

将来、完全な空ファイルが必要になった場合は「空のファイル」を内蔵テンプレートとして追加できるが、v0.6.0では扱わない。

### 2.4 テンプレートを選んだ場合

ファイル名と保存先は通常の新規作成と同じ規則を使い、本文だけを選択テンプレートの内容に置き換える。

例:

```text
ファイル名: 山田太郎.txt
テンプレート: 登場人物メモ
```

生成結果:

```text
# 登場人物

## 基本情報

- 名前:
- 年齢:
- 役割:

## 目的


## 葛藤

```

テンプレート本文はそのままコピーし、ファイル名、日付などの自動置換は行わない。

## 3. テンプレート登録方法

### 3.1 推奨する主操作

ファイルメニューへ次を追加する。

```text
新規ファイル
ファイルを開く
保存
別名で保存
────────────
このファイルをテンプレートとして登録…
テンプレートを管理…
────────────
エクスポート…
```

主操作は「このファイルをテンプレートとして登録…」とする。

ユーザーは通常のThen文書としてテンプレートにしたい内容を書き、完成した時点で登録する。テンプレート専用エディタや特殊な記法を新設しなくてよいため、現在の編集体験をそのまま利用できる。

### 3.2 登録ダイアログ

```text
┌──────────────────────────────────┐
│ テンプレートとして登録           │
├──────────────────────────────────┤
│ テンプレート名                   │
│ [ 登場人物メモ                ]  │
│                                  │
│ 保存先                           │
│ (●) このプロジェクト             │
│ ( ) すべてのプロジェクトで使う   │
│                                  │
│ 現在の本文をコピーして登録します │
│ 元のファイルとは連動しません     │
│                                  │
│                    [キャンセル] [登録] │
└──────────────────────────────────┘
```

テンプレート名の初期値は、現在のファイル名から拡張子を除いた値にする。

登録対象は、ディスク上の最終保存内容ではなく、エディタに現在表示されている本文とする。未保存の変更があっても、その時点の内容をテンプレートとして登録できる。

登録後のテンプレートはスナップショットであり、元ファイルとの関連は保持しない。元ファイルを編集してもテンプレートは変化せず、テンプレートを編集しても元ファイルは変化しない。

### 3.3 保存先の推奨

登録時に次の2つから選べるようにする。

- **このプロジェクト**: 作品固有の人物票、章構成、プロット用。既定値。
- **すべてのプロジェクトで使う**: 汎用的な日誌、レビュー、メモ用。

プロジェクトを開いていない場合は「このプロジェクト」を無効にし、共通テンプレートだけ登録できるようにする。

v0.6.0の範囲をさらに縮小する場合は、まず「このプロジェクト」だけを実装してもよい。ただしUIとコマンドの型には保存範囲を持たせ、後から共通テンプレートを追加できる形を推奨する。

### 3.4 同名テンプレート

同じ保存先に同名テンプレートが存在する場合は、自動的に `-2` を付けず、次の確認を出す。

```text
「登場人物メモ」はすでに登録されています。
現在の本文で置き換えますか？

[キャンセル] [置き換える]
```

テンプレート更新は、元になる文書を編集して同じ名前で再登録する操作とする。この方式なら、v0.6.0でテンプレート専用エディタを作らずに内容を更新できる。

### 3.5 補助的な登録方法

次は便利だが、v0.6.0の必須範囲には含めない。

- ファイルツリーのファイル右クリックから「テンプレートとして登録…」
- 選択範囲だけをテンプレートとして登録
- Idea／スニペットからファイルテンプレートへ変換
- テンプレート管理画面で空のテンプレートを新規作成

最初は「現在開いているファイル全体を登録」に限定する方が、登録対象が明確で誤操作も少ない。

## 4. テンプレート管理

### 4.1 v0.6.0で必要な管理操作

新規ファイルダイアログの選択肢末尾、またはファイルメニューの「テンプレートを管理…」から小さな管理画面を開く。

必要な操作は次の3つに絞る。

- 名前を変更
- 削除
- 現在のファイル内容で置き換える

```text
┌────────────────────────────────────────┐
│ テンプレートを管理                     │
├────────────────────────────────────────┤
│ このプロジェクト                       │
│ 登場人物メモ             [名前変更] [削除] │
│ 章の下書き               [名前変更] [削除] │
│                                        │
│ 共通                                   │
│ 日誌                     [名前変更] [削除] │
└────────────────────────────────────────┘
```

テンプレート内容の専用編集画面はv0.6.0では作らない。内容を更新したい場合は、通常の文書として内容を編集し、「このファイルをテンプレートとして登録…」から同名テンプレートを置き換える。

### 4.2 削除

削除前に確認を表示する。プロジェクトテンプレートはThenのTrashへ移動し、共通テンプレートはOSのごみ箱へ移動するのが望ましい。

テンプレートを削除しても、すでにそのテンプレートから作成されたファイルには影響しない。

## 5. 保存形式

### 5.1 JSONを使わない構成

```text
<workspace>/.then/templates/
  登場人物メモ.txt
  章の下書き.txt

<Then app data>/templates/
  日誌.txt
  レビューメモ.md
```

テンプレート名はファイル名から拡張子を除いた値とする。本文はファイル内容そのものとする。

- JSON sidecarは作らない
- YAML front matterも必須にしない
- ID、説明、カテゴリ、変数定義を持たせない
- 並び順はテンプレート名の自然順でよい
- `.txt` と `.md` を読み込めるようにする

`.then` は現行のプロジェクト一覧から除外されているため、プロジェクトテンプレートが通常のファイルツリーへ混ざることもない。

### 5.2 テンプレートの拡張子

テンプレート自身の拡張子は保存形式を示すだけで、生成ファイル名を強制しない。

たとえば `登場人物メモ.txt` から `山田太郎.md` を作成することもできる。生成ファイルの拡張子は、新規ファイルダイアログへ入力されたファイル名を優先する。

## 6. フロントエンド設計

### 6.1 専用ダイアログ型

現行の `requestInput` はテキスト入力1件だけを扱うため、テンプレート選択を無理に追加せず、新規ファイル専用のダイアログ型を追加する。

```ts
type TextTemplateOption = {
  name: string;
  scope: "workspace" | "profile";
  extension: "txt" | "md";
};

type CreateFileDialogValue = {
  fileName: string;
  template: TextTemplateOption | null;
};

type AppDialog =
  | ExistingAppDialog
  | {
      type: "createFile";
      title: string;
      fileName: string;
      template: TextTemplateOption | null;
      templates: TextTemplateOption[];
      confirmLabel: string;
      error: string;
      resolve: (value: CreateFileDialogValue | null) => void;
    };
```

`template: null` が「なし」を表す。ダイアログを開くたび必ず `null` で初期化する。

`requestMultiInput` の文字列フィールドへテンプレート名を入れる案は、存在しない名前やタイプミスを許してしまうため採用しない。`select` を持つ専用ダイアログの方が単純である。

### 6.2 作成処理

`handleCreateProjectFile` は次の順にする。

1. テンプレート一覧を読み込む
2. `createFile` ダイアログを開く
3. ファイル名とテンプレート選択を受け取る
4. バックエンドの作成コマンドを呼ぶ
5. プロジェクトツリーを再読込する
6. 作成ファイルを開いてエディタへフォーカスする

テンプレート本文をフロントエンドへ先に読み込んで `save_text_file` する必要はない。登録と作成のパス検証はバックエンドへ集約する。

## 7. Tauriコマンド案

### 7.1 テンプレート一覧

```rust
list_text_templates(root_path: Option<String>)
  -> Result<Vec<TextTemplateSummary>, String>
```

指定されたプロジェクトの `.then/templates` と共通テンプレートフォルダを走査し、ファイル名から一覧を作る。JSONの解析処理はない。

### 7.2 ファイル作成

既存コマンドへ任意のテンプレート指定を追加する。

```rust
create_text_file(
  folder_path: String,
  name: String,
  template_scope: Option<String>,
  template_name: Option<String>,
) -> Result<TextDocument, String>
```

- テンプレート指定なし: 現行どおり `# {title}\n` を書く
- テンプレート指定あり: 解決したテンプレート本文をそのまま書く

フロントエンドから任意のテンプレートパスを渡さない。`scope + name` を受け取り、バックエンドが許可されたテンプレートフォルダ内で解決する。

### 7.3 登録・管理

```rust
register_text_template(
  root_path: Option<String>,
  scope: String,
  name: String,
  extension: String,
  content: String,
  overwrite: bool,
) -> Result<TextTemplateSummary, String>

rename_text_template(...) -> Result<TextTemplateSummary, String>
delete_text_template(...) -> Result<(), String>
```

登録本文は現在のエディタ値を渡す。JSONは生成しない。

## 8. 安全性と競合処理

- テンプレート名からパス区切り、`..`、Windows予約文字を拒否する
- テンプレート保存先をcanonicalizeし、許可されたテンプレートフォルダ配下であることを確認する
- テンプレート読込サイズは1 MiB程度を上限とする
- UTF-8テキストだけを対象とする
- シンボリックリンク／ジャンクション経由で保存範囲外へ出ないようにする
- 同名登録は明示確認なしで上書きしない
- 1件のテンプレート読込に失敗しても、「なし」と他のテンプレートは利用できる
- 生成先の同名ファイル回避は現行の `name-2.txt` 規則を維持する

テンプレートにはコード実行機能がないため、変数エンジンやスクリプトの安全対策は不要である。

## 9. 実装順序

### v0.6.0必須

1. プレーンテキストのテンプレート保存先と一覧取得
2. `createFile` ダイアログ型とテンプレート選択UI
3. テンプレート指定付き `create_text_file`
4. ファイルメニューの「このファイルをテンプレートとして登録…」
5. 同名登録の置き換え確認
6. テンプレート管理画面の名前変更・削除
7. パス、文字コード、重複名のテスト

### v0.6.x以降の候補

- ファイルツリーからの登録
- 選択範囲だけの登録
- Idea／スニペットからの登録
- テンプレート本文の専用編集画面
- お気に入り、手動並び替え、検索
- テンプレートのエクスポート／インポート

変数展開、JSONメタデータ、条件分岐、複数ファイル生成は現時点では対象外とする。

## 10. テスト観点

### 新規作成

- `Ctrl+N` を開くたびテンプレートが「なし」になる
- 「なし」で現行の見出し付きファイルが作成される
- 選択したテンプレート本文が一字も変換されずコピーされる
- 出力ファイル名と拡張子はユーザー入力を優先する
- 横断検索やファイルツリーへテンプレート自体が混ざらない

### 登録

- 保存済み文書と未保存文書の現在内容を登録できる
- 登録後に元ファイルを変更してもテンプレートが変わらない
- 同名登録時に置き換え確認が出る
- プロジェクトテンプレートと共通テンプレートを区別できる
- プロジェクトを閉じた状態ではプロジェクト登録を選べない

### 管理

- 名前変更後に新規作成ダイアログへ即時反映される
- 削除後も既に生成したファイルは変化しない
- 壊れたテンプレートが1件あっても通常の新規作成を継続できる

## 11. 受け入れ基準

- 現行の新規ファイルダイアログへテンプレート選択が自然に収まる
- テンプレートを使わないユーザーの操作数が増えない
- テンプレートを選んでも追加の入力画面が開かない
- 現在の文書を3操作以内でテンプレート登録できる
- テンプレートの正体が通常のテキストファイルだけで、手動でも復旧できる
- JSONや特殊なテンプレート記法を理解しなくても使える

## 12. 推奨する最終仕様

v0.6.0では次を採用する。

1. `Ctrl+N` は「ファイル名＋テンプレート」のダイアログを開く
2. テンプレートの既定値は毎回「なし」
3. 「なし」は現行の `# title` 作成挙動を維持する
4. テンプレートを選ぶと、その本文を無加工でコピーする
5. 登録は「現在のファイルをテンプレートとして登録…」から行う
6. 登録内容は現在のエディタ本文全体
7. 同名登録は確認後に置き換える
8. テンプレートはプレーンな `.txt` / `.md` だけで保存する
9. JSON、変数、カテゴリ、説明、条件分岐は持たせない

この構成なら、ユーザーが想定している「スニペット的な定型文を入れた状態でファイルを作る」体験を、現行の新規ファイル操作へ小さく追加できる。
