## 工程2: 仕組みの説明

### 言葉

- JSX: 画面に並べるボタンなどを記述した部分。
- props: 親のAppから画面部品へ渡す値と操作。
- ref: 実際の画面要素やエディタを、あとから参照するための入れ物。
- 選択の控え: 右クリックした時点の範囲（開始・終了・本文）とマウス座標。

### 1. データの形

Appが `EditorContextMenuState | null` を持つ。nullなら閉じている。開いているときは `from`・`to`・`text`・`x`・`y` を持つ。移した部品はこれを受け取り、独自のstateやeffectを作らない。

### 2. 利用者の操作と内部の処理

| 操作 | 現在の処理。分離後も同じ |
|---|---|
| 本文を右クリック | エディタの選択を読み、選択が空なら右クリック位置から本文の位置を求める。ほかのメニューを閉じ、控えと座標をAppへ記録する |
| コピー | 控えの文字列をクリップボードへ書き、通知して閉じる |
| 切り取り | クリップボードへの書き込みに成功してから控えの範囲を削除し、通知して閉じる |
| 貼り付け | クリップボードを読み、控えの範囲を置き換え、本文へフォーカスを戻して閉じる |
| AIに渡す | 控えの文字列をAI欄へ入れてからメニューを閉じる。AIへの送信は行わない |
| プラグイン項目 | 対象のpluginId・commandIdで実行を依頼してから閉じる |
| ルビ | 控えを渡してルビ入力画面を開く |
| 縦中横・圏点 | 控えに対して既存の付け外し処理を呼ぶ。処理が成功したときだけこの描画側から閉じる |
| 記法をクリア | 控えを渡して既存の解除処理を呼ぶ |
| 文章方向 | 控えを渡して既存の選択画面を開く |
| 原稿を整える | 控えから対象行を決め、既存の整形画面を開く |
| 外側クリック・Escape | Appに残すイベント処理がメニューを閉じる。内部クリックはrefで見分ける |

### 3. 保存

メニューの開閉や座標は保存しない。本文を変更する操作は既存のエディタを呼ぶ。Appの変更検知・保存キュー・700msの遅延保存（3469〜3489行）をそのまま通す。保存条件・本文ファイル・保存ジャーナル・作品切り替えは移さない。

### 4. ほかの機能との関係

記法とクリップボードは既存の操作関数、AIは `handTextToAi`、プラグインは `pluginRuntimeHostRef.current?.executeCommand` を呼ぶ。位置計算は既存の `getScaledFixedMenuPosition` を呼ぶ。CSSの親子関係・class・メニューのDOM位置は変えない。部品の追加によって余分なDOM要素を挟まない。

### 5. 今の挙動の癖（今回変えない）

以下はコードから確認した条件であり、実機での確認は工程9で行う。

1. 選択なしではコピー・切り取り・AIは押せないが、貼り付け・記法のクリア・文章方向・整形は選べる。
2. 複数行の選択ではルビ・縦中横・圏点が押せない。プラグイン項目は空でない選択なら表示される。
3. プラグイン項目は選択がないと非表示だが、位置計算の高さには登録件数が加算される。今回はその計算も維持する。
4. 縦中横・圏点の処理がfalseを返すと、描画側では閉じない。
5. 工程9で、画面下側ではメニューの末尾が画面外へ出る場合があることを確認した。分離前からある固定の高さ計算を維持した結果であり、今回直さず `docs/KNOWN_ISSUES.md` に記録した。

## 工程5: 案

### 5-1. 方針

元の145行を `EditorContextMenu` へそのまま移し、状態や操作をpropsとして受け取る。幅・高さも描画と一緒に移す。新しいフック、React.memo、portal、遅延読み込み、共通化は追加しない。

### 5-2. 移すもの・残すもの

- 移す: メニュー本体、幅・高さ、描画専用の位置計算と選択判定のimport。型は重複定義を避けて共用する。
- 残す: 外側の表示条件、メニューのstateとref、開く処理・閉じる処理、共通のイベント登録、全操作の本体、保存、作品切り替え、ルビ・整形などのダイアログ。
- propsは元の変数名のまま渡す。プラグインホストのrefもそのまま渡す。

### 決めてほしいこと

案A（勧め）: 描画部分だけを分離する。約145行を整理でき、選択の取得や本文編集・保存を動かさずに済む。
