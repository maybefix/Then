## 工程2: 仕組みの説明

### 1. 資料ボードの読み込みと保存（癖1）

- 資料ボードの中身（資料カード、最近の資料、Idea のスレッドの並び順）は、作品ごとに `.then/reference-layouts/default.json` に入る。このファイルを書くのは、メインの画面の保存の useEffect（App.tsx 4066〜4091行）だけ。値が変わってから0.7秒後に保存する。Rust・Canvas のウィンドウ・ほかの処理は書かない（作品の間で資料を移すときに、移し先の作品のファイルを書く所がもう1つあるが、開いている作品のファイルではない）。
- 読み込みは、別の useEffect（4024〜4064行）。依存は `[isHydrated, projectFolder]`。読み込みを始めるときに `referenceLayoutLoadedRootRef` を空にして保存を止め、ディスクの内容と資料の候補（作品の中のファイルの一覧）を読み、終わったら保存を許す。
- `projectFolder` は作品のフォルダの木で、作品を開いたときのほか、名前の変更・移動・並べ替え・新規・削除のたびに新しいものに替わる。そのたびに資料ボードがディスクから読み直される。

### 2. 保存ジャーナル（癖2）

- 書きかけを守る記録。タブの名前（`file:<パス>`）ごとに、Rust が `%LOCALAPPDATA%\<識別子>\recovery\` にフォルダを作る。本文が変わるたびに記録し、保存し終えるとその世代まで済んだことにする。
- ふつうに閉じると、Rust がすべての記録を閉じ、保存し終えた記録のフォルダを消す（`close_all`）。強制終了やクラッシュのあとは、残った記録を次の起動で「保存されていない編集が残っています」として出す。
- タブを閉じたときは、`forgetDocumentJournal(tab.id)` が記録を捨てる。
- `src/editor/saveJournal.ts` の注記には「名前を変えたり移したりしたファイルはタブを保ち、記録はタブの名前で追いかける」とある。ところが、名前の変更と移動はタブの名前を新しいパスに替える。

### 3. パスを覚えている所（癖3と構造）

| 置き場所 | 名前の変更・移動（3つの操作） | 削除 |
|---|---|---|
| タブ | 付け替える | 閉じる |
| 最後に開いたファイル、進み具合、カーソルの位置 | 付け替える | 取り除く |
| プラグインのアンカー | 付け替える | 取り除く |
| プロットの本文のリンク `@[[…]]` | 付け替える | **何もしない** |
| 資料カード、最近の資料、資料の候補 | 付け替える | **何もしない** |
| 閉じたフォルダ | 付け替える（フォルダのとき） | **何もしない**（消したフォルダの記録が残る） |
| 選んでいるフォルダ、パンくずのフォルダ | 操作ごとに決める | 親へ移す |
| 保存ジャーナル | **何もしない**（古い名前の記録が残る） | **何もしない**（消したファイルの記録が残る） |

名前の変更・1件の移動・複数の移動は、上の付け替えを、それぞれ全部書いている（`src/projectEntryActions.ts`。約120行ずつ）。削除は自分の分だけを書いている。

## 工程3: 原因

1. **癖1**: 資料ボードの読み込みが、作品が変わったときではなく、作品のフォルダの木が替わるたびに走る。名前の変更・移動が付け替えたレイアウトは、0.7秒後の保存を待っている。そのあいだに木が替わると、読み込みが保存を止め、ディスクの古い内容で上書きする。同じことは、資料ボードを動かしてから0.7秒以内に、並べ替え・新規・削除・作品の中のフォルダを開く、をしたときにも起こる（見込み）。
2. **癖2**: 名前の変更・移動がタブの名前を替えるときに、古い名前の記録を閉じない。削除がタブを閉じるときにも、記録を捨てない（タブを閉じる操作は捨てる）。
3. **癖3と構造**: パスを覚えている置き場所の一覧がなく、操作ごとに書いている。削除は一覧の一部しか見ていない。

## 工程5: 案

### 5-1. 癖1の直し方

- **(a) 資料ボードは、作品が変わったときだけ読み込む。** 読み込みの useEffect の依存を、木そのものから作品のパス（`projectFolder?.path`）に替える。資料の候補の読み直しは、木が替わるたびに走る別の useEffect に分ける。ディスクのファイルを書くのはこの画面だけなので、同じ作品のあいだは画面の値がいちばん新しい。
- **(b) 4つの操作の中で、付け替えたレイアウトをすぐ保存してから木を替える。** 読み直しは残る。並べ替えなど、ほかの木の更新で起こる上書きは直らない。
- (a) で進める。原因（読み直す必要のない時に読み直している）を直すもので、名前の変更以外の上書きも一緒に止まる。気をつける点は、同じ作品を開き直したとき（作品の中のフォルダを開くなど）に、ディスクから読み直さなくなること。ほかの機能（プロット・Idea・進み具合）は開き直しで読み直すが、それらは Rust やほかのウィンドウも書く。資料ボードは、この画面しか書かない。

### 5-2. 癖2の直し方

名前の変更・1件の移動・複数の移動で、名前が替わったタブの古い名前の記録を閉じる。記録を閉じる新しい関数（`closeDocumentJournal`）は、Rust の `journal_forget` を `discard: false` で呼ぶ。保存し終えていればフォルダが消え、済んでいない分があれば復旧のために残る。この3つの操作は、Rust を呼ぶ前に未保存のタブを保存するので、ふつうは消える。削除は、確認で「未保存内容は破棄されます」と伝えているので、タブを閉じる操作と同じ `forgetDocumentJournal`（捨てる）を使う。

### 5-3. 構造（確認2のあとの依頼で決まった、付け替えをまとめること）

`src/projectEntryActions.ts` の中に、パスを覚えている置き場所の一覧を1か所に書く。

- `retargetPathOwners(changes)`: 古いパスと新しいパスの組の並びを受け取り、プラグインのアンカー、プロットのリンク、資料カード・最近の資料・資料の候補、進み具合・カーソルの位置・最後に開いたファイル、閉じたフォルダを付け替える。名前の変更・1件の移動・複数の移動が使う。
- `removePathOwners(path)`: 消したパスについて、同じ一覧から取り除く。削除が使う。
- タブ（本文の中身の扱いが操作ごとに違う）と、選んでいるフォルダ（操作ごとに決めている）は、今までどおり操作ごとに書く。

### 決めてほしいこと

**削除したファイルやフォルダを指していた、資料カード・最近の資料・プロットのリンクをどうするか**

- (a) 資料カード・最近の資料・資料の候補からは外す。プロットの本文のリンク `@[[…]]` は残す。
- (b) 今のまま全部残す。資料カードには「見つかりません」と出る。閉じたフォルダの記録と、保存ジャーナルの片付けだけを直す。
- (c) 資料カードなどを外し、プロットの本文のリンクも外す（`@[[第1章/c.txt]]` を消すか、ただの文字にする）。

勧めは (a)。資料カードと最近の資料は、ファイルを開くための入口で、消えたファイルを指すと開けないカードが残るだけになる。プロットの本文は利用者が書いた文章なので、アプリが書き換えない。ファイルを OS のごみ箱から戻せば、リンクはそのまま使える。気をつける点は、Then の中から削除を元に戻す画面がないこと。ごみ箱から戻しても、外した資料カード（位置と大きさ）は戻らない。

### 直す途中で見つけたこと

1回目の実機確認（`ccd8c2a` の build）では、名前の変更のあとも古い名前の記録のフォルダが残った。Rust への呼び出しを記録すると、`journal_forget`（`discard: false`）は名前の変更の後に呼ばれていた。ふつうに保存した記録に同じ呼び出しをすると消えたので、原因は Rust が閉じるときに元のファイルを確かめることだと分かった。自動テストは呼び出しの有無しか見ていなかったので、順番の確認を足して直した（工程7の `44449f4`・`702d8d1`）。

### 新しく見つけた癖（直していない）

サイドバーで閉じたフォルダの名前を変えると、フォルダが開いた状態に戻り、保存される開閉の記録（`appState.collapsedFolderPathsByWorkspace`）に古いパスが残った（確かめた）。工程2の3の表で、パンくずの閉じたフォルダ（`collapsedWorkspaceFolderPaths`、保存しない値）とこれを取り違え、置き場所の一覧から落としていた。同じ形で、ファイルのアウトラインの開閉、見出しの開閉、校正で「無視」にした指摘（相対パスごと）、閉じたタブの記録も、付け替えていない（見込み）。分離の前からあるもので、確認1の範囲の外なので、`docs/KNOWN_ISSUES.md` に記録した。

### 確かめられなかったこと

- パンくずの閉じたフォルダの記録（`collapsedWorkspaceFolderPaths`）は保存されない値で、画面で見分けにくいので、回帰テストだけで確かめた。
