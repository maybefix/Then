# Then Idea・資料統合 確定仕様／実装計画

確定日: 2026-09-23  
対象ブランチ: `codex/idea-reference-binder`

## 0. この文書の位置づけ

この文書を、Idea・資料統合の実装における正本とする。

以前のPoCで採用した次の発想は撤回する。

- Ideaとは別に「バインダー」を作る
- 「まとめて探す」というフラットな検索画面を作る
- Idea／資料／作品／共通／ファイル形式を同じ階層のタブやフィルターとして並べる
- 資料をIdeaスレッドとは独立した一覧で日常的に管理する

資料は独立した整理軸を持たず、**既存のIdeaスレッドの中へIdea断片と混在して置く**。ファイル本体の保存と、Idea上での所属は別の概念として扱う。

旧モックアップ `idea-reference-binder-mockup.html` はPoCの記録であり、今後の実装基準にはしない。

## 1. 確定した基本方針

### 1.1 日常操作の中心

日常的な流れは次のとおりとする。

1. Ideaへ思いつきを追加する。
2. 同じIdeaスレッドへ関連資料もクリップボタンから追加する。
3. スレッド内でIdea断片と資料を一緒に並べて眺める。
4. 必要なIdeaはIdeaポップアップ、資料は資料カードとして本文上へ開く。
5. 本文を書きながら参照・編集する。

### 1.2 保存範囲

- 資料はすべて作品専用とする。
- 共通資料・共通Canvasは廃止済みであり、UI、データモデル、フィルターへ再導入しない。
- 資料ファイル本体は作品フォルダ内の `.then/references/imports/` に保存する。
- 作品フォルダを別端末へ移したとき、資料、Idea上の参照、カード配置も一緒に移る。
- 資料追加時に保存範囲を選ばせない。

### 1.3 資料本体とスレッド参照

- 資料ファイルの実体は1つだけ持つ。
- Ideaスレッドには資料本体を複製せず、同じ `sourcePath` を指す参照を置く。
- 同じ資料を複数のIdeaスレッドから参照できる。
- 同じ資料を同一スレッドへ重複追加する操作は設けない。
- スレッド内で資料参照を移動・削除しても、必要な場合を除いて資料ファイル本体は移動しない。

```text
<project>/.then/references/imports/map.png  ← 実体は1つ

IdeaスレッドA
└─ 資料参照 → references/imports/map.png

IdeaスレッドB
└─ 資料参照 → references/imports/map.png
```

## 2. Idea画面の構成

### 2.1 追加欄

既存Idea画面の追加欄を、狭いサイドバーでも入力幅を確保できる2段構成にする。

```text
[Idea入力欄]
[・インボックス ▼] [クリップ] [＋追加]
```

クリップボタンを押すと、小さなメニューを表示する。

- ファイルを追加
- 新しいテキスト資料

「ファイルを追加」はWindowsのファイル選択画面を開く。複数ファイルの同時選択に対応し、選択したすべてのファイルを作品の資料フォルダへ取り込み、現在選択中のIdeaスレッドへ参照を追加する。

「新しいテキスト資料」は既存のテキスト資料作成処理を使い、作成後に現在選択中のIdeaスレッドへ参照を追加する。

ファイル追加・新規テキスト資料・別スレッドへの移動／追加で加わった資料参照は、対象スレッドの混在一覧の先頭へ置く。複数ファイルを同時追加した場合は、選択結果の順序を保ったまま先頭へまとめて追加する。

### 2.2 スレッド内の混在一覧

Ideaスレッド内は、Idea断片と資料参照を1本の順序付きリストとして表示する。

```text
Idea断片
画像資料
Idea断片
PDF資料
テキスト資料
```

- Idea断片と資料参照をまとめてドラッグ並べ替えできる。
- Idea断片のCanvasへのドラッグは維持する。
- 資料のCanvasへのドラッグも維持する。
- 本文エディタへのドラッグ挿入は行わない。
- 一覧本文のダブルクリックでポップアップを開く操作は設けない。
- ポップアップ／資料カードは専用アイコンから開く。

## 3. 一覧行の見せ方

Idea断片と資料の区別を最優先する。ただし、資料だけ背景色や外枠を変えることはしない。行の内部構造と種類アイコンで区別する。

### 3.1 Idea断片

- 従来に近い本文中心の表示とする。
- 一覧上でそのまま編集できる。
- Ideaであることが分かる既存アイコンを使う。
- 専用ポップアップアイコンを置く。

### 3.2 テキスト／Markdown資料

- 種類アイコンを表示する。
- 内容冒頭の短いプレビューを主に表示する。
- ファイル名も併記する。
- Idea断片と誤認しないレイアウトにする。

### 3.3 画像資料

- 小さな画像サムネイルを表示する。
- ファイル名を併記する。
- サムネイル生成に失敗した場合は画像アイコンへフォールバックする。

### 3.4 PDF資料

- PDFアイコンとファイル名だけを表示する。
- 一覧上ではページ数や先頭ページのサムネイルを表示しない。

### 3.5 表示しない情報

- 「作品」というラベル
- 「共通」というラベル
- `PDF`、`画像`などの文字バッジ
- 種類別フィルター

形式はアイコンとツールチップで判別できればよい。

## 4. 検索

- 「まとめて探す」は削除する。
- 既存Idea画面上部の検索欄で、Idea本文、資料ファイル名、テキスト／Markdown資料のプレビューを検索する。
- 検索中もスレッド構造を保つ。
- 各スレッド内では、検索に一致したIdea断片・資料だけを表示する。
- スレッド名は既に見出しとして表示されるため、各検索結果行へ重複表示しない。
- 全スレッド横断のフラットな検索結果画面は作らない。
- Idea／資料やファイル形式によるフィルターは作らない。

## 5. 行の「…」メニュー

資料行の操作は、Idea断片の「別スレッドへ移動」「削除」と同じ位置にある「…」メニューへ置く。

資料行のメニューには次を置く。

1. **別スレッドへ移動**
   - 対象スレッドへ同じ資料参照を追加する。
   - 現在のスレッドから参照を外す。
   - 資料ファイル本体は移動しない。

2. **別スレッドにも追加**
   - 対象スレッドへ同じ資料参照を追加する。
   - 現在のスレッドの参照は残す。
   - 同一スレッドへの重複追加はできない。

移動先／追加先のスレッド一覧の末尾には「新規スレッドに移動」「新規スレッドに追加」を置く。選択するとスレッド名入力を表示し、作成と移動／追加を一続きで完了する。Idea断片の移動先一覧にも「新規スレッドに移動」を置く。

3. **このスレッドから削除**
   - 原則として現在のスレッドの参照だけを外す。
   - 他スレッドの参照、資料ファイル本体、開いている資料カードは残す。
   - ただし現在の参照が最後の1件である場合は、孤立ファイルを作らず、後述の確認を行う。

4. **資料ファイルを削除**
   - 資料ファイル本体を削除する。
   - 全Ideaスレッドの同一資料参照を削除する。
   - 開いている同一資料カードをすべて閉じる。
   - 常に確認メッセージを出す。

移動・追加・削除には既存Idea行と同系統のアイコンを使ってよいが、Idea断片用処理と資料参照用処理は分離する。

## 6. 削除規則

### 6.1 他スレッドにも参照がある場合

「このスレッドから削除」は、現在の参照だけを削除する。

- ファイル本体は残す。
- 他スレッドの参照は残す。
- 本文上で開いている資料カードは残す。

### 6.2 現在の参照が最後の1件の場合

削除前に参照数を確認する。現在の参照が最後の1件なら、次の確認を出す。

> この資料はほかのスレッドから参照されていません。  
> このプロジェクトからの削除になりますが、よろしいですか？

- 「削除する」: 資料ファイル、最後の参照、開いている同一資料カードを削除する。
- 「キャンセル」: 何も変更しない。

参照を持たない「未整理資料」は作らない。左サイドバーにも孤立資料の保管場所は作らない。

### 6.3 「資料ファイルを削除」を直接実行した場合

参照しているスレッドが複数ある場合は、影響範囲を明示する。

確認文の例:

> この資料は3個のIdeaスレッドから参照されています。  
> 資料ファイルと、すべてのスレッドからの参照を削除します。よろしいですか？

ファイル削除と参照削除は一つの操作として扱い、片方だけが残らないようにする。失敗した場合は、可能な限り元の状態を維持し、エラーを表示する。

## 7. 本文上のIdeaポップアップと資料カード

### 7.1 Ideaポップアップ

Idea断片は専用ポップアップとして開く。

必要な操作:

- その場で本文編集
- 移動
- サイズ変更
- ピン留め
- 折りたたみ
- 閉じる

Ideaポップアップには「使用済み」切り替えを置かない。

一覧とポップアップは同じIdea断片を参照し、編集結果を即座に同期する。本文の複製をカード状態へ保存しない。

### 7.2 資料カード

資料は「軽い付箋」へ置き換えず、既存の資料カード機能を維持する。

- テキスト／Markdownはカード内編集を維持する。
- 画像はズームを維持する。
- PDFは既存のプレビュー、ページ操作、ズームを維持する。
- PDFは端末のDPIに合わせた高解像度キャンバスへ描画し、カード上の表示寸法だけで低解像度化しない。
- 移動、サイズ変更、ピン留め、折りたたみ、閉じるを維持する。

Ideaポップアップと資料カードは、同じカードレイヤー上に置いてよいが、見た目は完全に同一化しなくてよい。

### 7.3 同じ項目を再度開いた場合

初期実装では、同じIdea断片または同じ資料が既に開いている場合、そのカードを最前面へ移す。重複カードを複数枚開く機能は望ましいが、今回の完了条件には含めない。

ポップアップアイコンはIdeaと資料で同系統の見た目を使い、開く処理は分離する。

## 8. 左サイドバーの「開いているカード」

Idea画面上部を複雑にしないため、現在本文上に開いているカードの一覧は左サイドバーの専用領域へ置く。

- 既存の左サイドバー「資料」入口を置き換える。
- Ideaポップアップと資料カードを同じ一覧へ表示する。
- IdeaはIdeaアイコンと本文抜粋を表示する。
- 資料は種類アイコンまたは画像サムネイルとファイル名を表示する。
- クリックすると対応するカードを最前面へ移す。
- 閉じる、折りたたみ、ピン留め状態を確認・操作できる。
- 資料の追加、検索、ファイル管理はこの領域へ置かない。
- 開いているカードが0件なら空状態を表示する。

この領域は「未整理資料」や全資料ライブラリではない。開いているカードだけを扱う。

## 9. 既存の資料UIの扱い

Idea統合が成立した時点で、次を削除する。

- 右サイドバーの独立した「資料」画面
- 左サイドバーの従来の資料一覧入口
- Idea／まとめて探す／資料の3モード切り替え
- 作品／共通タブ
- 種類別フィルター
- 資料scopeのコピー／移転UI

低頻度の資料操作は、Idea内の資料行「…」メニューへ集約する。

## 10. データモデル

### 10.1 資料参照

資料ファイルとスレッド内の配置を分ける。

```ts
type IdeaReferenceLink = {
  id: string;              // スレッド内の参照ID
  sourceType: "reference";
  sourcePath: string;      // 作品ルートからの正規化相対パス
  createdAt: number;
};
```

- ファイル同一性は正規化した `sourcePath` で判定する。
- Windowsでは大文字・小文字や区切り文字の差を吸収する。
- 別スレッドの参照は別の参照IDを持つが、`sourcePath` は同じとする。

### 10.2 混在順序

永続化形式は、Idea断片と資料参照の混在順序を欠落なく保存できなければならない。

概念上は次の判別可能なunionとして扱う。

```ts
type IdeaThreadItem =
  | { sourceType: "idea"; fragment: IdeaFragment }
  | IdeaReferenceLink;
```

既存の `IdeaThread.fragments` を直接unionへ変更するか、資料参照と順序をプロジェクト側の別データとして保持するかは実装時に選べる。ただし次の条件を満たすこと。

- 旧 `fragments` だけを持つデータをそのまま読み込める。
- Idea断片と資料参照の相対順序を保存・復元できる。
- 同じ資料を複数スレッドから参照できる。
- 資料参照は必ずプロジェクトデータとして保存する。
- `snippetStorageMode: "profile"` の場合も、資料参照を `profileSnippets` へ保存しない。
- プロファイルIdeaの参照先スレッドが別端末で存在しない場合、資料参照を作品側のInboxへ安全に再接続し、消失させない。

### 10.3 カード状態

- Ideaポップアップは `threadId` と `fragmentId` を保持する。
- 資料カードは `sourcePath` と表示状態を保持する。
- 資料カードのスクロール、ズーム、PDFページ、編集状態は現行どおり保存する。
- 資料参照を別スレッドへ移動しても、資料カードは同じ `sourcePath` を参照し続ける。

## 11. 既存データの移行

### 11.1 既存Idea

- 既存の `IdeaThread.fragments` は、順序を保ったまますべてIdea項目として読み込む。
- 既存IdeaのID、本文、使用済み状態、Canvas由来情報を変えない。

### 11.2 既存の作品資料

既存の `.then/references/imports/` に資料があり、どのIdeaスレッドからも参照されていない場合は、初回移行時に作品のInboxへ参照を1件作る。

- 資料ファイル本体を移動・複製しない。
- 既存の資料カード配置は可能な限り維持する。
- 同じ `sourcePath` の参照を重複作成しない。
- 移行完了後は、参照を持たない資料ファイルを通常操作から新たに作らない。

### 11.3 旧PoCレイアウト

- `sourceType: "idea"` の既存カードはIdeaポップアップとして復元する。
- 作品資料カードは資料カードとして復元する。
- 廃止済みの共通資料カードは復元しない。
- 旧「まとめて探す」などのUI状態は移行対象にしない。

## 12. エラー処理と整合性

- 複数ファイル追加では、成功したファイルと失敗したファイルを区別して結果を表示する。
- 同名ファイルの扱いは既存資料取り込み規則を維持し、意図しない上書きをしない。
- 資料ファイルが外部要因で欠落した場合、参照行に「ファイルが見つかりません」を表示し、参照の削除操作を提供する。
- 資料ファイル削除後に参照だけが残らないようにする。
- 参照追加後に保存が失敗した場合、成功したように見せずエラーを表示する。
- Ideaポップアップや資料カードの操作で、本文エディタの選択、カーソル、タイプライタースクロール位置を変更しない。

## 13. 実装順序

1. プロジェクト資料参照と混在順序のデータモデルを追加する。
2. 旧Ideaと既存作品資料の移行処理・テストを追加する。
3. `pick_reference_file` を複数選択対応にするか、複数選択用commandを追加する。
4. Idea追加欄へクリップメニューを追加する。
5. Ideaスレッド一覧を混在項目へ対応させる。
6. 資料行のプレビュー、画像サムネイル、アイコンを実装する。
7. 混在ドラッグ並べ替えとCanvasドラッグを実装する。
8. 資料行の移動、追加、参照削除、ファイル削除を実装する。
9. 最後の参照チェックと確認メッセージを実装する。
10. Idea検索を資料込みへ拡張し、「まとめて探す」と種類フィルターを削除する。
11. Ideaポップアップから使用済み切り替えを除き、資料カード機能を回帰確認する。
12. 左サイドバーを「開いているカード」へ置き換える。
13. 独立した資料UIと不要になったCSS・command・状態を削除する。
14. 永続化、プロジェクト切り替え、再起動、別端末相当の移行テストを行う。

## 14. 完了条件

- Ideaスレッド内にIdea断片と資料が混在して表示される。
- 両者をドラッグで並べ替え、保存・復元できる。
- クリップから複数ファイルを選び、選択中スレッドへ追加できる。
- 同じ資料を複数スレッドへ追加できる。
- 資料参照の移動、複製、現在スレッドからの削除ができる。
- 最後の参照を削除するときだけ、プロジェクトからのファイル削除確認が出る。
- ファイル削除後に参照や開いているカードが残らない。
- Ideaと資料を同じ検索欄で検索でき、スレッド構造が維持される。
- 種類フィルター、「まとめて探す」、作品／共通UIが存在しない。
- Ideaポップアップと資料カードを同時に複数種類開ける。
- テキスト資料編集、画像ズーム、PDF表示が維持される。
- 左サイドバーから開いているカードを確認し、最前面へ移せる。
- 旧Idea、既存作品資料、既存カード配置を失わず移行できる。
- 本文のスクロール位置、選択、IMEをカード操作で壊さない。

## 15. 対象外

- 共通資料・共通Canvasの復活
- 作品／共通フィルター
- ファイル形式フィルター
- 全スレッド横断のフラット検索画面
- Marker／Anchorによる本文位置への固定
- 本文へのIdea・資料ドラッグ挿入
- 参照を持たない資料の管理画面
- 同じIdea・資料を任意に複数枚開くための専用操作
- モバイル／画面幅別のレスポンシブUI

この機能の評価基準は、機能数ではなく、**Ideaと資料を同じ文脈で整理し、執筆中に迷わず取り出せること**とする。
