# Then ライブラリ 仕様（叩き台）

作成日: 2026-10-02
状態: 第1・第2段階の方針確定（実装前）
モック: [library-mockup.html](library-mockup.html)

## 1. 目的

複数の作品を一つの場所で一覧・検索・分類できるようにする。そのために、作品（プロジェクト）の上位に **ライブラリ** を置く。

- **ライブラリ**: 複数作品を一覧、検索、分類する範囲。
- **プロジェクト**: 一作品の制作単位。本文、Idea、Plot、Canvas、資料、中間稿、チェックポイントを持つ。
- ライブラリ自身も、作品に属さない Idea、Plot、Canvas、資料、中間稿、チェックポイントを持てる（以下「ライブラリ直下の項目」）。

用語は UI・文書とも「ライブラリ」に統一する（「保管庫」「vault」は使わない）。

## 2. 段階

| 段階 | 内容 |
|---|---|
| 第1段階 | ライブラリの導入、左サイドバーの切り替え、既存プロジェクトの取り込み（コピー＋検証） |
| 第2段階 | 複数作品の横断機能（ライブラリホーム、横断検索、分類） |

本文順序の独立構造は今回の検討範囲に含めない。

## 3. 物理配置

ライブラリはフォルダであり、その直下にプロジェクトのフォルダを置く。

```text
<ライブラリ>/
├─ .then/
│  ├─ library.json        ← ライブラリの目印（これがあるフォルダがライブラリ）
│  ├─ project.json        ← ライブラリ直下の項目の状態（プロジェクトと同じ形式）
│  ├─ checkpoints/        ← ライブラリ直下ファイルだけのチェックポイント
│  ├─ boards/             ← ライブラリ直下の Canvas・中間稿
│  └─ references/         ← ライブラリ直下の資料
├─ 世界観メモ.md           ← ライブラリ直下のファイル
├─ 共有設定/               ← ライブラリ直下のフォルダ
├─ 作品A/
│  ├─ .then/project.json  ← これがあるフォルダがプロジェクト
│  └─ 01_本文/…
└─ 作品B/
   └─ .then/project.json
```

### 3.1 判定規則

- `.then/library.json` を持つフォルダを **ライブラリ** とする。
- ライブラリ **直下** のフォルダのうち `.then/project.json` を持つものを **プロジェクト** とする。
- プロジェクトの中のフォルダは、`.then/` を持っていてもプロジェクトとして扱わない（入れ子は不可）。
- プロジェクト以外のフォルダの中にあるプロジェクトも認識しない。グループ用のフォルダで作品をまとめることはしない。
- 短編集のように一つの作品の中に複数の作品を持つ場合は、一つのプロジェクトの中でフォルダに分ける。
- ライブラリ直下のフォルダの奥に `.then/project.json` を見つけたときは、警告を出す。中身をライブラリ直下のファイルとしては扱わない。警告には、そのフォルダをライブラリ直下へ移すよう案内を添える。

### 3.2 ライブラリ直下の扱い

ライブラリ直下は「配下のプロジェクトのフォルダを除外したプロジェクト」として扱う。既存のプロジェクト処理（並び順、進捗ラベル、Idea、Plot、Canvas、資料、中間稿、チェックポイント）をそのまま再利用する。

- 走査（ファイル一覧、文書インデックス、字数、検索）は、プロジェクトのフォルダを境界として中に入らない。
- チェックポイントの対象はライブラリ直下のファイルだけ。配下のプロジェクトは含めない。

### 3.3 library.json

```json
{
  "schemaVersion": 1,
  "id": "lib-…",
  "name": "わたしの作品集"
}
```

作品の一覧や分類情報はここに持たせない（§8.3）。

### 3.4 ライブラリは必須

プロジェクトは必ずライブラリの中で開く。ライブラリの外で作品を開く手段は残さない。

一方で、プロジェクトのフォルダは **自己完結** させる。作品フォルダをコピーして別のライブラリの直下に置けば、そのまま作品として使える。作品の受け渡しや別の端末への移動は、この性質で行う。

ライブラリの外にあるフォルダを開こうとした場合は、エディタでは開かずに取り込みへ誘導する。

- ライブラリをまだ一つも持っていない場合は、ライブラリの準備画面（§7.0）を出す。開こうとしたフォルダは、取り込む作品の候補に入れておく。
- ライブラリを持っている場合は、次の選択肢を出す。
  - 「<最近開いたライブラリ>」に取り込む（最初の選択肢）
  - 別のライブラリに取り込む…
  - 新しいライブラリを作って取り込む…（準備画面を開く）

既存のフォルダをそのままライブラリにする操作は提供しない。フォルダの中身が意図せずライブラリ直下のファイルになるのを防ぐため。

## 4. 現在のスコープ

アプリが「開いている」範囲は常に次のどちらか一つとする。

- **ライブラリ直下**
- **プロジェクト X**

複数プロジェクトの文書をタブで同時に開く状況は発生しない。サイドバーで別のプロジェクトを開いた時点で、スコープはそのプロジェクトに切り替わる。

スコープに連動して切り替わるもの:

- 文書タブ（スコープごとに保存・復元）
- 左サイドバーのファイル一覧
- パンくずの起点
- 右パネル（Idea、Plot、バインダー、校正、中間稿）、Canvas、資料、チェックポイント、エクスポート
- 「検索」の既定範囲

### 4.1 スコープ切り替えの手順

1. 現在のスコープの未保存の本文を保存する（今のワークスペース切り替えと同じ）。
2. 現在のスコープのタブ構成を記憶する。
3. 新しいスコープの状態（並び順、進捗、Idea、Plot、チェックポイントなど）を読み込む。
4. 新しいスコープで保存されているタブを復元する。
5. 保存されているタブがなければ **空の状態**（§6）にする。

タブ構成は今と同じく端末ローカルの `documentTabsByWorkspace` に、スコープのフォルダの絶対パスをキーとして保存する。ライブラリ直下のキーはライブラリのフォルダのパス、各プロジェクトのキーはプロジェクトのフォルダのパスになる。

## 5. 左サイドバー

### 5.1 ライブラリ直下を開いているとき

```text
ライブラリ: わたしの作品集
─────────────
▸ 共有設定/
  世界観メモ
─────────────
作品
  📖 作品A           12,345字
  📖 作品B            8,210字
```

- 上段: ライブラリ直下のフォルダとファイル（今のツリーと同じ見た目と操作）。
- 下段: プロジェクトの一覧。ライブラリ直下のファイルやフォルダとは見た目で区別する（本アイコンと字数、ドラッグによる並び替えなし）。
- プロジェクトの行をクリックすると、そのプロジェクトのスコープへ切り替わる（§4.1）。
- 下段の末尾に「＋ 新しいプロジェクト」「既存プロジェクトを取り込む」を置く。

### 5.2 プロジェクトを開いているとき

```text
← わたしの作品集
─────────────
作品A
▾ 01_本文/
    第一章   執
    第二章   未
```

- 最上部に「← <ライブラリ名>」の戻るボタンを置く。
- その下は今のプロジェクトのツリーそのもの。

### 5.3 戻る操作とパンくずの一致

パンくずの先頭にライブラリ名を加える。

```text
わたしの作品集 › 作品A › 01_本文 › 第一章
```

サイドバーの「← ライブラリ名」とパンくずの「ライブラリ名」は、**同じ関数**（例: `enterLibraryRoot()`）を呼ぶ。保存、タブの記憶と復元、空の状態への遷移など、挙動に差を作らない。パンくずの「作品A」も、サイドバーのプロジェクト行と同じ `enterProject(path)` を呼ぶ。

## 6. 空の状態

### 6.1 現状

今の Then には、タブがゼロの状態はない。

| 状況 | 今の挙動 |
|---|---|
| ワークスペースを開いたが保存タブがない | 最初のテキストファイルを自動で開く |
| ワークスペースにテキストファイルが一つもない | 空の無題タブ（スクラッチ）を作る |
| 最後のタブを閉じた | 空の無題タブ（スクラッチ）を作る |
| 「＋」で新しいタブ | 「新しいタブ」スタートページ（フォルダを開く／テキストファイルを開く） |

### 6.2 提案

**空の状態** を新しく定義する。タブ帯にはタブが一つもなく、エディタ領域にスコープ用のスタートページを出す。

- プロジェクトの空の状態: プロジェクト名、最近編集した文書（最大5件）、「新規ファイル」「Plot を開く」、左のツリーから開けるという案内。
- ライブラリ直下の空の状態: 第1段階ではライブラリ直下用のスタートページを出す。第2段階でライブラリホーム（§8.1）に置き換える。

次のどちらの場合も空の状態にする。

- 保存されているタブがない状態でスコープに入ったとき（最初のファイルは自動で開かない）
- 最後のタブを閉じたとき（空の無題タブは作らない）

## 7. 既存プロジェクトの取り込み

第1段階では、プロジェクトの保存形式は変えない。そのため既存プロジェクトの取り込みは「形式の変換」ではなく、「ライブラリ内へのコピー＋検証」になる。

### 7.0 ライブラリの準備画面

ライブラリをまだ一つも持っていない状態で起動したとき、またはライブラリの外のフォルダを開こうとしたときは、起動画面の前に準備画面を出す。

- ライブラリ名（既定「わたしの作品集」）と作成する場所（既定 `ドキュメント\Then`）を指定する。
- ライブラリは、作成する場所の中に **新しいフォルダとして** 作る。既にあるフォルダは使わない。
- 取り込む作品として、最近の履歴にある旧版のワークスペースをチェック済みで並べる。「ほかの作品フォルダを追加…」で追加できる。
- 実行すると、作品ごとに「コピーして検証中 → 完了／失敗」を表示する。終わったら「ライブラリを開く」でライブラリ直下を開く。
- 「あとで」で起動画面に戻れる。「作成済みのライブラリを開く…」で既存のライブラリを選べる。
- 取り込んだ作品の最近の履歴は、取り込み先のパスに置き換える。

### 7.1 手順

1. 取り込むプロジェクトのフォルダと、取り込み先のライブラリを選ぶ。
2. 取り込み先ライブラリの `.then/importing/<id>/` へ、プロジェクトのフォルダを丸ごとコピーする（`.then/` を含む）。`.then/` 配下なので、作業中のコピーはツリーに出ない。
3. 検証する（§7.2）。
4. 検証に通ったら、コピーに `project.json` がなければ作る。そのうえで `<ライブラリ>/<作品名>` へ改名する。同名があれば「作品名 (2)」とする。
5. 取り込み元が旧版の端末ローカルのデータ（`app-state.json` の進捗ラベルやチェックポイント）を持っている場合は、その旧データを **取り込み先のコピー** へ移す。取り込み元のパスを鍵に読み、パスを取り込み先に置き換えて書く。取り込み元には書き込まない。
6. 端末ローカルのタブ構成とカーソル位置を、取り込み元のパスから取り込み先のパスへ写す。
7. 取り込んだプロジェクトのスコープに切り替える。完了画面では、取り込み元がそのまま残っていることを伝え、「元のフォルダをエクスプローラーで開く」ボタンを出す。

### 7.2 検証項目

- ファイル数とフォルダ数が一致する。
- すべてのファイルについて、サイズと内容のハッシュが一致する。
- `.then/project.json` が読み込め、`revision` が一致する。
- チェックポイントの件数が一致し、すべて読み込める。
- 進捗ラベルのキーがすべて実在のファイルを指す（取り込み元で既に切れているものは警告だけにする）。
- Canvas のボード、中間稿、資料の取り込み済みファイルの件数が一致する。

### 7.3 失敗時

- 取り込み元には一切書き込まない。自動で削除もしない。
- 検証に失敗したら、自分で作った一時フォルダだけを削除する。そのうえで失敗した項目を表示する。
- 途中でアプリが終了したときは、次にそのライブラリを開いたとき、残った `.then/importing/` を見つけて削除するか確認する。

### 7.4 手作業での取り込み

形式が変わらないので、エクスプローラーでプロジェクトのフォルダをライブラリ直下へ移動するだけでも認識される。この場合、端末ローカルのタブ構成は引き継がれず、最初は空の状態で開く。

## 8. 横断機能（第2段階）

### 8.1 ライブラリホーム

ライブラリ直下の空の状態として、作品の一覧を出す。

- 表示: 作品名、状態、あらすじ、総字数、進捗の内訳（未着手、執筆中、推敲中、完了）、最終更新日。
- 並び替え: 更新日、作品名、字数。
- 絞り込み: 状態、作品名やあらすじの文字列。
- カード表示と表表示を切り替えられる。

### 8.2 横断検索

検索パネルの範囲に「ライブラリ全体」を追加する（現在の本文／プロジェクト／ライブラリ全体）。

- 結果は作品ごとにまとめて表示する。
- 別の作品の結果を開くと、その作品のスコープへ切り替えてから該当箇所へ移動する。
- ライブラリ全体の置換は提供しない。置換は今どおり「現在の本文」「プロジェクト」の範囲だけにする。

### 8.3 分類情報

分類情報は各プロジェクトの `.then/project.json` に持たせる。

```json
{
  "work": {
    "title": "作品A",
    "status": "writing",
    "summary": "…"
  }
}
```

- ライブラリは、各プロジェクトの `project.json` を読み集めて一覧を作る。
- 読み集めた結果のキャッシュは端末ローカルに置き、共有のファイルにはしない。可搬化計画の「単一の共有インデックスを競合点にしない」方針に従う。
- 総字数と進捗の内訳はキャッシュから出し、作品を開いたときに更新する。
- タグは今の Then に実装がないため、今回の分類情報には含めない。必要になった時点で `work` に項目を足す。

## 9. ライブラリとプロジェクトの間の項目

### 9.1 参照の向き

- プロジェクトの項目は、ライブラリ直下の項目を参照しない。
- ライブラリ直下の項目は、プロジェクトの項目を参照してよい。参照は `作品A/01_本文/第一章.md` のような、ライブラリからの相対パスで持つ。
- 作品フォルダがライブラリから外された場合、ライブラリ側の参照は「見つからない」と表示する。プロジェクト側は影響を受けない。

### 9.2 移動とコピー

次の項目に「プロジェクトへ移動／コピー」「ライブラリへ移動／コピー」を用意する。

- Idea（断片とスレッド）
- Plot カード
- Canvas のボード
- 資料
- 中間稿

ライブラリからプロジェクトへ移すとき、移す項目がライブラリ直下の別の項目を参照している場合:

- 参照先も一緒にコピーするか、参照を外すかを選ばせる。
- 黙ってリンク切れにはしない。

## 10. 起動画面

起動画面の「最近のワークスペース」を「最近のライブラリ・プロジェクト」にまとめる。プロジェクトの項目は、所属するライブラリ名を添えて表示する。旧版のワークスペースの項目には「取り込みが必要」と表示する（§3.4）。
