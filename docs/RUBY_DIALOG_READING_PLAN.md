## 工程1: 調査の結果

- ダイアログを開く処理: `openRubyNotationModal`（`src/editor/editorNotationActions.ts` 215行）。選択が1行の中なら、`{ type: "ruby", selection, reading: "", error: "" }` で開く。本文は読まない。
- ダイアログ（`src/App.tsx` 13292〜13350行）: 「対象」の欄に選択の文字列（読むだけ）、「ルビ」の欄に `reading`（`autoFocus`、空のときは「読みを入力」と薄く出る）。
- 付いたルビの見つけ方は、`applyRubyToSelection`（`src/editor/selectionEdits.ts` 349〜390行）の中にだけある。`[本文(rb,…)]`・`｜本文《…》`・`漢字《…》` の中身か全体を選んでいれば当たる。今は、見つけた後に新しい読みで書き換えるところまでが1つの関数になっていて、今の読みを取り出す入口がない。

## 工程2: 仕組みの説明

### 今の流れ

1. 右クリックしたときの選択の控えを、メニューが覚える。
2. 「ルビ...」を押すと、控えが1行の中かを確かめ、読みの欄が空のダイアログを開く。
3. 読みを打って「反映」→ `applyRubyToSelection` が、付いたルビに当たれば読みを置き換え、当たらなければ `[本文(rb,読み)]` を付ける。

### 変えた後の流れ（案A）

2 で、本文を読んで、控えが付いたルビに当たるかを確かめる。当たれば、読みの欄に今の読みを入れて開き、欄の文字を全部選んだ状態にする（そのまま打てば置き換わり、矢印キーで一部を直せる）。当たらなければ、今と同じく空で開く。

ルビの見つけ方は、`applyRubyToSelection` と同じ規則を使う。2か所に同じ規則を書くと食い違うので、見つける部分を `findRubyAtSelection` として切り出し、`applyRubyToSelection` もそれを使う形にする（書き換えの結果は変えない）。

### 今の読みの取り出し方

| 書き方 | 例 | 欄に入る読み |
|---|---|---|
| `[本文(rb,読み)]` | `[東京(rb,とう きょう)]` | `とう きょう`（一字ずつの空白もそのまま） |
| `｜本文《読み》` | `｜京都《きょうと》` | `きょうと` |
| `漢字《読み》` | `大阪《おおさか》` | `おおさか` |
