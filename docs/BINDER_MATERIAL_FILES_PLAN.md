### 気づいた点

- **ボードの資料カードは、今もどの改名・移動にも付いていかない**。素材の md の資料や、画像を入れたフォルダ（`素材/資料/`）を改名・移動すると、ファイルは動くが（フォルダの改名・移動は中の画像ごと動く）、ボードの資料カードは古いパスのまま開けなくなる。資料カード・最近の資料は付いていく。
- **画像を入れたフォルダを原稿の段へ移せる**。移すと画像・PDF は資料の候補から外れ（候補は素材フォルダの中だけ）、画面のどこにも出なくなる。資料カードは付いていく（パスは正しい）が、候補にないので開いた後の扱いが揃わない。削除の入口もなくなる（`delete_imported_reference` は素材フォルダの中だけ）。
- 改名で画像の名前を「地図2」と入れると、今の Rust は `地図2.txt` にする（拡張子を txt と決め打ちしている）。画像を改名するなら、元の拡張子を守る別の扱いが要る。
- 改名の Rust は、終わったファイルを `read_text_document` で読んで返す。画像だと中身を文字として読もうとする（失敗はしないが、無駄で、文字化けした中身が返る）。
- 素材フォルダのない作品でも、Rust の取り込み（`references_folder_for_import`、idea_migration.rs 753–780）は「素材」フォルダを作ってから `素材/資料/` へ入れる（1-6・2-3 と同じ作り方）。**入口がないだけ**。
- 画像・PDF は並び順（`project.json` の `order`）を持たない。素材の段では、置かれたフォルダの中で文字のファイルのあとに、資料の候補の順（パスの名前順）で並ぶ。

## 工程2: 仕組みの説明

### 言葉

- **ファイルの一覧**: 左のサイドバーの原稿と素材の木。Rust の `list_project_folder` が txt・md とフォルダだけを返す。チェックポイント・検索・字数・書き出し・見出しの一覧はこの一覧から読む。
- **資料の候補**: 資料として開けるファイルの一覧。Rust の `list_reference_candidates` が素材フォルダ全体から集める（txt・md・画像・PDF）。素材の段の画像・PDF はここから並べる。
- **資料カード**: 右のペインや資料レイヤーで資料を開いたカード。`.then/reference-layouts/default.json` の `cards`。
- **最近の資料**: 同じファイルの `recent`。
- **ボードの資料カード**: Canvas のボード（`.then/boards/*.canvas`）に置いた資料のカード。`type: "reference"` で、`sourcePath`（作品からの相対パス、`/` 区切り）・`name`・`kind` を持つ。

### 1. データの形

画像・PDF そのものは素材フォルダの中のふつうのファイル。どこにも「画像の一覧」は保存しておらず、毎回フォルダを読んで集める。パスを覚えているのは次の4か所（すべて作品からの相対パス）。

| 置き場所 | 保存先 | 今の改名・移動で |
|---|---|---|
| 資料カード | `.then/reference-layouts/default.json` の `cards[].sourcePath` | 付いていく（App の state を付け替え、保存は App の遅延保存） |
| 最近の資料 | 同 `recent[].sourcePath` | 付いていく |
| ボードの資料カード | `.then/boards/<id>.canvas` の `nodes[].sourcePath` | **付いていかない** |
| 本文の `@[[…]]`（ノート・原稿・投稿） | 各ファイル | 書き換えない（決まり） |

### 2. 利用者の操作と内部の処理（変えたあとの案）

| 操作 | 内部の処理 |
|---|---|
| 画像・PDF の右クリック →「リネーム」 | 名前を聞く（初期値は今の名前、拡張子つき）。拡張子を書かなければ元の拡張子を足す。Rust の `rename_project_entry` が同じフォルダの中で名前を変え、ボードの資料カードを書き換える。画面側で資料カード・最近の資料・資料の候補を付け替える。通知「「地図.png」をリネームしました」 |
| 画像・PDF を素材の中のフォルダ・素材の段の見出しへドラッグ | Rust の `move_project_entry` がそのフォルダへ移し、ボードの資料カードを書き換える。並び順は持たないので、置いた位置（前・後）は使わず、そのフォルダの中へ入れる。通知「「地図.png」を移動しました」 |
| 画像・PDF を原稿の段へドラッグ | 落とせる場所として光らない（落としても何もしない）。Rust も断る |
| 素材の中のフォルダ（画像を含む）を改名・移動 | 今と同じ。加えて、ボードの資料カードも付いていく |
| （決めてほしいこと 1 が A なら）md の資料の改名・移動 | 今と同じ。加えて、ボードの資料カードも付いていく |

### 3. 保存

- ファイルの名前と場所: Rust がその場で変える。
- ボードの資料カード: Rust が同じ命令の中で `.then/boards/*.canvas` を書き換える（変わるボードだけ）。書き換えに失敗したら、書いたボードを戻し、ファイルの改名・移動も戻して失敗にする。
- 開いている Canvas（別ウィンドウ・本文の場所に埋め込んだもの）: Canvas は自分の持っているボードを丸ごと保存し直すので、ファイルを書き換えただけでは次の保存で古いパスに戻る。画面側から「パスが変わった」を Canvas へ届け、Canvas が持っているボードの資料カードも付け替える（同じ付け替えは2回しても同じ結果なので、順番が前後しても最後は新しいパスになる）。
- 資料カード・最近の資料: 今と同じく App の state を付け替え、App の遅延保存で書く。

### 4. ほかの機能との関係

- チェックポイント・検索・字数・書き出し・見出しの一覧: どれもファイルの一覧（`collectProjectTextFiles`・`collectManuscriptFiles`、もとは `list_project_folder`）から読む。画像・PDF は一覧に入れないので、改名・移動を広げても読もうとしない（工程3）。
- 資料の削除（`delete_imported_reference`）: 素材フォルダの中の資料だけ消せる。素材の中で移すだけなので、移した後も消せる。
- 投稿の「ノート」の記録（2-3）: ノート（md）のパスだけを持つ。画像・PDF には関係しない。
- プラグインの目印（`retargetPluginAnchors`）: 本文のファイルのパスだけ。画像・PDF のパスを渡しても当たるものがないだけ。

## 工程3: 依存関係

### 改名・移動を txt・md 以外へ広げたとき、画像を読もうとする処理がないか

| 処理 | どこからファイルを集めるか | 画像・PDF を読むか |
|---|---|---|
| チェックポイント（`create_project_checkpoint`） | 画面側がファイルの一覧（txt・md）の木と中身を渡す。戻すときも txt・md だけ書き、フォルダは `ensure_project_folder_tree` で作るだけ | 読まない。戻しても画像は動かない・消えない |
| 検索・置換（`projectSearchActions.ts` 224） | `collectProjectTextFiles(projectFolder)` | 読まない |
| 字数（`projectAst.ts`） | `collectProjectTextFiles`、素材は除く | 読まない |
| 書き出し（`collectManuscriptFiles`） | ファイルの一覧の原稿だけ | 読まない |
| タブ・書きかけの記録 | タブは txt・md だけ開く | 画像のタブはない |
| 改名の返り値（`rename_project_entry` → `read_text_document`） | 改名したファイルそのもの | **読む**。画像・PDF では読まずに、フォルダと同じ形（中身なし）で返すように変える |
| 移動の返り値（`move_project_entry_unlocked` → `read_text_document`） | 移したファイル | **読む**。同じく画像・PDF では読まない |
| 並び順（`prepare_project_config_after_move`） | `list_project_entries`（txt・md） | 読まないが、移した先の `order` に名前を入れる。画像・PDF のときは入れない |
| 進捗（`retarget_file_progress_path`） | `project.json` の進捗 | 画像に進捗はないので、当たるものがないだけ |
| 資料の候補（`list_reference_candidates`） | 素材フォルダ | 画像を名前と大きさだけ見る（中身は読まない）。改名・移動のあと、画面側で付け替える |

結論: 画像・PDF をファイルの一覧に入れないままにすれば、チェックポイント・検索・字数・書き出しは今と変わらず画像を読まない。Rust の改名・移動の中で中身を読む2か所と、並び順に名前を入れる1か所だけを、画像・PDF のときに外せばよい。

### 変える処理を呼ぶもの・書くもの

- `rename_project_entry`: 画面の `handleRenameProjectEntry` と、2-3 の「ノートにする」は使っていない（新しいファイルを作る）。`materials_role.rs` のテストが素材フォルダの改名で呼ぶ。
- `move_project_entry`: 画面の1つの移動、`move_project_entries` の中、`file_move_diagnostics.rs`（`test:sidebar-file-move`）。
- ボードのファイル: Canvas の保存（`save_canvas_board`、錠なしで丸ごと書く）、2-5 の移行（`rewrite_boards`）、ボードの作成・削除・並べ替え。改名・移動でボードを書き換えると、開いている Canvas の保存と行き違いうる（工程2の3で、Canvas 側でも付け替えて揃える）。

## 工程5: 案

### 5-1. 方針

- Rust の改名・移動を、**素材フォルダの中にある、資料の拡張子（png・jpg・jpeg・webp・pdf）のファイル**にだけ広げる。そのほかのファイル（拡張子の違うもの、素材の外の画像）は今までどおり断る。
- 画像・PDF はファイルの一覧に入れないまま。改名・移動の命令の中で中身を読まず、並び順も持たせない。
- パスの付け替えは、今ある `retargetPathOwners` をそのまま使う（資料カード・最近の資料・資料の候補・校正の無視）。ボードだけ足す。
- 画面は、今のファイルの行と同じ見え方・同じ操作。足す文字は、メニューの「リネーム」（ほかの行と同じ言葉）だけ。

### 5-2. Rust

1. `rename_project_entry`: 画像・PDF のときは、(a) 素材フォルダの中か確かめる、(b) 入れた名前が元の拡張子で終わらなければ元の拡張子を足す（決めてほしいこと 2）、(c) 中身を読まずに返す。txt・md とフォルダは今と同じ。
2. `move_project_entry_unlocked`: 画像・PDF のときは、元と先の両方が素材フォルダの中なら通す。並び順（前・後）は受け取っても使わず、`order` に名前を入れない。中身を読まずに返す。`move_project_entries`（複数）は今のまま txt・md だけ。

4. （決めてほしいこと 3 が A）フォルダの移動で、素材の中のフォルダを素材の外へ出すとき、中に画像・PDF があれば断る。

### 5-3. 画面

1. 画像・PDF の行に `onPointerDown` を付け、ドラッグできるようにする（1つずつ）。
2. 落とせる場所: 画像・PDF を動かしているときは、素材の中のフォルダの行（真ん中）と素材の段の見出しだけ。素材の中のファイルの行の前・後へ落とすと、その行のフォルダの中へ入れる（並び順はない）。原稿の段の行・見出しは光らない。
3. 右クリックのメニューを「開く」「リネーム」「削除」にする。
4. `projectEntryActions.ts` に、画像・PDF の改名・移動の処理を足す（`findProjectEntry` を通らない）。名前を聞く欄は「ファイル名」。通知はほかのファイルと同じ文。終わったら `retargetPathOwners` で付け替え、ファイルの一覧は読み直さない（画像は一覧にないため）。
5. Canvas へパスの変更を届ける: `retargetPathOwners` から、作品からの相対パスの「前 → 後」を、別ウィンドウには新しいイベントで、本文の場所に埋め込んだ Canvas には props で渡す。Canvas は持っているボードの資料カードを付け替える（変わったときだけ保存する）。
