# Then v0.7.0 実装計画

作成日: 2026-10-16  
状態: 開発予定。本文の追加機能は未実装。

## 1. 予定する機能

v0.7.0では、原稿を書く画面に原稿用紙モードを追加し、バインダーとアイデア追加ポップアップから資料追加・AI調査依頼を行えるようにする。バインダー内のスレッドの並べ替えにも対応する。一部テーマで見づらいウィンドウ上部の文字・ボタンの配色も調整する。

| 機能 | 今回の予定範囲 |
| --- | --- |
| 原稿用紙モード | 原稿用紙◯枚で書かないといけないというニーズに対応するため、本文編集画面のモードとして追加する。升目やページの詳細仕様は実装前に確定する |
| バインダーのAI調査 | 質問を指定したAIへ送り、長い回答をMarkdown資料として同じスレッドへ保存する |
| ポップアップからの資料追加 | 既存のアイデア追加ポップアップから、追加先スレッドへ資料を追加できるようにする |
| ポップアップからのAI調査 | 既存のアイデア追加ポップアップで質問を入力し、調査依頼として追加できるようにする |
| スレッドの並べ替え | バインダーのスレッド順を利用者が変更し、その順序を保存・復元できるようにする |
| ウィンドウ上部の配色調整 | 一部テーマで背景に対して見づらい文字・アイコン・ウィンドウ操作ボタンの色を調整する |

AI調査の接続先はGemini、OpenAI、Claude、ローカルLLMの四系統を予定する。Web検索の対応能力、認証情報、保存、停止・復旧は、[AI調査の実装手順書](BINDER_AI_RESEARCH_IMPLEMENTATION_PLAN.md)に従う。

この全体計画はv0.7.0の機能範囲を管理し、AI調査の手順書はその詳細を管理する。今回の予定を記録した段階で、アプリのバージョン番号やリリース告知を変更しない。

## 2. 共通処理を使う範囲

バインダーとポップアップは入力の入口として扱い、資料追加とAI調査の処理は共通にする。接続処理やキー管理をポップアップへ追加実装しない。

| 処理 | 共通化する内容 |
| --- | --- |
| Idea追加 | 本文、追加先スレッドを渡す既存の処理 |
| 資料追加 | ファイル選択・取り込み、テキスト資料作成、資料候補の更新、スレッドへの参照追加 |
| AI調査依頼 | 質問の保存、実行記録の作成、待機列、回答の資料化 |
| 追加先 | 操作開始時の作品とスレッドIDを保持し、画面移動後に別の追加先へ適用しない |
| スレッド順 | 一覧と各入力欄の追加先選択で、共通の保存順序を使う |

ポップアップは現在の `QuickIdeaModal` を拡張する。資料選択・作成後に入力中の文章が失われず、AI調査依頼は保存・受付が完了してから閉じる。閉じた後の調査はバインダー側で確認できるようにする。

## 3. 実装の順序

以下は手戻りを抑えるための作業順案とする。原稿用紙モードの仕様確認は先に行い、コード変更はバインダー系と分ける。

1. 原稿用紙モードの表示・編集・出力の対象範囲を決める。バインダー側ではスレッド順の保存方式と共通の追加処理を確認する。
2. スレッドの並べ替えと保存・復元を実装する。既存のスレッド内項目の並べ替えと区別する。
3. 既存の資料追加処理をポップアップへ接続する。新しい取り込み・保存処理を作らない。
4. AI調査の手順書に沿って、バインダーで質問から回答資料の保存まで完成させる。
5. 共通の調査依頼処理をポップアップへ接続し、同じ追加先・状態・資料保存の規則で動かす。
6. 原稿用紙モードを、確定した仕様の範囲で実装する。
7. 一部テーマのウィンドウ上部の配色を調整し、通常時・ホバー時・非アクティブ時の見やすさを確認する。
8. 各機能の回帰確認後、組み合わせた状態で受け入れ試験を行い、操作マニュアルとリリース告知を更新する。

AI調査の初期版にポップアップ対応を含める。バインダーだけで動く段階は途中の到達点であり、v0.7.0の予定範囲全体の完了とは扱わない。

### 3.1 開発期間の目安

開発期間は、着手から約1か月半を計画上の目安とする。v0.6.6の開発にも前バージョンから約1か月かかったことを踏まえ、今回の追加範囲に応じた期間を確保する。着手日と公開日は、この文書では確定しない。

期間内の配分案は、仕様確認・機能開発に約4週間、組み合わせた状態での検証・修正・公開準備に1〜2週間とする。配分は暫定とし、工程ごとの作業量が分かった時点で更新する。

原稿用紙モードの編集挙動と、各AIの検索・引用・保存への対応には未確定部分がある。最初の仕様確認と、一つのAPIでの一連の実動作が完了した時点で残りの作業量を見直す。期間が不足する場合は公開目安と追加仕様を見直し、保存・復旧・本文入力の確認を省いて日程に合わせない。

## 4. 原稿用紙モードの仕様確認

原稿用紙モードを追加することは予定範囲として確定している。次の詳細はまだ確定していないため、この計画だけで独自の仕様を実装し始めない。

| 確認項目 | 決める内容 |
| --- | --- |
| 升目と用紙 | 字数・行数、余白、ページの見せ方、変更できる設定 |
| 縦横 | 【決定】縦書き・横書きに対応する |
| 配置 | 禁則、句読点、段落字下げ、半角文字や連続する英数字の扱い |
| 独自記法 | ルビ、圏点、縦中横、見出し、装飾を升目へどう配置するか |
| 既存機能 | 【一部決定】タイプライタースクロールにも対応する。ページ区切り表示を実装。選択、カーソル、IMEとの関係は未確定・未検証 |
| 保存と出力 | 【一部決定】表示・編集について集中的に実装する。PDF等の原稿用紙出力はVivliostyle側の設定が関わるため要検討。設定の保存単位は未検討 |

既存の原稿テキストを升目に合わせて空白や改行で書き換えない方針を基本案とする。表示・レイアウト側で実現できる範囲を先に調べ、エディタ全体の置き換えを前提にしない。

## 5. スレッドの並べ替え

予定するのはスレッド一覧の並べ替えであり、既存のIdea・資料のスレッド内並べ替えに追加する機能となる。並べ替えでスレッドIDや、含まれるIdea・資料の所属を変更しない。

初期案は、保存されているスレッド配列の順序を使い、インボックスを先頭に固定し、通常スレッドを手動で並べ替える方式とする。現行一覧もインボックスを先頭に表示するため、その規則を流用できる。並べ替え操作をドラッグおよび上下移動で行う。

検索・スターによる絞り込み中の並べ替えは、非表示項目との順序を取り違えない仕様にする。初期案では「すべて」かつ検索なしの一覧で操作できる範囲に限定する。保存モードが作品単位か端末共通かに応じて既存のIdea保存先へ順序を保存し、新しい順序専用ストアは必要になった場合だけ設ける。

調査中のスレッドを一覧内で並べ替えても、調査依頼を再送・停止したり、回答の保存先を変更したりしない。追加先の解決には配列の位置ではなくスレッドIDを使う。

## 6. ウィンドウ上部の配色調整

一部テーマで、ウィンドウ上部の背景色に対して文字や操作ボタンが見づらくなる問題を修正する。2026-10-16に共有された画像では、緑系の背景に対する一部のパンくず文字と、右端のウィンドウ操作アイコンの視認性が確認対象になる。対象テーマ名は実装時に特定する。

対象は上部バーの文字・アイコン、最小化・最大化／元に戻す・閉じるボタンとする。通常時に操作を識別でき、ホバー時にも文字やアイコンが背景へ埋もれない配色にする。非アクティブ時の表示も確認する。

既存のテーマ変数と上部バーのスタイルを確認し、共通スタイルの問題か、テーマ固有の指定の問題かを分けて修正する。今回の範囲は上部バーの視認性改善とし、テーマ全体の配色変更へ広げない。明色・暗色テーマへの影響と、閉じるボタンのホバー表示を確認する。

## 7. v0.7.0の受け入れ確認

- [ ] 確定した仕様の原稿用紙モードへ切り替え、本文編集・IME入力・保存が動く。
- [ ] 原稿用紙モードと既存表示の切り替えで、本文や独自記法が意図せず変化しない。
- [ ] バインダーからAI調査を依頼し、回答をMarkdown資料として同じスレッドで読める。
- [ ] ポップアップから資料を追加でき、入力中のIdeaや追加先が失われない。
- [ ] ポップアップからAI調査を依頼し、閉じた後もバインダーで状態と回答を確認できる。
- [ ] バインダーとポップアップで、認証、送信内容、停止・復旧、資料保存の処理が共通になっている。
- [ ] スレッドを並べ替え、再起動後も順序が保たれる。追加先選択にも同じ順序が反映される。
- [ ] スレッドの並べ替えが調査の実行状態や資料の所属へ影響しない。
- [ ] 対象テーマでウィンドウ上部の文字・アイコン・最小化・最大化／元に戻す・閉じるボタンが背景に埋もれず、通常時・ホバー時・非アクティブ時に識別できる。
- [ ] 配色調整によって他の明色・暗色テーマの上部バーが見づらくならない。
- [ ] 既存のIdea追加、資料カード、スレッド内並べ替え、本文編集が維持される。
- [ ] AI調査手順書の完了条件と、各接続先の実装済み能力を確認する。
