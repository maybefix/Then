## 工程2: 仕組みの説明

### 言葉

- **コピーのカード**: Idea の断片の本文を写したテキストカード。OriginRef（`thenOrigin`）が付いている。元の断片とは同期しない。
- **元**: カードの OriginRef が指す断片。2-4・2-5 のあとは、断片そのものはなく、投稿かノートの1段落になっている。
- **置き換え**: テキストカードを、同じ ID・位置・大きさ・色のファイルのカードにすること（4-4 の「カードごと」と同じ形）。矢印はカードの ID でつながっているので残る。
- **移行の記録**: `project.json` の `ideaMigration.fragments`。断片の ID から、投稿の ID かノートのパスが引ける。

### 1. データの形

前（テキストカード）:

```json
{ "id": "node-1", "type": "text", "x": 0, "y": 0, "width": 260, "height": 150, "text": "港の場面の一",
  "color": "4", "thenOrigin": { "source": "idea", "sourceId": "a-s1", "sourceThreadId": "a-t1",
  "sourceWorkspacePath": "C:\\…\\作品A", "copiedAt": 1783243519253 } }
```

後（ファイルのカード）:

```json
{ "id": "node-1", "type": "file", "x": 0, "y": 0, "width": 260, "height": 150, "file": "素材/場面： 港.md", "color": "4" }
```

- 本文・題・縦横・フォント・OriginRef・スレッドの欄は、ファイルのカードには持たない（4-4 と同じ）。バックアップには残る。
- 置き換えたカードを親にしていたスレッドの子は、その場に残してスレッドから外す（4-4 の `convertCardsToFiles` と同じ）。

### 2. 利用者の操作と内部の処理

| 操作 | 今 | 4-5 のあと（案） |
|---|---|---|
| 新しい版で起動する | Plot → Idea → 中間稿の移行、通知1つ | そのあとにコピーのカードの移行。通知は同じ1つにつなげる |
| 作品を開く・切り替える | 同上（その作品だけ） | 同上 |
| コピーのカードを見る | テキストのまま。元への印はない | 置き換えたものはノートのカード（ノートの本文を映し、直すとノートへ書き戻す。4-2） |
| 置き換えを戻す | — | 画面からは戻せない（バックアップのボードを写して戻す） |

### 3. 保存

- ボード: `<作品>/.then/boards/*.canvas`（ライブラリ直下も同じ）。global のボードは今は読めない（`canvas_boards_dir`、`lib.rs:4641-4659`）。ゴミ箱のボードは `.then/boards/.trash/<日時>--<ID>.canvas`。
- Canvas の保存は、読んだときのハッシュを `save_canvas_board` の `expected_hash` で送り、ファイルが変わっていたら書かずに「ほかのアプリでファイルが変更されました」（「ファイルの内容を読み込む」「この内容で上書きする」）を出す（`lib.rs:3817-3846`、`CanvasWindowApp.tsx:4132-4160`）。
- 移行は Rust がボードのファイルを直接書く（2-5 の資料カードの書き換えと同じ）。開いている Canvas は、次に保存するときにハッシュが合わないことで気づく。

### 4. ほかの機能との関係

- **埋め込みの Canvas**: 作品を切り替えると本文の画面に戻り、Canvas の中身は捨てる（`App.tsx:6275-6281`）。開き直すと読み直すので、移行と重ならない。
- **別ウィンドウの Canvas**: 作品を切り替えても、開いたときの作品のボードのまま残る。同じ作品を開き直したときだけ、移行が開いているボードを書き換えうる（起動時は別ウィンドウがない）。
- **リンク索引・つながり**: 「置かれているボード」はファイルのカードも数える（`link_index.rs:101`）。置き換えると、ノートのつながりにそのボードが出る。
- **「この順で原稿を作る」（4-4）・「投稿にする」**: テキストカードだけが対象。置き換えたカードは対象から外れる。
- **ボードを送る・ゴミ箱・戻す**: カードをそのまま運ぶ。ゴミ箱のボードを戻すと、コピーのカードも戻る。

### 5. 今の挙動の癖（直さないもの）

1. OriginRef の `sourceWorkspacePath` は送ったときの作品の場所のまま。ライブラリへ取り込んだ作品では古い場所を指す（手元の2枚）。
2. 同じ ID のカードが、ライブラリ直下のボードと作品のボードに1枚ずつある（手元の2枚。ボードを送ったか写したもの）。
3. ドラッグで作ったコピーには OriginRef がない。
4. アプリ側の Idea の移行は断片の行き先を記録しない。

### 画面を隠す・動かすので、そこからしか届かなくなる操作

今回は画面を隠さない・動かさない。ただし置き換えたカードでは、テキストカードでしかできない次の操作ができなくなる。

| 操作 | テキストカード | ファイルのカード | ほかの届き方 |
|---|---|---|---|
| カードの本文を直す | ボードに書く | ノートへ書き戻す（ノートをタブで開いていれば表示だけ） | ノートを開いて直す |
| 題・縦横・フォントをカードごとに変える | できる | できない | ノートの側で |
| スレッドに入れる・スレッドの親にする | できる | できない | なし（外れたままになる） |
| 「投稿にする」 | できる | 対象外 | 投稿の欄に写す |
| 「この順で原稿を作る」 | 対象 | 対象外 | — |
| 置き換えの前の文に戻す | — | Canvas の Ctrl+Z の履歴に入らない | バックアップのボード（画面からは届かない） |

## 工程5: 案

### 5-1. 方針

- 4-4b と同じく、Rust の命令1つで作品ごとに移す。起動時と作品を開いたときに、Plot → Idea → 中間稿 → コピーのカードの順で呼び、通知は1つにつなげる。
- 置き換えは、元がはっきり分かり、置き換えても文が失われないカードに限る。それ以外は何もしない（テキストのまま、OriginRef も残す）。
- 「済んだ」の印は持たない。置き換えたカードはテキストカードでなくなるので、次に呼んでも何もしない。残したカードは毎回調べ直すが、書かない（ボードを読むだけ）。

### 5-2. 移行の流れ（勧めの形）

1. 作品（またはライブラリ直下）のボード `*.canvas` を読み、OriginRef 付きのテキストカードを集める。なければ何もしない。
2. 元を探す。断片の ID で、まずそのボードの作品の `ideaMigration.fragments` を、なければライブラリ直下と他の作品の記録を引く（`sourceWorkspacePath` は使わない。癖1）。
3. 行き先を決める（決めてほしいこと 1〜4）。
   - ノートの1段落になった断片で、そのノートが同じ作品にあり、カードの本文が元の断片（バックアップの本文）と同じ → そのノートのファイルのカードへ置き換える。
   - 投稿になった断片で、その投稿をあとで同じ作品のノートにしている → そのノートへ置き換える。
   - それ以外（投稿のまま・元が見つからない・別の作品のノート・本文が違う） → 何もしない。
4. 置き換えるボードがあれば、そのボードをバックアップ `<作品>/.then/backups/copy-cards-<日時>/boards/` に写して読み直し、同じであることを確かめる。何を置き換えたかを `cards.json`（ボード・カード ID・元の断片・指したノート）に書く。
5. ボードを書く（一時ファイルから置き換え）。途中で失敗したら、その回に書いたボードをバックアップから戻す。
6. 結果（置き換えた枚数、ボード）を返す。画面は通知の文を作り、置き換えたボードがあればファイルの一覧は読み直さない（ファイルは増えない）。

### 決めてほしいこと

場面ごとに案を当てはめた比べ表: [BINDER_COPY_CARD_MIGRATION_SCENARIOS.md](BINDER_COPY_CARD_MIGRATION_SCENARIOS.md)

#### 1. 置き換える条件（本文が元と違うとき）

- **A. 本文が元と同じときだけ置き換える（勧め）**。比べるのは改行の形（CRLF/LF）だけをそろえた本文。違うカード（カードで直した）はテキストのまま残す。理由: 置き換えるとカードの文はノートの本文に変わり、カードで直した文は画面から消える。同じなら失うものがない。
- B. 違っても置き換え、カードの文をノートの末尾に段落で足す。ノートの中身が変わる（2-4 で作ったノートに、利用者が書いていない段落が増える）。
- C. 違っても置き換え、カードの文はバックアップにだけ残す。画面から見えなくなる。

#### 2. 元が見つからないカード・置き換え先がないカード

- **A. テキストのまま残し、OriginRef も残す（勧め）**。何も書かない。理由: 文を失わず、あとで投稿のカードなどができたときの手がかりになる。毎回調べ直すが、書かないので重さは読むだけ。
- B. テキストのまま残し、OriginRef を外す（次から調べない）。ボードを書くので、バックアップも作る。
- C. 消す（勧めない。文が失われる）。

#### 3. 投稿になった断片から来たカード（手元の2枚はこれ）

- **A. 投稿をあとでノートにしていれば（投稿の行の `note`、同じ作品）そのノートへ、そうでなければテキストのまま（勧め）**。理由: Canvas に投稿を指すカードがない。投稿のカードを作るのは 4-5 の範囲を超える（別の作業の候補にする）。
- B. 投稿は全部テキストのまま（ノートにした投稿も置き換えない）。
- C. 移行のときに投稿をノートにして（2-3 の「ノートにする」と同じ形）置き換える。投稿が受信箱から外れ、ノートが増える。

#### 4. 同じスレッドから来たカードが何枚もある・スレッドのグループ

- **A. そのスレッドから来たカードが、そのボードに1枚だけのときに置き換える。2枚以上なら全部テキストのまま（勧め）**。グループ（スレッドを送ってできた枠）はそのまま。理由: ファイルのカードはノートの全文を映すので、2枚以上を置き換えると同じノートのカードが並び、矢印の意味（断片の順）も消える。
- B. 全部置き換える（同じノートのカードが並ぶ）。
- C. グループと中のカードを、グループの位置のノートのカード1枚にまとめる（中のカードと矢印を消す）。

#### 5. カードの ID・位置・色・矢印

- **A. 保つ（勧め）**。4-4 の「カードごと」と同じく、同じ ID・位置・大きさ・色のファイルのカードにし、矢印はそのまま残る。置き換えたカードを親にしていたスレッドの子はスレッドから外す。置き換えたカードがスレッドの子なら、スレッドから外れる（ファイルのカードはスレッドに入れない）。
- B. 新しい ID のカードを横に置き、元のカードは残す（置き換えではなく足す）。

#### 6. 通知の文

- **A. 「コピーのカード N 枚をノートのカードに置き換えました」を、Plot・Idea・中間稿の通知のあとに「。」でつなぐ（勧め）**。置き換えが0枚なら何も出さない。失敗は「コピーのカードを置き換えられませんでした」。理由: 4-4b と同じ作り。
- B. 何も出さない。

#### 7. 別ウィンドウで開いているボード

- **A. 移行の前に別ウィンドウの保存を書き切ってもらい（`flushCanvasWindow`）、置き換えたボードを別ウィンドウが開いていれば、読み直してもらう（勧め）**。理由: そのままだと、別ウィンドウで次に保存したときに「ほかのアプリでファイルが変更されました」が出て、「この内容で上書きする」を選ぶと置き換えが戻る。2-6 の改名と同じく、知らせを1つ足す。
- B. 何もしない（ハッシュの確かめに任せる）。

#### 8. ゴミ箱のボード

- **A. 移さない（勧め）**。戻したあと、次に作品を開いたときに移る（印を持たないので）。理由: ゴミ箱を空にする操作がない（KNOWN_ISSUES）ので、ゴミ箱のボードを書き換える意味が薄い。
- B. ゴミ箱のボードも移す。

### 見つけた癖（確認2で決める）

1. **ファイルのカードは色を保存しても画面に出ない**: `c-same` は `color: "3"` と `data-color="3"` を持つが、色の CSS が `.canvasTextNode[data-color]` にしか当たっていない。4-2 からの挙動で、4-4 の「カードごと」も同じ（KNOWN_ISSUES 2026-11-22）。
2. **同じノートのファイルのカードがすでにあっても、コピーのカードを置き換える**: S9 で足した `c-new` は、すでにある `c-same` と同じノートのカードになり、同じノートのカードが2枚並んだ。決めごと 4 は「同じノートへ行くコピーのカード」だけを数えていて、すでにあるファイルのカードは数えない（KNOWN_ISSUES 2026-11-22）。
