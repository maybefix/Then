## 工程2: 仕組みの説明

### 言葉
- **遅延保存**: 書き換えのたびにすぐ書かず、少し待ってからまとめて書く。続けて書き換えると待ち直す。
- **useEffect の後片付け**: React が、useEffect の見ている値が変わったとき（または画面から消えるとき）に、前の回の useEffect が返した関数を呼ぶこと。新しい回の useEffect はその後に走る。
- **待っている保存の一覧**（`src/pendingSaves.ts`）: 遅延保存が、待ち始めるときに「今すぐ書く」処理を名前で載せ、書いたら外す一覧。閉じる前に `flushPendingSaves` で全部書く（PR maybefix/Then#35）。

### 1. 今の流れ（作品Aで Idea を書いて、すぐ作品Bへ切り替える）
1. Idea を足すと、作品の Idea の値（`snippets`）が変わり、useEffect が「0.7 秒後に作品Aの `project.json` へ書く」を予約する。保存する中身と作品Aのパスは、この予約の中に取っておかれる。並び順も変わるので、資料ボードのファイルの保存も同じように予約される。
2. 0.7 秒たたないうちに切り替えメニューで作品Bを押すと、`openWorkspaceFolder` が作品Bの Idea・プロットなどを読み、作品のパス（`projectFolder`）と作品の値をまとめて作品Bのものにする。
3. 値が変わったので、React が前の回の useEffect の後片付けを呼ぶ。後片付けは予約を取り消す（書かない）。
4. 新しい回の useEffect は、作品Bの値で走る。作品Bでは何も変わっていないので、作品Aの書き換えはどこにも書かれない。
5. 作品Aへ戻ると、ディスクの古い Idea が読まれ、書いた Idea はない。

### 2. 後片付けが呼ばれるとき
作品の切り替えのほかに、同じ作品の中で値が変わるたびに呼ばれる（Idea を1つ足すたび、プロットを1文字変えるたび）。このときは、新しい回の useEffect が新しい値で予約し直すので、取り消してよい。後片付けからは、どちらの理由で呼ばれたかが分からない。

### 3. 前の作品の値が新しい作品へ書かれないこと
予約の中に、予約した時点の作品のパスと中身が取っておかれる。新しい作品の値で予約するのは、新しい作品の値が読み込まれた後だけ（`snippetWorkspacePath`・`plotWorkspacePath`・`proofreadTermsWorkspacePath` が新しい作品のパスと同じとき、資料ボードは `referenceLayoutLoadedRootRef` が新しい作品のパスのとき）。

### 4. ほかの機能との関係
- 閉じる前の書き切り（`flushPendingSaves`）は、待っている保存の一覧を使う。切り替えで取り消された保存は一覧からも外れる。
- Idea の管理単位の切り替えは、切り替える前に作品の Idea を自分で書いている。
- アンカーは、作品の切り替えで前の作品へすぐ書く。

### 5. 今の挙動の癖（直さないもの）
1. **作品を切り替える直前 0.7 秒以内の、作品ごとの書き換えが消える**（この修正の対象）。
2. カーソル位置は、動かしてから 0.6 秒以内に別のファイルへ移ると、覚えられない（`cursor-position` の後片付けが取り消す）。作品の切り替えに限らない。今回は直さない。
3. Canvas などの子の窓の側の遅延保存（`docs/ANCHOR_SAVE_ON_CLOSE_FIX_PLAN.md` の癖3）。今回は扱わない。

## 工程3: 原因

作品ごとの遅延保存の後片付けが、作品が変わったときも、同じ作品の中で値が変わったときと同じく、予約を取り消すだけにしている。作品が変わったときは、新しい回の useEffect がもう前の作品の値を持っていないので、取り消した書き換えを書く者がいない。

### 再現（自動テスト、`ba66a59`）
`scripts/test-save-on-work-switch.mjs`（新しく足す `test:save-on-work-switch`）。App 全体を build して headless の Edge で動かし、Rust の代わりに、作品A・作品Bの保存先を持つ入れ物を置く。保存の命令（`save_project_snippets` など）は、どの作品へ何を書いたかを記録し、保存先の中身を置き換える。もう一度開くと、保存したものが読まれる。
1. 作品Aの Idea の一覧で「作品Aで切り替える直前に書いたIdea」を追加し、62ms 後に切り替えメニューで作品Bを押す。2 秒待つ。**作品Aへの保存は1回も呼ばれなかった。** 作品Bへは、開いた 0.7 秒後に作品Bの値（Idea・プロット・校正辞書・無視した指摘・資料ボード）が書かれた。
2. 作品Bでプロットの「セクションを追加」を押し（右サイドバーに 001・002 が出た）、117ms 後に作品Aへ切り替える。**作品Bへのプロットの保存は呼ばれず、作品Bの保存先のプロットは1枚のまま。**
3. 作品Aに戻ると、Idea は「作品Aのメモ 1 件」で、足した Idea はなかった。
4. 前の作品の値を新しい作品へ書いた保存はなかった（今も、直した後も、これを確かめる）。

### 見つけた別の癖（調べている途中で）
- 作品を開くと、何も変えていなくても 0.7 秒後に `project.json` へ Idea・プロット・校正辞書・無視した指摘を書き直す（上の再現の1で、作品Bへ4回）。資料ボードのファイルは、開いただけでは書かない（`referenceLayoutOnDiskRef`、`docs/REFERENCE_LAYOUT_STARTUP_FIT_PLAN.md`）。中身は読んだものと同じなので、失われるものはない。

## 工程5: 案

### 5-1. 方針
作品が変わるときだけ、待っていた保存を、取っておいた前の作品のパスと中身で書く。同じ作品の中で値が変わるときは、今のまま取り消して待ち直す。前の作品の値を新しい作品へ書く経路は作らない（予約の中のパスと中身だけを使う）。

### 決めてほしいこと

**1. 直し方**
- **案1: 後片付けで、作品が変わったときだけ、取り消す代わりに前の作品へ今書く。** 勧め。消えるのは後片付けで取り消すときなので、そこで直す。作品を変える入口が5つあっても（切り替えメニュー、別の作品のファイルを開く、作品を閉じる、など）すべてに効く。アンカーと同じ形。App が「今開いている作品のパス」を描画の直後に覚え（`useLayoutEffect`）、後片付けでそれが予約のパスと違えば書く。`schedulePendingSave` に「取り消す代わりに書くか」を渡せるようにする。書くのは新しい作品の値が画面に入った直後で、書き終わるのは待たない。
- 案2: 切り替えの処理（`openWorkspaceFolder`）の頭で `flushPendingSaves` を待つ。書き終えてから新しい作品を読むので、すぐ同じ作品へ戻っても順番が確か。ただし、ほかの入口（別の作品のファイルを開く、作品を閉じる）にはそれぞれ足す必要がある。また、読み込みのあいだ（数百 ms）に書き換えたものは、今と同じく消える。アプリ状態やカーソル位置も、ついでに早く書く。
- 案3: 案1と案2の両方。順番も確かで、入口の漏れもない。手間と変える場所が増える。

**2. 見つけた別の癖（開いただけで `project.json` を書き直す）**
- **今回は直さず、`docs/KNOWN_ISSUES.md` に記録する。** 勧め。失われるものはなく、直すと読み込みの処理（4つの読み込みと、何を「読んだ値」とみなすか）に手が入る。
- 一緒に直す（資料ボードと同じく、読んだ値と同じなら書かない）。

### テストの直し方と足すテスト
- `test:save-on-work-switch`（足す。今は落ちる）: 上の再現の1〜4。直した後は、作品Aへ切り替えるときに Idea と並び順が作品Aへ書かれ、作品Bへ切り替えるときにプロットが作品Bへ書かれ、作品Aへ戻ると Idea があり、相手の作品の保存先は元のまま。
- 案1なら `test:pending-saves` に足す: 後片付けで「書く」と答えると、待たずに一度だけ書き、一覧から外れる。「書かない」なら今のとおり取り消す。もう書き終えた予約は、後片付けで書き直さない。
- 既存のテストの期待は変えない。

### 実機確認
- 再現（直す前のアプリ）: 作品Aで Idea を足してすぐ作品Bへ切り替え、作品Aの `project.json` を切り替えの前後で比べる。プロット・校正辞書・資料ボードも同じように。
