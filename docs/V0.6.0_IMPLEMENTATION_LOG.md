## ページ編集の再実装

### 2026-08-27: 初回実装の問題を確認

- 初回実装は単一の連続本文を画面幅単位で移動し、ページ枠を重ねただけであり、本文を固定ページへ再組版していなかった。
- ページ数も実際のページ断片ではなくスクロール量から推定していた。
- 縦送りは横方向の本文移動を上下操作へ割り当てただけで、ページ単位のレイアウトになっていなかった。
- この状態は要求された「ページング表示での編集」を満たさないため、完了判定を撤回する。

### 再実装方針

- 各ページに固定の本文領域を持たせ、本文が領域を超えた時点で次ページへ自動リフローする。
- ページ数分のページ枠を実際に生成する。
- 横送りではページを右から左へ並べ、縦送りでは同じページ断片を上から下へ移動できるようにする。
- ProseMirrorの編集状態・IME・Undo・選択範囲は単一のまま維持し、CSS断片化されたページ表示と同期する。
- 再実装が完了するまで、既存のインストーラーを完成版として扱わない。

### 2026-08-27: 実ページへの本文断片化

- 固定サイズの編集領域に CSS multi-column を適用し、入りきらない本文を同じ寸法のページ断片へ自動的に送り出す構成へ変更した。
- ページ枠は断片数と同じ数だけ生成し、各枠の内側だけを表示する。単一の巨大な編集面を枠で囲っただけの旧方式は廃止した。
- 縦書きでは断片化軸が上下、横書きでは左右になるため、表示中ページに対応する断片を編集枠内へ移動して表示する。
- ページ移動軸とは分離し、横ページ送りは右から左、縦ページ送りは上から下へページ枠と編集内容を同期させる。
- 表示中のページ枠だけで本文をクリップし、編集・選択に伴ってキャレットがページ境界を越えた場合は、その断片のページへ自動追従する。

## ページ表示の見出しジャンプ修正

### 2026-08-28: 不具合と原因

- 見出し・検索結果などから本文へジャンプした際、ページ境界ではない中途半端なスクロール位置で停止する不具合を確認した。
- ページ表示でも通常表示と同じフォーカス処理を使っていたため、ブラウザがキャレットを先に可視化しようとしてページ面を任意量スクロールしていた。
- ページ面全体に設定されていた `scroll-behavior: smooth` により、対象ページへ戻す補正も即時反映されず、半端な位置が残り得た。

### 修正方針

- ページ表示中のプログラム的なフォーカスには `preventScroll` を使う。
- 見出しジャンプ後はキャレットが属するページを算出し、そのページ境界へ即時スナップする。
- ボタン操作によるページ送りだけは従来どおり滑らかに移動する。

### 2026-08-28: 行番号の不具合を追加確認

- ページ表示の1ページ目で、先頭行の番号に最終ページ側の番号が重なって表示される不具合を確認した。
- 複数ページにまたがる段落では、同じ列位置にある別ページの文字断片が1本の表示行として統合され、段落全体の矩形が可視判定に使われていた。
- ページ表示では文字断片をページ単位に分離して文書順に数え、行番号・現在行ハイライトとも現在ページの断片矩形だけを使うよう修正する。

### 2026-08-28: 修正実装と実画面検証

- 縦書き本文は後続断片を負のY方向へ生成し、表示時にページ番号分だけ正方向へ移す構成へ変更した。これにより1ページ目が必ず文書先頭になる。
- 負方向のoverflowは `scrollHeight` に含まれないため、本文Rangeのunion寸法から実ページ数を算出するよう変更した。
- 行断片は過去の同一座標を全検索せず、文書順で隣接する断片だけを統合する。別ページで再利用される同じ列位置は別の行として扱う。
- 150行・13ページの縦書き検証本文で次を確認した。
  - 1ページ目は行番号1〜12、2ページ目は13〜24。
  - 後半見出しへのジャンプは9ページ目の境界（縦送り `scrollTop=4760`）へ移動。
  - 先頭見出しへ戻ると1ページ目の境界（`scrollTop=0`）へ即時復帰。
  - 横送りでも後半見出しは9ページ目、先頭見出しは `scrollLeft=0`、次ページは負方向へ移動し、行番号13〜24を表示。
- ページ操作ボタンによる移動は滑らかなまま維持した。
- `npm run test:v058-high-risk`、`npm run test:v059-visibility`、`npm run test:v0510-ime-visual-lines` はすべて成功した。
