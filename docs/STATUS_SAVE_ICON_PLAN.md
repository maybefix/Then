## 工程2: 仕組みの説明

### 言葉

- 保存の状態（`SaveStatus`）: 開いている文書が、読み込み中（`loading`）・保存済み（`saved`）・未保存（`dirty`）・保存中（`saving`）・保存失敗（`error`）のどれか。
- 保存点: 利用者が手で作るチェックポイント。ステータスバーには最後の手動保存点からの経過時間と字数の増減を出す。

### 1. 画面に出るもの

左から、保存の印、保存の状態の文言、（設定で出すなら）ファイルの場所、エラー、ページ数、原稿用紙の枚数、保存点、プラグインの項目、右端に字数。印は飾りで（`aria-hidden`）、読み上げは隣の文言が担う。

### 2. 操作と内部の処理

| 操作 | 内部で起きること | 印 |
|---|---|---|
| 文書を開く | 読み込み中 → 保存済み | 黄 → 緑 |
| 文字を打つ | 未保存になり、少し待って自動保存。保存中を経て保存済み | 黄 → 黄 → 緑 |
| 保存に失敗 | 保存失敗 | 赤 |

### 3. 保存

印は表示だけで、何も保存しない。保存点の表示も、保存点の一覧とプロジェクトの索引から計算するだけ。

### 4. ほかの機能との関係

- 集中モードでは、ステータスバーごと隠れ、マウスを乗せると出る（`test-v0511-focus-mode`）。今回は触らない。
- タブの「保存済み」（`DocumentTabs.tsx`）は別の表示で、今回は変えない。

### 5. 今の挙動の癖

- 読み込み中・保存中も、未保存と同じ黄色の印になる。
- 保存点の表示の計算（`statusProjectVisibleTextLength`）は、設定で保存点の表示を切っているときは計算しない。

## 工程5: 案

### 5-1. 印

- 保存済み: チェックマーク。色は `--success`。
- 未保存・保存中・読み込み中: サイクルマーク（円を描く2本の矢印）。色は `--warning`。回転はさせない（止まった印のまま）。
- 保存失敗: 決めてほしいこと（下）。
- 大きさは文字（12px）に合わせて 12px。SVG は `stroke="currentColor"` で書き、色は CSS の `color` で決める。今の丸の `background` の代わりに `color` を使うだけなので、配色ごとの変数はそのまま効く。
- 「線」の配色: 保存済みは墨（`--sen-ink`）、それ以外は朱（`--sen-vermilion`）。今の枠と塗りの色分けをそのまま線の色に置き換える。
- クラス名 `statusDot` は `statusSaveIcon` に改める（丸ではなくなるため）。

### 5-2. 分離

- 案 A（勧め）: App.tsx の 3493〜3502行の2つの計算と、11843〜11853行の受け渡しの組み立てを、`src/components/status/useCheckpointStatusInfo.ts` のフック（React の関数部品から呼ぶ、値を作る関数）へ移す。App.tsx には `const checkpointStatus = useCheckpointStatusInfo({...})` の1つの呼び出しと、`checkpoint={checkpointStatus}` が残る。App.tsx は約20行減る。
- 案 B: 移さない。表示はもう `StatusBar.tsx` にあり、App.tsx に残るのは受け渡しだけなので、そのままでも筋は通る。

### 決めてほしいこと
