### 気づいた点

1. **ボードは `.then/boards/` にあり、Obsidian の保管庫からはふつう見えない。** Obsidian は名前が点で始まるフォルダを一覧に出さないので、Then のボードを Obsidian で開くのは、利用者がファイルを外へ写したときだけになる（Obsidian の決まりからの見込み。試していない）。
2. **Obsidian は知らない種類のカードを読み飛ばし、保存すると落とす。** インストール済みの Obsidian（`resources/obsidian.asar`）の Canvas の読み込み（`importData`）を読むだけで確かめた。`file`・`text`・`link`・`group` 以外は `continue` で飛ばし、保存はそのとき画面にあるカードから作り直す。今ある資料のカード（`type: "reference"`、Then 固有）も同じ扱いになる。
3. **投稿はライブラリで共有**（3.8）。ライブラリ直下のボードからも、どの作品のボードからも、同じ投稿を指せる。ファイルのカードは作品の中のファイルしか指せない（ライブラリ直下のボードから作品のノートは指せない。4-5 の気づいた点）ので、ここが大きく違う。
4. **ボードを送る先は、いつも同じライブラリの中**（作品 ↔ ライブラリ直下）。投稿のカードは、送ったあとも同じ投稿を指せる。
5. **投稿の ID は変わらない。** 消して「元に戻す」と、同じ ID の行が元の位置に戻る（`restore`）。ノートにしても投稿は残る（受信箱から外れるだけ）。
6. **投稿のペインでも本文を直せる。** カードからも直せるようにすると、同じ投稿を2か所で直せる。投稿の書き込みはどちらもハッシュを比べるので、黙って上書きはしない（後から書いたほうが「外で直された」になる）。
7. **4-5 の移行で、元が投稿のコピーのカードは「元の印」（`thenOrigin`）を残したままテキストで残っている**（4-5 の確認1の 2 で A）。移行は作品を開くたびに調べ直すので、投稿のカードができれば、同じ手がかりで置き換えられる。
8. **4-5 の移行は、ライブラリ直下のボードでは直下の記録しか見ない**（`Sources::load(root)` が、そのフォルダの `project.json` の `ideaMigration` だけを読む）。作品の断片から来たカードが直下のボードにあっても（手元の Books の1枚）、行き先を引けない。投稿のカードなら直下にも置けるので、作品の記録も引けば置き換えられる。
9. **手元の Books はまだ Idea の移行が済んでいない**（読むだけで確かめた。`テスト_snapshot検証用/.then/project.json` に `ideaThreads` があり `ideaMigration` がない。ライブラリの `posts.jsonl` もない）。4-5 で数えた2枚（ライブラリ直下 `作品用テスト.canvas` と作品の `テスト_snapshot検証用-board.canvas` の `node-mr7l5dlh-1`）は、次に新しい版で開いたとき、Idea の移行で元の断片 `frag-mr0z6zjt-6` が「受信箱から外した投稿」になり、続くコピーのカードの移行の対象になる。
10. **Canvas の「投稿にする」は、メイン画面で書けたかを待たずに「N件を投稿にしました」と出す**（`postSelectedCards` 2972行。知らせを送った時点で成功と書く。書けなかったときは、メイン画面に「投稿を保存できませんでした」が出る）。今回見つけた癖。工程2の5の K1。
11. 文字列を確かめるテスト（`text-deps`）: 関係するファイルのうち、ソースを文字列で読むのは `test:performance` の `createLatestFrameScheduler`（`CanvasWindowApp.tsx`）だけ。今回は触らない。ほかはすべて動かして確かめるテスト。

## 工程2: 仕組みの説明

### 言葉

| 言葉 | 意味 |
|---|---|
| 投稿 | 右のペイン「アイデア」に書き流す1件。ライブラリの `.then/posts.jsonl` に1行で持つ。返信は、返信先の ID（`replyTo`）を持つ投稿 |
| 投稿のカード | この作業で足す、投稿を指すカード。投稿の ID だけを持ち、本文は毎回投稿から映す |
| ファイルのカード | 4-2 のノート・原稿を指すカード（JSON Canvas の `file` ノード） |
| コピーのカード | 昔、Idea の「Canvas へ送る」で作ったテキストカード。文は Idea からの写しで、元の断片の印（`thenOrigin`）を持つ |
| 行のハッシュ | 投稿1行の中身から作る値。直す・消すときに、画面が読んだときの値と今のファイルの値を比べ、違えば書かない |
| メイン画面 | Then の本体の窓。ファイルと投稿に書くのはここだけ（4-2 の決まり）。Canvas が別ウィンドウでも、書き込みはメイン画面に頼む |

### 1. データの形（案 A のとき）

ボードのファイルに書くのはこれだけ。

```json
{ "id": "post-mr9…", "type": "post", "x": 120, "y": 80, "width": 260, "height": 150, "post": "p-mr8…", "color": "3" }
```

- `post` は投稿の ID。本文・日時・作品はボードに書かず、開くたびに投稿から読む。
- ノートか、返信か、受信箱にあるかも書かない（変わるので）。

### 2. 利用者の操作と内部の処理（勧めの組み合わせのとき）

| 操作 | 画面で起きること | 内部の処理 |
|---|---|---|
| 「資料を追加」の一覧で投稿を押す | 画面の真ん中に投稿のカードが置かれる | 一覧はメイン画面が持つ投稿（`usePostStream`）を、ノート・原稿の一覧と同じ経路で Canvas に渡す。カードは `{"type":"post","post":ID}` でボードに保存 |
| カードを見る | 見出しに「投稿」と時刻、ほかの作品の投稿なら作品名。本文は投稿の本文全部。ノートにした投稿はノートの札 | 投稿の一覧から ID で引く |
| カードをダブルクリックして直す | ノートのカードと同じく、その場で文を直せる | 0.5 秒止まったら、読んだときの行のハッシュを付けてメイン画面に頼み、`posts_update` で書く。投稿のペインもその場で新しくなる |
| カードの「開く」 | 右のペインが「アイデア」になり、絞り込み「すべて」でその投稿へ動く | 「つながり」の元の投稿と同じ（`postReveal`） |
| 投稿のペインで直す・返信する・外す | カードの文・札がその場で変わる | メイン画面の投稿の一覧が変わるたびに Canvas へ渡す |
| 投稿を消す | カードは残り、中身のない薄いカードになる | ID が見つからない。「元に戻す」で戻ると元のカードに戻る |
| ボードを送る | 送り先でも投稿のカードのまま | 送り先は同じライブラリなので、同じ投稿を指せる |
| ボードをゴミ箱へ・戻す | ほかのカードと同じ | 投稿には触らない |
| カードを複製・色・線・グループ | ファイルのカードと同じ | — |
| 「投稿にする」「この順で原稿を作る」 | 投稿のカードは入らない | どちらもテキストカードだけを見る（今のまま） |

### 3. 保存

- **ボード**: 投稿のカードは、ほかのカードと同じボードの保存（遅延保存・`expected_hash`）で書く。新しい保存の経路はいらない。
- **投稿**: カードで直した文は、メイン画面が `posts_update`（本文・ハッシュ・直した時刻）で書く。ほかの行は1文字も変えない（今の作り）。外で直されていれば書かず、カードに選ぶ画面を出す（ファイルのカードと同じ作り。ボタンは「投稿の内容を読み込む」「この内容で上書きする」の見込み）。
- **閉じるとき**: 待っている書き戻しは、ファイルのカードと同じく閉じる前に書き切る（`setPendingSave`）。
- **読み込み**: Canvas は投稿のファイルを自分では読まない。メイン画面が持つ一覧を受け取る（ファイルを読むのは1か所のまま）。

### 4. ほかの機能との関係

- **ライブラリ直下のボード**: 投稿のカードを置ける（ファイルのカードは置けない）。投稿の一覧は、直下を開いていても同じライブラリの投稿。
- **ライブラリに入っていない作品**: 投稿はその作品の `.then/` にある（3.8）。その作品のボードは、その作品の投稿を指す。外の作品へはボードを送れないので、ずれは起きない。
- **置かれているボード（3-4）**: `board_references` は投稿のカードを拾わない（知らない種類として飛ばす）。ノート・原稿の「つながり」は変わらない。投稿の側に「置かれているボード」を出すかは確認1の 5-7。
- **4-5 の移行**: 置き換え先に投稿を足すかは確認1の 4。
- **古い版の Then**: 4-2 より後の版は、投稿のカードを知らない種類として取っておき、保存で書き戻す（画面には出ない）。4-2 より前の版は、開いて保存すると落とす。
- **Obsidian**: 工程1の気づいた点 1・2。

## 工程3: 依存関係

- **カードの形**（`canvasTypes.ts`）を、ボードの読み込み（`normalizeCanvasDocument`）・保存（`serializeCanvasDocument`）・付け替え（`retargetCanvasReferenceNodes`）・送る（`libraryTransfer.ts`）・Rust の移行（`copy_card_migration.rs`）・置かれているボード（`link_index.rs`）が読む。
- **投稿の一覧**は `usePostStream`（App）が持つ。Canvas には、埋め込みなら props（`liveProjectFiles` と同じ並び）、別ウィンドウなら `CANVAS_LIVE_DATA_EVENT` と開くときの payload で渡す。
- **書き戻し**は、Canvas → メイン画面（埋め込みは関数、別ウィンドウは知らせ）→ `posts_update`。ファイルの書き戻し（`CANVAS_FILE_WRITE_EVENT`）と同じ形の別の知らせを足す見込み。
- **投稿の ID を書く処理**: `post_stream.rs` の `update`・`delete`・`restore`・`make_note` は ID を変えない。ID を作るのは `new_post_id` と、移行の `migrated_post_id`（断片から決まる値）だけ。
- **移行の順**: Plot → Idea → 中間稿 → コピーのカード（`migratePlotBeforeOpening`）。Idea の移行が投稿を作ってから、コピーのカードの移行がそれを指す。

## 工程5: 案

### 5-1. 方針

4-2 のファイルのカードの作りをなぞる。違うのは、読む先がファイルではなくメイン画面の投稿の一覧で、書く先が `posts_update` であることだけにする。Rust の命令は足さない（移行を除く）。

### 決めてほしいこと

場面ごとの見え方は [BINDER_POST_CARD_SCENARIOS.md](BINDER_POST_CARD_SCENARIOS.md)。

#### 1. 保存の形

- **A. Then 固有の種類 `{"type":"post","post":"<投稿の ID>"}`（勧め）**。持つ欄は ID・位置・大きさ・色・`post` だけ。理由: 本文を二重に持たないので、ずれが起きない。今の資料のカード（`reference`）と同じ扱いになる。Obsidian では出ないが、ボードは `.then/` の中にあり、ふつうは Obsidian から見えない。
- B. テキストのカードに写しと印 `{"type":"text","text":"<本文の写し>","thenPost":"<ID>"}`。Obsidian や 4-2 より前の Then では写しの文が出る。ただし写しは古くなり、Then が毎回書き直す（ボードの保存が増える）。外で写しを直しても Then は投稿で上書きする。テキストカードを見るほかの処理（スレッド・「投稿にする」・この順で原稿を作る）すべてに除外を足す。
- C. JSON Canvas の `link` に Then だけの URL `{"type":"link","url":"then://post/<ID>"}`。Obsidian では開けないリンクのカードが出る。

#### 2. カードで直せるか

- **A. 直せる。0.5 秒止まったら投稿へ書き戻す（勧め）**。理由: 3.4 の「カードで直したら参照先へ書き戻す」とノートのカードに揃う。投稿のペインでも直せるので、どちらで直しても同じ投稿が変わる。外で直されていれば書かずに選ばせる。空にしたときは書かない（投稿は空にできない）。
- B. 表示だけ。ダブルクリックで右のペインのその投稿へ動く。理由があるとすれば、書き戻しの経路（順番待ち・衝突の画面）を作らずに済む。

#### 3. 置く入口（いくつでも）

- **① 「資料を追加」の一覧と、別ウィンドウのサイドパネルに投稿を足す（勧め）**。資料・ノート・原稿のあとに、投稿を新しい順で並べる。行は「投稿」の札と書き出し、日時と作品名。検索は本文で当てる。理由: Canvas の中だけで済み、埋め込みでも別ウィンドウでも同じに動く。
- ② U7: 右のペイン「アイデア」の投稿を Canvas へドラッグする。投稿の本文はその場で直せる欄なので、ドラッグをつかむ場所（行の時刻など）を決める必要がある。Canvas が別ウィンドウのときはメイン画面から届かない（4-3 でバインダーから置くときと同じ）。
- ③ Canvas の「投稿にする」で、投稿にしたテキストカードを、その投稿のカードに置き換える（同じ ID・位置・大きさ・色。Ctrl+Z で戻す）。今はカードがテキストのまま残り、同じ文が2つになる。ただし今の「投稿にする」の結果を変える。

#### 4. 4-5 で残したカード（元が投稿のコピーのカード）の移行を含めるか

4-5 と同じ規則（文が元の断片と同じ、そのボードでその投稿を指すカードがこの1枚だけ、ID・位置・大きさ・色を保つ、ゴミ箱のボードは触らない、バックアップ、失敗したら戻す、通知は Plot・Idea・中間稿とつなげて1つ）で、行き先を投稿にも広げる。ノートにした投稿は、今のままノートのカードにする（作品のボード）。

- **A. 含める。ライブラリ直下のボードは、ライブラリの全作品の移行の記録から元の断片を引き、1つの作品に決まるときだけ置き換える（勧め）**。手元の Books では2枚とも投稿のカードになる見込み。直下のボードでは、ノートにした投稿もノートのカードは置けないので投稿のカードにする。
- B. 含める。作品のボードだけ（直下のボードは今のまま）。手元の Books では作品のボードの1枚だけ。
- C. 含めない。カードはテキストのまま、元の印も残る。

あわせて通知の文（A・B のとき）: **投稿だけなら「コピーのカード N 枚を投稿のカードに置き換えました」、両方なら「コピーのカード N 枚をノートと投稿のカードに置き換えました」、ノートだけなら今のまま（勧め）**。
