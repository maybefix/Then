## 工程2: 仕組みの説明

### 言葉

| 言葉 | 意味 |
|---|---|
| 管理単位 | 設定の「Ideaの管理単位」（`snippetStorageMode`）。「作品ごとに分ける」（workspace）なら作品の `.then/project.json` の Idea を、「全作品で共有する」（profile）ならアプリ状態の `profileSnippets` を右サイドバーに出す |
| スレッドの並び順 | スレッドの中の断片と資料リンクを混ぜた表示順（`IdeaThreadLayout`）。管理単位に関係なく、作品ごとの `default.json` の `ideaThreads` に、スレッドの ID ごとに保存する |
| 資料リンク | スレッドの中に置いた資料ファイルへの参照。ファイルそのものではない |
| 整合処理 | `reconcileIdeaThreadLayouts`（`src/ideaReferenceModel.ts`）。いまの Idea の組に合わせて並び順を作り直す。並び順にない断片は末尾に足し、今の組にないスレッドの並び順は捨て、そこにあった資料リンクは受信箱へ移す |
| Idea カード | 資料ボードに置いた、断片を表示するカード。`default.json` の `cards` に、スレッドの ID と断片の ID で保存する |

### 1. 管理単位の切り替え（件1）

1. 設定で別の管理単位を選ぶと、`handleSnippetStorageModeChange` が設定を書き換え、表示する Idea の組を入れ替える。確認も通知もない。
2. 組が入れ替わると、整合処理の effect が走る。新しい組にない ID の並び順は捨てられ、そこにあった資料リンクは受信箱へ移る。受信箱は ID が同じなので、並び順のうち断片の項目だけが捨てられる。
3. Idea カードの effect が、新しい組にない断片のカードを消す。
4. 0.7秒後に `default.json` が保存される。
5. 元の管理単位へ戻すと、断片は整合処理で各スレッドの末尾に足し直される。混ぜた順番、移った資料リンクの元の所属、消えた Idea カードは戻らない。
6. 「作品ごと」から切り替える直前0.7秒以内の Idea の編集は、遅延保存のタイマーが取り消されるので、`project.json` に書かれないまま表示から消える見込み（まだ確かめていない）。

### 2. Canvas へのドラッグ（件2）

右サイドバーの断片の日付の行をつかむと、`handleFragmentDragStart` がドラッグのデータに断片の ID（`application/x-brew-snippet-id`）だけを入れ、操作の種類を「移動」（`effectAllowed = "move"`）にする。Canvas の `handleViewportDrop` は本文の文字列（`text/plain`）からカードを作るので、文字列がないと何もしない。Canvas 自身の側面パネルからのドラッグは、ID と本文の両方を入れ、操作の種類を「コピー」にしているので動く。

### 3. 断片の削除を元に戻す（件3）

削除すると断片の配列から外れ、整合処理が並び順からもその項目を捨てる。「元に戻す」は断片の配列の元の位置に戻すが、並び順には戻さないので、整合処理が末尾に足す。表示順は並び順で決まるので、末尾に出る。別のスレッドへの移動（`moveFragment`）の「元に戻す」は、並び順も元の位置に戻しているので、この問題はない。

### 4. スレッドの削除（件4）

削除するとスレッドが組から外れ、整合処理がそのスレッドの並び順を捨て、資料リンクを受信箱へ移す（ID はそのまま）。「元に戻す」はスレッドだけを戻すので、並び順は空から作り直され、断片は配列の順に並び、資料リンクは受信箱に残る。

### 5. 今の挙動の癖（今回は直さないもの）

- 並べ替え（`reorderIdeaThreadItem`）には「元に戻す」がない。
- `reorderFragment` など、使われていない7つの処理は残す（Idea 分離の 5-6）。

## 工程5: 案

### 件1: 管理単位の切り替え

- **案A（勧め）: 管理単位ごとに並び順を分けて持つ。** `default.json` に、表示中でない側の管理単位の並び順と Idea カードを預けておく欄を足す（例: `ideaThreadsMode: "workspace"`、`otherIdeaLayout: { mode, ideaThreads, ideaCards }`）。切り替えたときと作品を開いたときに、ファイルの管理単位と今の設定が違えば入れ替える。古いファイル（欄がない）は、今の設定の並び順として読む（今と同じ）。切り替えの前に、作品の Idea の遅延保存を書き終える。
  - 利用者から見て: 切り替えて戻すと、混ぜた順番、資料リンクの所属、Idea カードが元に戻る。確認の画面は出さない。
  - 保存形式: 欄を足すだけ。古い Then で開くと、足した欄は無視され、今と同じに動く。
  - 手間: 中。Rust の構造体に欄を2つ足す。
- 案B: 切り替える前に確認の画面を出し、ボタンを「切り替える（並び順と資料の所属は受信箱に戻る）」のような文言にする。遅延保存も書き終える。保存形式は変えないが、崩れること自体は直らない。
- 案C: 案A に加えて、確認の画面も出す。案A で崩れなくなるので、確認は要らないと考える。

### 件2: Canvas へのドラッグ

- **案A（勧め）: ドラッグのデータに本文も入れる。** Canvas の側面パネルと同じく `text/plain` に本文を入れ、操作の種類を「コピーか移動」（`copyMove`）にする。スレッド内の並べ替えは今のまま「移動」として動く。
- 案B: Canvas の側が、ID しかないときに Idea の組から本文を探す。ほかの入力欄に本文が入るようにはならないが、別ウィンドウの Canvas では組を持っていない場合がある。

### 件3: 断片の削除を元に戻す

- **案A（勧め）: 並び順の位置も覚えて戻す。** `moveFragment` の「元に戻す」と同じ形にする。

### 件4: スレッドの削除

- **案A（勧め）: 削除を元に戻すと、資料リンクもスレッドへ戻す。** 削除の時点のスレッドの並び順を覚えておき、元に戻すときに、受信箱へ移った資料リンク（同じ ID のもの）を受信箱から外してスレッドへ戻す。削除したときに受信箱へ移る動き自体は変えない（資料リンクを失わないため）。そのあいだに利用者が別のスレッドへ動かした資料リンクは、そのままにする。
- 案B: スレッドを削除するときに、資料リンクも一緒に外す（受信箱へ移さない）。元に戻すと戻る。資料ファイルそのものは残るが、リンクは資料ボードからたどり直す必要がある。

### 決めてほしいこと

1. 件1 の直し方（案A／案B／案C）。勧めは案A。崩れないことが目的で、確認の画面を出しても崩れは残るため。Rust と保存形式（欄の追加）に触ることになる。
2. 件2 の直し方（案A／案B）。勧めは案A。Canvas 自身の側面パネルと同じ動きになり、別ウィンドウの Canvas でも動く。
3. 件4 の直し方（案A／案B）。勧めは案A。今の「削除しても資料リンクは失わない」を保ったまま、元に戻せるようにする。
4. 一緒に直すか: 断片やスレッドの削除を元に戻したときに、資料ボードの Idea カードも戻すか。勧めは「戻す」。同じ「元に戻す」の中で、削除の時点のカードを覚えておけば済む。
