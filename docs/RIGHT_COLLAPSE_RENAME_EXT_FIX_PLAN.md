## 工程5: 案

決まっていること（2026-10-24、利用者の答え）: 2つとも直す。右サイドバーの畳みは、左と同じくアプリ全体で1つ保存して起動時に戻す。名前の変更は、まず実機で起きるかを確かめ、起きれば見出しの切り出しと同じく、画面の側で元の拡張子を足す（Rust は変えない）。PR は1つ。

### 5-1. 癖1の書き方

左サイドバーと同じ形にする。`setIsRightSidebarCollapsed` が画面の値とアプリの状態（`rightSidebarCollapsed`）の両方を書き、`normalizeState` で読み（`true` のときだけ畳む）、起動時の読み込みで画面へ戻す。読み込みの直しは `src/utils/rightSidebarState.ts` に足す。

### 5-2. 癖2の書き方

`handleRenameProjectEntry` で、ファイルのときは、名前の前後の空白を落とし、拡張子（`.md`・`.txt`、大小文字は問わない）がなければ元のファイルの拡張子を足してから、今の名前と比べ、Rust へ渡す。フォルダは今のまま。

### 決めてほしいこと

1. **A（ペイン幅を拡張も戻らない）を一緒に直すか**。勧めは「一緒に直す」。畳みのすぐ隣のボタンで、同じ書き方（アプリの状態に1項目）で直せる。幅のボタンは今の値をひっくり返す書き方なので、値を渡す書き方に変える。
2. **B（ファイルの操作が保存の印を進み具合に使っている）をどうするか**。勧めは「この PR の後に、別の PR で直す」。6つの処理にまたがり、処理中の「読み込み中」をやめるか、何で進み具合を見せるかも決める必要があるので、別に調べて案を出したい。

### 5-3. B の直し方

直す前の QA 用アプリで、2つとも起きることを確かめた。関係ないファイルの名前の変更に失敗すると、保存済みの今のタブが「保存失敗」になり、作品を切り替えようとすると「未保存の変更があります … 一章.md」と聞かれた（「保存失敗」のタブは未保存として数えられる。`isDirtyDocumentTab`、`src/editor/documentTabState.ts`）。逆に、今のファイルの保存が本当に失敗しているときにフォルダを作ると、印が「保存済み」になった。

| 案 | 利用者から見て |
|---|---|
| **1（勧め・決定）: 印に触らず、失敗は通知** | ファイルの操作（ファイル・フォルダの作成、名前の変更、削除、1つ・複数の移動、並び順の保存）は、今のタブの印を書かない。処理中の「読み込み中」もやめる。印を書くのは保存の処理（`enqueueDocumentSave` と自動保存）だけ。操作の前に未保存のタブを保存する分は、今までどおりそのタブの印に出る。失敗は通知で知らせる。今通知がない5つ（ファイルの作成・フォルダの作成・名前の変更・1つの移動・並び順の保存）に「〜できませんでした」を足す。エラーの文は今までどおり |
| 2: 処理中は「読み込み中」、終わったら元に戻す | 処理中の「読み込み中」は残し、終わったら操作の前の印へ戻す。前もっての保存の結果と纏める処理が要る |
| 3: 失敗のときだけ直す | 成功した後の「保存済み／未保存」はそのまま（保存に失敗していても、フォルダを作ると「保存済み」になる癖は残る） |
