### 気づいた点

- **移行の前の姿を作るコードは、移行のときに消える。** 1-6 で Plot の読み込みと `normalizePlotCards` を、2-4 で `alignIdeaLayoutToMode` や `profileSnippets` の読み込みを消す。だから「前」の姿は、コードで毎回作るのではなく、**ファイル（期待値）として残す**必要がある。

- Rust の読み込みにしかない処理（旧形式 `snippets` からの変換、`.json.bak` からの復旧）を動かすテストもない。
- `scripts/fixtures/` には `app-state-pre-portability.json`（`test:project-portability` の見本）が1つだけある。今回の見本は、この並びに置ける。

## 工程2: 仕組みの説明

### 言葉

- **見本データ（fixture）**: テストのために用意した、作品フォルダと設定ファイルの一式。
- **期待値（golden）**: 見本データを今のコードで読んだときに画面に出るものを、ファイルに書き出したもの。移行の後は、移行した結果をこれと比べる。
- **見え方の写し**: 「画面に出るもの」を、ID や画面の開閉状態など比べなくてよいものを除いて、決まった形の JSON にしたもの。
- **並び順（`default.json` の `ideaThreads`）**: スレッドの中で、断片と資料リンクをどの順に出すか。断片の本体は `project.json`、並びは `default.json` と、別のファイルにある。

### 1. 移行の入力（データの形）

| 入力 | 置き場所 | 中身 |
|---|---|---|
| `plotCards` | 作品の `.then/project.json` | `{ id, kind: "section"｜"chapter", num, title, body, expanded, managerCollapsed }` の配列。ライブラリの直下の `project.json` にも入りうる（ライブラリへ移動・コピーしたとき） |
| `ideaThreads` | 作品の `.then/project.json` | スレッド `{ id, kind: "inbox"｜"thread", title, starred, createdAt, updatedAt, fragments }`、断片 `{ id, body, used, createdAt, updatedAt, originRef? }` |
| `snippets`（旧形式） | 作品の `.then/project.json` | `{ id, title, text, category, tags }`。`ideaThreads` が空のときだけ、Rust がインボックスの断片に作り直して返す。次に保存すると消える |
| 並び順 | 作品の `.then/reference-layouts/default.json` | `ideaThreads: [{ threadId, items: [{ sourceType: "idea", fragmentId } ｜ { sourceType: "reference", id, sourcePath, createdAt }] }]` |

| 資料ファイル | 作品の `.then/references/imports/` | 画像・PDF・テキスト。取り込み資料（`imported: true`） |

今回は操作を足さない。移行の前の姿は「作品を開いたとき」に決まるので、作品を開く処理だけを扱う。

今回は保存の処理に触れない。テストは見本データを読むだけで、ファイルを書かない（見本データのフォルダを書き換えないことも確かめる）。

### 4. ほかの機能との関係

### 5. 今の挙動の癖と、固定するかどうか

「固定する」は、今の挙動のまま期待値に入れ、移行の後もそれと比べること。「固定しない」は、期待値に入れないこと（移行で扱いを決めるか、移行に関係しない）。
