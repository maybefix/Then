## 工程2: 仕組みの説明

### 言葉

- **作品の切り替えメニュー**: パンくずの先頭（本のアイコンと作品名、作品がなければ「一時ファイル」）を押すと開くメニュー。
- **ライブラリそのもの**: 作品を入れておく親のフォルダ。開くと、作品の一覧（ライブラリのホーム）が出る。最近の記録では `library.role` が `"root"`。

### 1. 今のメニューの中身

| 部分 | 作品を開いているとき | 開いていないとき |
|---|---|---|
| 見出し | 作品名（ライブラリそのものを開いているときはライブラリ名）と、パス（設定が有効のとき） | 「一時ファイル」 |
| 検索欄 | あり | あり |
| 現在のプロジェクト（フォルダの木） | あり | なし |
| 最近開いたプロジェクト | あり。今の作品に「現在」の印、押しても閉じるだけ | あり |
| ライブラリ | **なし** | あり（知っているライブラリがあるとき） |
| 別のフォルダを開く... | あり | あり |

### 2. 利用者の操作と内部の処理

| 操作 | 内部 |
|---|---|
| 一覧の作品・ライブラリを押す | `closeBreadcrumbMenuAndRun` でメニューを閉じてから `openWorkspace(パス)`。今の作品なら何もしない |

### 3. 保存

メニューは何も保存しない。開いた作品・ライブラリは、`openWorkspace` が最近の記録に足す（今回変えない）。

### 4. ほかの機能との関係

- 帯の左端のライブラリ名、左サイドバーの「← ライブラリ」: 今の作品が入っているライブラリへ戻る（`openWorkspace` を呼ぶ）。

## 工程5: 案

### 5-1. 方針

- 部品の中に `renderWorkspaceSwitcher(scope)` を1つ置き、作品を開いているときは今の作品を、開いていないときは null を渡して呼ぶ。行（作品・ライブラリ）の描き方も `renderWorkspaceRecord` の1つにまとめる。
- 出し分けは3つだけにする: 見出しのパス、「現在のプロジェクト」のフォルダの木、「現在」の印（開いているフォルダとパスが同じ行）。ライブラリの一覧は、どちらでも出す（知っているライブラリがあるとき）。
- 並びは、現在のプロジェクト → 最近開いたプロジェクト → ライブラリ → 別のフォルダを開く...。作品を開いていないときは今と同じ並び。
- 作品の中にいるとき、その作品のライブラリも一覧に出し、押すとライブラリへ移る（帯のライブラリ名と同じ処理）。

### 5-2. 見込み

- 部品は約70行減る（2つのメニュー計164行 → 約95行）。案 B（挙動を変えずにまとめる）とほぼ同じで、ライブラリの一覧の出し分けがない分だけ、わずかに少なくなる。
- 作品を開いたまま、作品名 → ライブラリ名の2回の操作で、ほかのライブラリへ移れる。

### 決めてほしいこと

1. **ライブラリそのものを開いているとき、一覧の中の今のライブラリ**
   - a. 「現在」の印を付け、押しても閉じるだけにする（推す）。最近の作品の一覧と同じ規則（開いているフォルダとパスが同じ行）なので、作品とライブラリで扱いが揃う。
   - b. 一覧から外す。
2. **コマンドパレットで、ライブラリが「プロジェクトを開く: 書庫」と出る**
   - a. 一緒に直す（推す）。ライブラリの記録は「ライブラリを開く: 書庫」、補助の文字は「ライブラリ」にする。作品の記録と「別のプロジェクトを開く...」は変えない。同じ「ほかのライブラリへ移る」操作の文言なので、揃えて出すと迷わない。
   - b. 今回はしない（記録する）。

### テストの直し方と足すテスト

- `test:topbar-parts`: 先に「今は失敗する」期待を書く。作品を開いているときにライブラリの一覧が出て、押すと `openWorkspace(ライブラリのパス)` を呼ぶこと。ライブラリそのものを開いているとき、今のライブラリに「現在」の印が付き、押しても何もしないこと（1-a なら）。作品のないときの期待は変えない。
- パレットを直すなら `test:palette-commands` にライブラリの記録の例を足す。
- 効くことの確かめ: まとめた描画にわざと不具合を2つ入れ、落ちることを見て戻す。
