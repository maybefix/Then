# チェックポイント画面 リデザイン実装指示書

Then の「チェックポイント」（スナップショット）画面を作り直すための仕様。
既存の保存・復元・自動退避のロジックはそのまま使い、**画面の構成と差分の見せ方だけを変える**。

> 実装前に、既存コードの「保存点の作成」「復元」「復元前の自動退避」「比較先の切り替え」がどこにあるかを確認し、それを呼び出す形で組むこと。新しい保存形式やデータ構造は作らない。

---

## 1. 目的

今の画面の問題は「何が変わったか」が見えないこと。左右に全文を並べているが変更箇所のハイライトがなく、結局目で見比べることになっている。
新しい画面では **「時系列の一覧から選ぶ → 変わった所だけ見る → 全体かファイル単位で戻す」** の流れにする。

既存機能で削るものはない。

| 既存の機能 | 新しい画面での置き場所 |
|---|---|
| 保存点の一覧・検索 | 左サイドバー（日付でグループ化） |
| 保存点を作成 | サイドバー上部「今の状態を保存点にする」 |
| 比較先の選択 | 詳細上部の「比較先」セレクト |
| 左右並べの全文比較 | 「左右に並べる」表示モード（ただし変更段落のみ） |
| 復元「全体」 | 詳細ヘッダーの「この時点に戻す」 |
| 復元「選択」 | 各ファイルの「このファイルだけ戻す」／「並び順だけ戻す」 |
| 復元前の自動退避 | 変更なし（確認ダイアログと完了通知で明示） |

---

## 2. 画面構成

```
┌ ヘッダー ─────────────────────────────────────────┐
│ ← 本文へ戻る   チェックポイント                       │
├ サイドバー（約300px）──┬ 詳細（残り全部、本文最大幅980px）──┤
│ 保存点        7件      │ [完了通知バナー]（復元直後のみ）     │
│ ┌現在のプロジェクト──┐ │ 保存点名               [この時点に戻す][⋯] │
│ │ 8ファイル·27,145字  │ │ 8月4日 08:03 · 8ファイル · 27,003字 │
│ │[今の状態を保存点に]│ │ メモ                                │
│ └────────────┘ │ ┌比較先 [現在のプロジェクト▾]  [変わった所だけ|左右に並べる]┐ │
│ [🔍 名前・メモで絞り込む]│ 要約文            旧 → 新   +184字 −41字 │
│ ☑ 自動退避も表示（3件） │ 凡例：消えた文／加わった文           │
│                        │ ┌ファイルカード（開閉）──────────┐ │
│ 8月4日                 │ │ ▾ ファイル名  フォルダ  [変更] +142 −38 [このファイルだけ戻す] │
│ ● 保存点名             │ │ ⋯ 32段落 変更なし                │ │
│   08:03·8ファイル·字数 │ │ 33 今は〜〜（インライン差分）      │ │
│ 7月10日                │ └──────────────────┘ │
│ • 復元前の退避  09:54  │ [フォルダの並び順]カード             │
│ …                      │ ✓ 変更のないファイル 6件は省略        │
│                        │ 注記：戻すときは直前の状態を自動保存  │
└────────────┴──────────────────────┘
```

幅が狭いときは、サイドバーが上、詳細が下に縦積みになる（flex-wrap）。

## 3. 各部の仕様

### 3-1. サイドバー

- **現在のプロジェクト** カード：ファイル数と総字数を表示。字数は既存の文字数カウントを流用し、新規計算しない。
- **今の状態を保存点にする**：押すとカード内に名前入力欄（placeholder「例：第2稿に入る前」）、「やめる」「保存する」が出る。名前が空なら「名前のない保存点」。保存したら一覧の先頭に追加し、それを選択状態にする。
- **絞り込み**：名前とメモの部分一致。0件なら「一致する保存点はありません」。
- **自動退避も表示**：チェックを外すと「復元前の退避」を一覧から隠す。選択中の保存点は隠さない。件数を併記する。
- **一覧**：新しい順。日付ごとに見出し（例「8月4日」「今日」）を付ける。
  - 手動の保存点：黒丸 + 名前（太字）+「時刻 · ファイル数 · 字数」+ メモ（あれば）。
  - 自動退避：小さいオレンジの点 + 「復元前の退避」+ 右寄せで「時刻 · ファイル数」。1行で控えめに表示する。
  - 選択中：白背景 + 1.5pxの黒い内枠。`aria-current` を付ける。

### 3-2. 詳細ヘッダー

- 保存点名（22px太字）、メタ情報、メモ。
- 自動退避を選択中は「復元を実行する直前に、自動で作られた保存点です。」と表示する。
- **この時点に戻す**（黒背景の主ボタン）：確認ダイアログを開く（scope = all）。
- **⋯** メニュー：「名前とメモを編集」「この保存点を書き出す」「この保存点を削除」（削除は赤文字）。既存機能があれば接続し、なければ項目ごと出さない。

### 3-3. 比較バー

- **比較先** セレクトの選択肢は次の順。
  1. 現在のプロジェクト（初期値）
  2. ひとつ前の保存点（日付 時刻）
  3. その他の保存点
- 保存点を切り替えたら比較先は「現在のプロジェクト」に戻す。
- **表示モード**：「変わった所だけ」（初期値）と「左右に並べる」のセグメント切り替え。`aria-pressed` を付ける。

### 3-4. 要約行

- 要約文の例：「2ファイルの本文と、フォルダの並び順が変わっています」「5ファイルが加わり、1ファイルの本文が変わっています」。
- 方向表示：比較先が現在、または新しい保存点なら「この保存点（日時）→ 比較先」。比較先が古い保存点なら「比較先（日時）→ この保存点」。
- 増減字数：+は青、−はオレンジ。

### 3-5. ファイルカード

- 変更のあったファイルだけを並べる。先頭のカードだけ初期状態で開く。
- 見出し行：開閉シェブロン、ファイル名、フォルダ名、種別バッジ（変更／追加／並び順）、増減字数、戻すボタン。
- 開いたときの中身：
  - **変わった所だけ**：変更のある段落だけを、行番号付きでインライン表示する。間の変更のない段落は「⋯ N段落 変更なし」に畳む。
  - **左右に並べる**：同じ段落を左（旧）と右（新）に並べる。列見出しに旧・新のラベルを付ける。旧側に存在しない場合は「（この時点ではまだありません）」。
- **追加されたファイル**：冒頭数段落を「加わった文」として表示するか、「新しく加わったファイルです（+N字）」とだけ表示する。
- **フォルダの並び順** カード：旧と新の並び（例「01_記事 → 02_メモ → 03_野球」）を2行で並べる。ボタンは「並び順だけ戻す」。
- 末尾に「変更のないファイル N件は省略しています」（点線枠）。
- 差分がゼロなら「比較先と同じ内容です。戻しても何も変わりません。」。

### 3-6. 差分の見た目

| 種類 | 背景 | 文字色 | 装飾 |
|---|---|---|---|
| 消えた文（旧にだけある） | `#ffe6d1` | `#7a3300` | 取り消し線 |
| 加わった文（新にだけある） | `#dce9ff` | `#0f3a8f` | 下線（`#6b93e6`、offset 5px） |

色だけに頼らず、取り消し線と下線を必ず併用する。本文は明朝系、16px、行間2。

### 3-7. 確認ダイアログ

| scope | タイトル | 本文 |
|---|---|---|
| all | 「{保存点名}」の時点に戻す | {N}ファイルの本文と、フォルダの並び順を {日時} の状態に戻します。 |
| file | 「{ファイル名}」だけ戻す | このファイルの本文を {日時} の状態に戻します。ほかのファイルはそのままです。 |
| order | フォルダの並び順だけ戻す | 本文には手を触れず、フォルダの並び順だけを {日時} の状態に戻します。 |

共通の注記：「今の状態は「復元前の退避」として自動で保存されるので、あとから元に戻せます。」
ボタンは「キャンセル」「戻す」（主ボタン）。

### 3-8. 復元後

- 既存の自動退避を実行してから復元する（既存の順序を変えない）。
- 一覧の先頭に「復元前の退避」が増える。
- 詳細の上部に、青系の完了バナーを `role="status"` で出す。文言は「「{保存点名}」の時点に戻しました。直前の状態は「復元前の退避」として保存してあります。」で、「閉じる」ボタンを付ける。

## 4. 差分計算の仕様

1. **段落単位**：段落（改行区切り）ごとにハッシュを取り、LCS／Myers系で一致・削除・追加を求める。要約と増減字数を出すため、画面を開いた時点で全ファイル分を計算する。
2. **文字単位**：「変更」と判定された段落ペアにだけかける。削除と追加が隣り合う段落はペアとして扱う。日本語は単語区切りがないので文字単位で計算する。結果が細切れになりすぎる場合は `Intl.Segmenter`（granularity: "word"）で文節寄りにまとめる。
3. **ファイル単位**：パスで突き合わせ、追加・削除・変更・変更なしに分類する。
4. **並び順**：フォルダとファイルの順序配列を比較し、違えば「並び順」カードを1枚出す。
5. 既存コードに差分ライブラリや差分処理があれば流用する。新たに入れる場合は軽量なものを選ぶ（例：diff-match-patch 系や jsdiff 系）。

---

## 5. パフォーマンス制約（必須）

タイプライタースクロールの高速化を壊さないための約束。

- 差分計算は **チェックポイント画面を開いたとき／保存点・比較先を切り替えたときだけ** 走らせる。エディタの入力・スクロール・保存の経路には一切入れない。
- 「現在との差分」を常時更新しない。
- 計算結果は `保存点ID + 比較先ID + 本文ハッシュ` をキーにキャッシュする。
- 文字単位の差分は、そのファイルカードを開いたときに遅れて計算する。
- 閉じたカードの中身は描画しない。全文は描画しない（変更段落と区切り表示だけ）。
- 大きいプロジェクトで画面を開くのが遅ければ、段落単位の計算を Worker（または非同期タスク）へ移す。
- チェックポイント画面にいる間は、エディタ側のスクロール処理やイベント購読を止める。戻ったときにカーソル位置とスクロール位置を復元する。

---

## 6. 未確定事項（実装前に確認）

- **保存点より後に追加されたファイルの扱い**：全体復元で削除されるのか、残るのか。既存の復元処理の挙動を確認し、確認ダイアログの本文に反映する。
- **差分処理の有無**：既存の比較画面に差分計算が入っているか。入っていればそれを流用する。
- **⋯メニュー**：「書き出す」「削除」「名前とメモを編集」の既存実装があるか。

---

## 7. 進め方

1. 既存のチェックポイント画面のコードと、保存・復元・自動退避の呼び出し箇所を特定し、上の未確定事項に答える。
2. 差分計算モジュールを、画面から独立した純粋関数として作り、テストを書く（段落の追加・削除・変更、並び順変更、変更なし）。
3. サイドバーを作り直す（グループ化、自動退避の表示切り替え、保存点の作成）。
4. 詳細側を作る（比較バー、要約、ファイルカード、2つの表示モード）。
5. 確認ダイアログと復元後の通知を既存の復元処理に接続する。
6. 2万字超と10万字超のサンプルプロジェクトで、画面を開く時間と、エディタに戻ったあとのタイプライタースクロールの体感を確認する。
