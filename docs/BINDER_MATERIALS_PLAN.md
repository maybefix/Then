### 気づいた点

- **検索は AST を探している。** 全文検索（C10）は、索引の AST（A4）に入っているファイルを探す。3.6 の「アウトラインと AST は原稿だけ」と「検索は素材も含める」を両方そのまま入れると、素材が検索に出なくなる。D-2 で決める。
- **チェックポイントは「スナップショットにないファイルを消す」作りになっている。** 全体の復元（A7）は、スナップショットにない今のファイルをごみ箱へ移す。素材をチェックポイントから外すなら、ここも原稿だけに絞らないと、復元のたびに素材がごみ箱へ行く。
- **1-3a の退避はチェックポイントを通る。** ほかのアプリで変わったファイルを上書きするとき、消える側は `storeTextInCheckpoint`（`App.tsx:6944`）→ `buildManuscriptSnapshot` の差し替え（A5）でチェックポイントに残す。素材をチェックポイントから外すと、素材の保存でこの退避が「作品フォルダにない原稿です」で失敗し、1-3a の守りが素材に効かなくなる。
- **保存そのものは区分と関係ない。** タブの保存は `journal_save`（パスとハッシュだけを見る）、置換は `save_text_file` の `expectedHash`。区分を付けても、素材の保存がハッシュ比べを外れることはない（外れる道は上の退避だけ）。
- **プラグインに一覧を渡す API は今はない。** `findPluginDocument`（B2）はパスで1件探すだけ。3.6 の「区別できる形で渡す」は、今は渡すものがない。探すときは素材も見つかるままにする。
- `project.json` の `validate_project_config` は、正しくない値があると作品を開けなくする。`materialsFolder` の値が変（`../x`、`.then`、区切り文字入り）でも作品を開けなくしないよう、検証で止めずに「未設定」と同じに扱う。

## 工程2: 仕組みの説明

### 言葉

- **区分**: 一覧の各ファイル（とフォルダ）に付ける「原稿」か「素材」かの印。
- **素材フォルダ**: 作品フォルダ直下の、`project.json` の `materialsFolder` に書かれた名前のフォルダ。中のものは入れ子もすべて素材。
- **索引（文書 AST）**: 各ファイルを読んで作る、見出し・段落・字数の構造。左のツリーの字数、全文検索、チェックポイントが使う。

### 1. データの形

- `project.json` に `materialsFolder`（文字列、省略可）を足す。今の作品には書かれていない。
- 一覧の1件に `role`（`"manuscript"` か `"material"`）を足す。素材フォルダそのものも `"material"`。
- 画面側の `ProjectEntry` 型に `role?` を足す。欄がないもの（古いチェックポイントの `projectTree` など）は原稿として読む。

### 2. 利用者の操作と内部の処理（入れたあと）

| 操作 | 内部 | 素材の扱い |
|---|---|---|
| 作品を開く・ツリーを読み直す | `list_project_folder` が `materialsFolder` を読み、素材フォルダの下に `role: "material"` を付ける | 一度だけ判定 |
| 左のツリーを見る | 1-4 までは今のツリーのまま。素材のファイルには進捗記号を出さない。字数はフォルダの字数として出す（D-3） | 進捗なし |
| ステータスバー・凡例の合計字数 | `buildSidebarMetrics` の作品合計を原稿だけで数える | 数えない |
| ライブラリ画面 | `computeWorkStats` の字数・ファイル数・進捗の内訳を原稿だけで数える | 数えない |
| 書き出し | 候補を原稿だけにする | 対象外 |
| 全文検索・置換 | D-1 しだい（勧めは含める） | — |
| チェックポイント | D-6 しだい（勧めは含める） | — |
| 素材を開いて書く・保存 | 原稿と同じ。1-3a のハッシュ比べも同じ | 原稿と同じ |

### 3. 保存

- 区分はファイルに保存しない。一覧を読むたびに、`materialsFolder` とパスから決め直す。
- `materialsFolder` は今回、画面から書く手段を作らない（素材フォルダを作る操作は 1-4 と 2-5）。実機確認では `project.json` に手で書く。
- 進捗（`fileProgress`）はパスごとに残る。素材へ移したファイルの進捗は消さずに残し、表示と集計で見ないだけにする（D-4）。

### 4. ほかの機能との関係

- **1-3a（保存前の外部変更）**: 保存は区分を見ない。退避はチェックポイントを通るので、D-6 で素材をチェックポイントに入れる限り、素材にも効く。
- **1-4（三段化）**: 区分を見て、ツリーを「原稿／素材／投稿」に分ける。今回の `role` をそのまま使う。
- **2-5（資料の移動）**: `素材/` を作り、`materialsFolder` を書く。
- **3-3（素材リスト）**: `[[名前]]` を素材フォルダの中から探す。

### 5. 今の挙動の癖（直さないもの）

- `素材` という名前のフォルダがあっても、今は普通のフォルダとして扱われる（見本データの作品B）。`materialsFolder` を書かない限り、入れたあとも同じ（D-3）。
- 書き出しは、作品にファイルが1つもないとき開いている1枚を候補にする（`App.tsx:5484`）。原稿が0で素材だけの作品では、素材の1枚が書き出しの候補になりうる。D-5 で扱う。

## 工程5: 案

### 5-1. 方針

1. Rust の一覧で区分を付ける。`list_project_entries_within` が、`materialsFolder` が設定されていて、作品のルートから見たパスがその名前のフォルダの中にあれば `role: "material"` を付ける。設定がなければ全部 `"manuscript"`。
2. `collectProjectTextFiles` の戻り値に `role` を足す。原稿だけが要る呼び出しのために `collectManuscriptFiles`（`role` が素材でないもの）を足す。各呼び出しはどちらを使うかを1つずつ選ぶ（工程1の表）。パスを見て判定する関数は作らない。
3. 索引（AST）は全ファイルのまま持ち、各ファイルに `role` を写す。字数の合計と、原稿だけを見る処理は `role` で絞る（D-2）。
4. チェックポイントは素材も入れる（D-6）。合計の字数は全ファイルのまま。
5. 素材フォルダのない作品では、`role` がすべて `"manuscript"` になり、絞り込みは何も外さない。だから結果は今と同じになる（8-1 のテストで確かめる）。
