## 工程1: 原因

1. **準備の競争**: テストの `open` は、1回目の読み込みから 1.2 秒後に `localStorage` を消してテストの設定（`then.app-state.v1`。タイプライタースクロールは切、レイアウトは場面ごと）を書き、読み込み直す。アプリは読み込みの後 0.7 秒待ってから、そのときの状態（既定の設定）を `localStorage` に書く（`src/App.tsx` の `saveStoredState`）。この書き込みが、テストが書いた後、読み込み直しの前に入ると、テストの設定が既定で上書きされる。読み込み直した後はタイプライタースクロールが入になり、本文の左右に 2400px の余白が付いて本文が横に流れる。通る回でも、アプリの書き込みとテストの書き込みの差は 0.13 秒しかなかった。
2. **`reveal` の弱さ**: 文字の左右の端が画面の幅（0〜2400）の中なら流さない。右のサイドバー（x=2100〜2400）に隠れた文字も「見えている」とみなし、サイドバーの上を押していた（「乙」が x≈2343）。

## 工程2: 再現

テストの写しを作り、テストの書き込みを 0.6 秒に早め、読み込み直しを 1.5 秒遅らせて、アプリの書き込みが必ず「テストの書き込みの後・読み込み直しの前」に入るようにした（読み込み直しの後の待ちは 3 秒から 4.5 秒にした）。直す前のテストでは、通常の表示の2つに加えて、原稿用紙モードでも「原稿用紙のページ境界が出ている」（境界 0。レイアウトも既定に戻るため）と、同じ2つが落ちた（15件中5件）。

## 工程3: 直したこと（`scripts/test-ai-selection-browser.mjs` だけ）

- `open`: テストの設定を書く前に、そのページの `localStorage` の書き込み（`setItem`・`removeItem`・`clear`）を止める。古いページのアプリが待たせている保存は、読み込み直すまで何も書けない。テストの設定は、止める前に取っておいた `setItem` で書く。読み込み直した後、エディタを開いてから、アプリが保存した設定がテストの設定のまま（タイプライタースクロールが切、レイアウトが場面のもの）であることを確かめ、違えばそこで止める。
- `reveal`: 文字の中心で `document.elementFromPoint` を引き、エディタ（`.ProseMirror`）の中に当たらなければ（画面の外・サイドバーの下）、見えていないとみなして流す。

## 工程4: 自動テスト

画面は1回だけ `vite build --base ./` で scratchpad に build し、どの回も `--dist` で同じものを使った。
